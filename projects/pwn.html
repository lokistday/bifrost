수행할 과제

  1. project-parser-starter.c의 parse 함수만 완성하세요. 호출자가 가진 버퍼와 출력 포인터의 계약도 적습니다.
  2. 자체 C 테스트 main을 만들어 A/B의 Hex를 바이트 배열로 실행합니다.
  3. 길이 0/8/9·1바이트 헤더·잘림·후행 데이터·NUL을 검사하고 Sanitizer에서도 실행합니다.
  4. 결과를 JSON으로 모아 검사기에 전달하고 메모리 소유권·부분 I/O 연결의 한계를 보고합니다.

출력 계약

한 레코드는 정확히 2+선언 길이 바이트여야 합니다. 길이 0은 허용하며 8 초과는 거부합니다. accepted_ids는 입력 순서, payload_sum은 허용 본문의 unsigned 바이트 합, nul_ids는 허용 본문에 NUL이 있는 ID입니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

C 과제는 직접 작성한 소스를 로컬에서 컴파일·실행하는 별도 검사를 제공합니다. 격리된 테스트 환경에서 실행하세요. 처음 제공된 starter는 미완성이므로 검사가 실패해야 정상입니다.

python3 project-c-tests.py --source project-parser-starter.c --sanitize

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 경계·잘림·후행 바이트를 정확히 판정하고 두 표본 결과가 일치한다.
  2. 길이를 검사하기 전에 헤더/본문을 읽지 않는다.
  3. 본문 길이를 strlen으로 대체하지 않고 호출자 객체의 수명을 지킨다.
  4. 정상·거부 테스트와 컴파일 옵션·Sanitizer 기록을 제공한다.

실제 형식으로 연결하기

gcc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined로 자체 C 테스트를 실행하고 Python 참조 결과와 비교합니다.
