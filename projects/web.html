세션과 재시도를 함께 검증하는 예약 서비스

세션 만료와 중복 예약을 분리해서 검사하세요. 만료한 요청은 예약 DB에 도달하지 않아야 하고 같은 요청의 재전송은 재고를 두 번 줄이면 안 됩니다.

수행할 과제

  1. 세션 판정과 DB 상태 변경의 경계를 그림으로 그립니다.
  2. web_state.Checkout을 사용해 시나리오를 순서대로 실행하는 드라이버를 작성합니다.
  3. A/B 결과를 제출하고 만료 경계·수량 변경 재시도·타인 사용자 키를 반례로 확인합니다.
  4. 개인 응답 캐시와 복구 토큰을 이 서비스에 붙인다면 추가할 정상·거부 검사 4개를 설계합니다.

출력 계약

현재 신뢰한 세션의 expires보다 now가 작을 때만 예약합니다. 만료는 UNAUTHENTICATED입니다. 그 외에는 제공된 Checkout.reserve의 사용자별 키·수량 계약을 적용합니다. outcomes는 요청 순서, stock과 orders는 최종 상태입니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 두 표본의 상태 전이를 재현하고 만료 요청이 재고를 바꾸지 않는다.
  2. REPLAY·CONFLICT·OUT_OF_STOCK을 구분한다.
  3. 실패·재시도 후 재고와 주문의 불변 조건을 확인한다.
  4. 인가·CSRF·캐시·토큰 검증을 서로 대체하지 않고 제안한다.

실제 형식으로 연결하기

Checkout의 실제 SQLite 테이블을 SELECT로 읽고 상태 전이 표와 비교합니다. 브라우저 테스트는 별도의 격리된 자체 서비스에서만 확장합니다.
