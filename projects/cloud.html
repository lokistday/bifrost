먼저 준비할 것

ZIP 전체를 풀고 원본을 보관하세요. 폴더 전체의 작업 사본에서 진행합니다. 모든 자료는 직접 만든 교육용 표본이며 외부 서비스에 접속할 필요가 없습니다.

  • Kubernetes 네임스페이스와 RBAC
  • 프라이빗 엔드포인트와 DNS 경로
  • 긴급 접근의 만료·회수·증거

각 파일을 따로 받으면 의존 파일이 빠질 수 있습니다. 실행할 때는 ZIP 전체를 사용하세요.

수행할 과제

  1. 변경 전 역할·신뢰 주체·DNS 경로·승인 수명을 연결한 경계 그림을 만듭니다.
  2. 기본 입력을 깊게 복사한 뒤 A/B 변경을 적용해 세 판정 목록을 만듭니다.
  3. 잘못된 subject namespace를 넓은 권한으로 해결하지 않고 신뢰 대상과 바인딩을 점검합니다.
  4. 실제 Kubernetes Role/RoleBinding JSON 초안, 변경 영향·감사 전달·복원 목표·롤백 증거를 보고서에 포함합니다.

출력 계약

각 JSON은 기본 boundary-models.json에 적용할 독립적인 변형입니다. role_namespace, subject_namespace, lease_revoked만 바꿉니다. 기존 rbac/private/lease 판정 함수를 사용하고 각 요청의 결과를 입력 순서대로 출력합니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

독립 시도 후, 참고 결과와 풀이 읽기

공개된 참조 구현입니다. 답을 본 뒤에는 새로운 반례를 직접 만들어 설명할 수 있는지 확인하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 네임스페이스·주체·행동과 사설 경로·인가를 분리했다.
  2. 회수된 긴급 권한의 모든 사용이 거부되는지 확인했다.
  3. 정상 기능과 거부 기능을 함께 검증하고 모형 밖의 조건을 적었다.
  4. 제한된 Role/RoleBinding 초안과 감사·RPO/RTO·롤백 계획이 연결된다.

보고서에 남길 것

범위·환경 → 예상 → 실제 관찰 → A/B 차이 → 반례와 수정 → 미확인 사항. 해시·종료 상태·테스트 결과만으로 모든 결론을 증명했다고 표현하지 마세요.

1–3일 뒤 답안 없이 B를 다시 풀거나 새 입력을 만들어 확인하세요. 설명이 막히면 해당 선행 차시로 돌아가 필요한 부분을 보충합니다.

실제 형식으로 연결하기

제공된 project-role.json의 apiVersion/kind/metadata/rules를 Kubernetes 공식 예제와 대조합니다. 선택적으로 격리된 본인 로컬 클러스터에서만 auth can-i로 검증하고 실제 결과와 모형 차이를 기록하세요.
