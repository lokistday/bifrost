수행할 과제

  1. 새 작업 폴더에서 DB를 생성하고 원본 해시와 보관 기록을 남깁니다.
  2. sqlite3의 mode=ro로 열거나 별도 작업 사본에서 SELECT를 수행합니다. 행의 원시 시각과 UTC를 함께 보관합니다.
  3. 호스트·세션 범위로 연결해 A/B 결과를 만들고 제외된 기록의 이유를 적습니다.
  4. 1페이지 보고서에서 관찰 사실·가설·미확인·추가 수집·업무 영향을 분리합니다.

출력 계약

project-build-db.py가 A/B DB를 생성합니다. host=lab-1, session=S7인 행만 조사 범위입니다. timeline은 UTC 시각순 ID, reads는 그 범위의 read ID입니다. 시각 동률은 ID순입니다. suspect_actor는 자료만으로 실제 행위자를 확정할 수 없어 UNKNOWN입니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

SQLite 파일은 새 이름으로만 생성합니다. 이미 있으면 덮어쓰지 않고 멈춥니다.

python3 project-build-db.py --variant a
python3 project-build-db.py --variant b

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 원본/작업 사본 해시와 재현 명령을 보관했다.
  2. 호스트·세션·시간을 함께 사용하고 범위 밖 기록을 섞지 않았다.
  3. 시각 순서를 인과나 실제 행위자의 신원으로 과장하지 않았다.
  4. 각 결론에 이벤트 ID를 연결하고 반증 자료·관측 공백을 적었다.

보고서에 남길 것

범위·환경 → 예상 → 실제 관찰 → A/B 차이 → 반례와 수정 → 미확인 사항. 해시·종료 상태·테스트 결과만으로 모든 결론을 증명했다고 표현하지 마세요.

1–3일 뒤 답안 없이 B를 다시 풀거나 새 입력을 만들어 확인하세요. 설명이 막히면 해당 선행 차시로 돌아가 필요한 부분을 보충합니다.

실제 형식으로 연결하기

JSON 모형에서 실제 SQLite 헤더·테이블·읽기 전용 질의로 넘어갑니다. 선택 과제로 자기 테스트 계정에서 만든 Windows 이벤트를 wevtutil로 내보내고 원시 XML과 비교할 수 있습니다. 외부 공유 전에 개인정보를 검토하세요.

이 프로젝트의 범위

SQLite는 실제 형식이지만 행은 교육용 합성 자료입니다. 실제 EVTX·메모리 이미지 수집·증거 법적 적격성까지 다루는 인증 과정은 아닙니다.
