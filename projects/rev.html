수행할 과제

  1. 소스는 처음 시도 동안 접어 두고 자체 컴파일한 바이너리의 문자열·분기·출력을 조사합니다.
  2. login/read/logout/unknown을 포함한 전이표와 Python 참조 구현을 직접 만듭니다.
  3. A/B 시퀀스를 실행해 출력과 복원 구현을 차등 비교합니다.
  4. 최적화된 바이너리를 비교하고 발견한 규칙의 근거·반례·ABI 제한을 보고합니다.

출력 계약

project-machine.c를 -O0/-O2로 빌드합니다. 각각의 표본 tokens를 argv에 순서대로 전달합니다. states는 명령 처리 후 상태의 배열, accepted는 성공 명령 수입니다. 알 수 없는 명령은 상태를 유지합니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 각 명령의 전후 상태와 허용 조건을 복원했다.
  2. A/B와 자신이 만든 반례에서 구현과 실행 결과를 비교했다.
  3. 정적 문자열의 존재와 실행 도달 여부를 구분했다.
  4. 빌드 옵션·도구 버전·관찰 근거를 포함했다.

보고서에 남길 것

범위·환경 → 예상 → 실제 관찰 → A/B 차이 → 반례와 수정 → 미확인 사항. 해시·종료 상태·테스트 결과만으로 모든 결론을 증명했다고 표현하지 마세요.

1–3일 뒤 답안 없이 B를 다시 풀거나 새 입력을 만들어 확인하세요. 설명이 막히면 해당 선행 차시로 돌아가 필요한 부분을 보충합니다.
