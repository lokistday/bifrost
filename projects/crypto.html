수행할 과제

  1. 가상 환경에서 고정 requirements.txt를 설치하고 공개 교육 키라는 범위를 적습니다.
  2. AES-GCM 검증과 시퀀스 검사 순서를 구현하고 A/B를 비교합니다.
  3. 인증 실패 요청의 큰 seq가 정상 요청을 막지 않도록 실패 후 last 상태를 확인합니다.
  4. 실제 봉투 재포장 예제를 실행한 증거와 정기 교체·유출 대응·서명 권한 검토를 함께 보고합니다.

출력 계약

기존 round2-crypto.json의 공개 DEK를 사용합니다. AAD는 UTF-8 JSON 배열 ["project-v1",tenant,document,version,seq]를 공백 없이 직렬화한 바이트입니다. seq도 인증 대상입니다. 인증 실패는 AUTH_FAIL, 인증 성공 후 seq>last일 때만 ACCEPT하고 last를 갱신하며 그 외에는 REPLAY입니다. last는 이 연습의 단일 blue/17/1 스트림 상태입니다.

project-answer-template.json의 필드와 타입은 유지하고 직접 계산한 결과를 새 answers-a.json·answers-b.json에 넣습니다. 빈 목록과 0은 자리표시자입니다.

결과를 확인하는 방법

각 분야 작업 폴더의 터미널에서 실행합니다. Linux/WSL/macOS는 python3, Windows PowerShell은 py -3를 사용하세요. Crypto는 가상 환경에 requirements.txt 설치가 필요합니다.

python3 project.py check answers-a.json --variant a
python3 project.py check answers-b.json --variant b

결과 검사기는 답안 JSON만 읽습니다. 코드를 실행하거나 서버로 제출하지 않습니다. 결과 일치(0)·불일치(1)·답안 입력 오류(2)를 구분합니다. 코드 품질과 보고서의 사실성은 아래 기준으로 별도 검토하세요.

완주를 판단하는 기준

항목별 0 = 근거 없음 · 1 = 설명만 가능 · 2 = 재현할 근거 있음. 8점은 자기 평가 척도이며 인증 점수가 아닙니다. 각 항목에 해당하는 파일·명령·이벤트 위치를 보고서에 연결하세요.

  1. 실제 인증 실패와 재전송 거부를 구분했다.
  2. 인증 실패한 요청이 상태를 갱신하거나 평문을 노출하지 않는다.
  3. A/B와 재시작·동시 처리의 한계를 설명한다.
  4. KEK/DEK 교체와 과거 노출·현재 권한을 구분해 검증 계획을 썼다.
