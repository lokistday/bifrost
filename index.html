01 / ROADMAP

방향은 일찍 정하고, 경험으로 다듬기

분야 선택을 기초 학습이 끝날 때까지 미루지 않습니다. 초반에 관심 방향을 정하고, 공통 기초와 분야 입문 실습을 병행하면서 경험에 따라 조정하세요.

STEP 00분야 탐색처음부터 시작

실력을 갖추기 전에도 관심 분야부터 정하기

지금 잘하는 분야를 고르는 단계가 아닙니다. 어떤 문제를 풀 때 궁금증이 생기는지 살펴보고, 우선 공부할 방향을 정합니다. 아래 설명은 직무를 확정하는 검사가 아니라 작은 실습을 고르기 위한 지도입니다. 경험이 쌓이면 분야를 바꾸거나 두 분야를 함께 탐색해도 괜찮습니다.

먼저 구분하기기초 역량(Foundation)은 특정 전문 분야가 아니라 모든 트랙을 받쳐주는 공통 기반입니다. 전문 분야를 고르더라도 Python/C, Linux, 네트워크, Git과 기록 습관을 관심 분야에 맞춰 병행하세요.
01

Web Hacking

웹 서비스가 왜 안전하지 않게 동작할까?

주로 다루는 문제
로그인·권한 오류, 입력값 처리, 데이터 노출, 웹/API 요청 흐름
만나는 개념
HTTP, 쿠키·세션, 인증·인가, SQL, 출력 인코딩, API
잘 맞을 수 있는 관심
웹사이트가 동작하는 방식, 사용자와 서버 사이의 흐름, 문제를 수정해 확인하는 과정이 재미있다.
도움 되는 기초
HTTP 기초와 Python 또는 JavaScript 입문. 처음부터 고급 코딩을 알 필요는 없다.
첫 실습
로컬 데모 앱이나 허가된 교육 랩에서 요청·응답을 살펴보고, 취약한 입력 처리와 안전한 수정의 차이를 기록한다.
학습 경로 공통 기초 → Web Hacking 차시 → 안전한 수정·회귀 테스트 프로젝트
02

Pwn / System

프로그램과 운영체제 내부에서 무슨 일이 일어날까?

주로 다루는 문제
메모리 오류, 프로그램 실행 흐름, 권한 경계, 시스템 수준의 취약점
만나는 개념
C, 포인터, 스택·힙, 프로세스, 디버거, 완화 기법
잘 맞을 수 있는 관심
낮은 수준의 동작을 파고들고, 오류가 발생하는 정확한 조건을 추적하는 것이 좋다.
도움 되는 기초
C 문법, 주소·메모리 개념, Linux 터미널. 생소하면 C 기초부터 천천히 시작한다.
첫 실습
자신이 만든 작은 C 프로그램을 디버거로 실행하고 변수·주소·실행 흐름이 어떻게 바뀌는지 관찰한다.
학습 경로 C·Linux 기초 → 로컬 교육용 바이너리 → 오류 원인과 방어 방법 기록
03

Reverse Engineering

소스 코드가 없어도 실행 파일의 동작을 알아낼 수 있을까?

주로 다루는 문제
실행 파일의 동작 파악, 함수·조건 분기 추론, 의심스러운 프로그램 분석
만나는 개념
어셈블리, 레지스터, 함수 호출, 정적·동적 분석, 디컴파일
잘 맞을 수 있는 관심
퍼즐처럼 단서를 연결하고, 관찰 근거를 바탕으로 동작을 추론하는 일을 즐긴다.
도움 되는 기초
C 기초와 함수·조건문 이해가 도움이 된다. 어셈블리는 작은 예제부터 익힌다.
첫 실습
직접 컴파일한 짧은 프로그램이나 공개 교육용 바이너리에서 문자열·함수·분기 흐름을 확인하고 추론을 기록한다.
학습 경로 C 기초 → 어셈블리·디버거 → 분석 근거와 추론을 구분한 보고서
04

Forensic

남아 있는 디지털 흔적으로 어떤 일이 있었는지 설명할 수 있을까?

주로 다루는 문제
로그와 이벤트 분석, 파일 흔적 보존, 증거 상관관계와 사건 시간순서 재구성
만나는 개념
로그 필드, 파일 시스템, 해시, 메타데이터, 타임라인, 증거 보존
잘 맞을 수 있는 관심
관찰한 사실을 꼼꼼히 비교하고, 증거와 추측을 구분해 설명하는 것이 좋다.
도움 되는 기초
파일 시스템, 타임스탬프, 로그 형식과 증거 보존의 기초가 도움이 된다. 네트워크 분석은 별도 Network Security 트랙에서 깊게 다룬다.
첫 실습
교육용 샘플 로그와 파일 메타데이터를 분석해 사건 타임라인을 만들고, 증거와 추론 및 한계를 구분해 기록한다.
학습 경로 증거 수집·보존 → 로그·파일 분석 → 타임라인과 근거 중심 보고서
05

Network Security

네트워크 통신을 관찰하고 위협을 찾아 방어할 수 있을까?

주로 다루는 문제
프로토콜 이해, 트래픽 분석, 서비스 노출과 통신 보안, 네트워크 방어
만나는 개념
TCP/IP, DNS, HTTP/TLS, 포트, Wireshark, 방화벽과 세그먼테이션
잘 맞을 수 있는 관심
통신이 오가는 과정을 추적하고, 시스템 간 연결과 방어 방법을 이해하는 일이 흥미롭다.
도움 되는 기초
IP·HTTP·Linux 기초에서 시작해 웹 인가·클라우드 네트워크를 연결한다. 설계 모듈은 여러 분야를 함께 보는 중급 과정이다.
첫 실습
교육용 PCAP에서 DNS 질의와 TCP 연결을 찾아 흐름을 정리하고, 관찰 가능한 정보와 암호화로 보이지 않는 정보를 구분한다.
학습 경로 패킷·TLS 관찰 → 망 분리·최소 허용 → 탐지·Zero Trust → 통합 설계
06

Cryptography

데이터의 비밀과 진위를 어떤 보장으로 지킬 수 있을까?

주로 다루는 문제
기밀성·무결성·인증, 암호 프로토콜과 키 관리
만나는 개념
정수·모듈러 연산, 대칭키·공개키, 해시·MAC, nonce와 키 수명
잘 맞을 수 있는 관심
규칙을 찾고 가설을 시험하거나, 작은 도구를 만들어 문제를 해결하는 것이 재미있다.
도움 되는 기초
기초 수학과 Python이 유용하지만, 처음에는 Base64와 간단한 치환 문제부터 시작할 수 있다.
첫 실습
인코딩과 암호화의 차이를 확인하고, 쉬운 교육용 문제 하나를 풀이 과정과 검증 방법까지 기록한다.
학습 경로 표현·수학 → 무결성·인증 → 현대 암호와 키 관리

첫 실습
제공된 텍스트에서 필드를 추출하고 두 단계 변환을 검증합니다.

08

Cloud Security

누가 어떤 자원에 접근하고, 누가 설정을 책임질까?

주로 다루는 문제
공동 책임, IAM, 네트워크, 데이터 공개, 비밀 관리와 감사
도움 되는 기초
네트워크·웹 인가·JSON 읽기
첫 실습
계정과 결제 없이 로컬 구성 파일을 검토하고 수정안을 작성합니다.
Cloud Security 과정 열기 ↗

아직 무엇을 고를지 모르겠다면

  1. 문제 유형으로 고르기: 웹 요청과 권한은 Web, 메모리와 실행 흐름은 Pwn/System, 실행 파일의 내부 동작은 Reverse Engineering, 디지털 증거와 로그는 Forensic, 프로토콜과 트래픽 방어는 Network Security, 암호 원리·키 관리는 Cryptography, 단서·자동화는 Misc, 클라우드 신원·구성은 Cloud Security를 먼저 살펴보세요. Network Security는 이 지식을 연결해 통합 방어로 확장합니다.
  2. 작게 시험하기: 관심 분야 2개를 골라 각각 30–60분짜리 입문 실습을 하나씩 해봅니다. 어려웠는지보다 과정이 궁금했는지, 더 알아보고 싶은지가 중요한 신호입니다.
  3. 임시 선택하기: 주 관심 분야 1개와 보조 분야 1개를 정하고, 공통 기초와 함께 2–3주 경험해 봅니다. 마음이 바뀌면 선택을 업데이트하세요.
  4. 기록으로 비교하기: 흥미도, 막힌 개념, 실습 후 새로 생긴 질문, 결과를 설명할 수 있는 정도를 짧게 적어 다음 선택에 활용합니다.

안전 원칙: 실습은 직접 만든 환경, 본인이 소유한 시스템, 또는 명시적으로 허가된 교육용 랩과 샘플 데이터에서만 진행하세요. 실제 서비스나 타인의 장비를 대상으로 시험하지 않습니다.

다음 단계 기준 — 완벽한 확신 대신 관심 분야 1개와 보조 분야 1개를 임시로 고르고, 첫 입문 실습과 함께 배울 공통 기초를 말할 수 있다.

  • Linux / Shell — Windows에서 시작하는 방법 ↗

STEP 03집중 학습선택 분야 심화

기초와 실습 경험을 연결해 깊이 파고들기

선택 분야의 핵심 개념과 도구를 체계적으로 익히고, 난도를 조금씩 높여 갑니다. 필요하면 처음 선택한 분야를 조정해도 됩니다.

  • 분야별 핵심 개념
  • 중급 실습과 워게임
  • 도구 사용과 분석 방법
  • 취약점 원리와 방어 관점
다음 단계 기준 — 단순히 따라 하는 수준을 넘어 문제의 원인과 해결 과정을 설명할 수 있다.

  • 심화 실습과 CTF
  • 코드 분석과 자동화
  • 기술 보고서
  • GitHub 포트폴리오
도달 목표 — 결과를 재현하고, 선택한 기술과 판단 근거를 다른 사람에게 설명할 수 있다.

03 / PRACTICE LOOP

읽고 끝내지 말고, 직접 확인하기

각 학습은 이해 → 실습 → 기록 → 다음 단계의 흐름으로 이어집니다. 정답 맞히기 퀴즈 대신 직접 실행하고 설명할 수 있는 결과물을 만듭니다.

01 / UNDERSTAND
⌕

개념 이해하기

왜 필요한 개념인지, 어떤 상황에서 쓰이는지, 무엇과 연결되는지 먼저 파악합니다.

남길 것
핵심 개념 3~5줄과 간단한 그림 또는 흐름도
02 / TRY IT
⌘

안전한 환경에서 실습하기

로컬 환경이나 허가된 학습 플랫폼에서 동작을 재현하고, 결과를 관찰합니다.

남길 것
실행 명령, 입력값, 관찰 결과, 실패 원인
03 / DOCUMENT
↗

기록하고 다음으로 이동하기

무엇을 배웠는지와 아직 모르는 점을 정리하고, 다음 차시로 넘어갈 준비를 합니다.

남길 것
README 또는 Write-up, 후속 학습 질문
04 / CAREER & RESOURCES

학습을 실제 결과물로 연결하기

자격증이나 도구의 개수보다, 무엇을 이해했고 직접 무엇을 만들고 검증했는지 보여주는 것이 중요합니다.

01

분석 Write-up

문제의 핵심, 접근 과정, 막힌 지점, 해결 원리, 재발 방지 관점을 정리합니다.

  • 풀이만 복사하지 않기
  • 핵심 코드와 패킷 설명
  • 배운 점과 한계 기록
02

작은 보안 프로젝트

취약점 재현, 안전한 수정, 회귀 테스트까지 연결해 하나의 완성된 결과물로 만듭니다.

  • 실행 가능한 코드
  • 명확한 README
  • 재현 및 검증 절차
03

진로 탐색

웹 모의해킹, 시스템 보안, 리버싱, 보안관제 등 관심 직무의 실제 업무와 요구 역량을 비교합니다.

  • 공개 채용 공고 읽기
  • 관심 분야 프로젝트 연결
  • 부족한 역량 목록화
Dreamhack웹·시스템 보안 실습학습 플랫폼 ↗
CTFtime대회 일정과 정보대회 찾아보기 ↗
GitHub코드와 학습 기록저장소 만들기 ↗
OWASP웹 보안 지식과 자료공식 자료 ↗
↗
진로와 병역 관련 선택은 별도로 확인하세요군 복무 경로는 개인 상황에 따라 달라지는 선택지 중 하나입니다. 필요해지는 시점에 공식 모집·편입 요건을 확인하고, 학습 로드맵과는 별도로 판단하세요.
05 / LEARNING PRACTICES

커리큘럼을 더 탄탄하게 만드는 공통 습관

기술 지식과 함께 조사·검증·실습·기록 습관을 익히면 어떤 트랙에서도 학습을 이어가기 쉬워집니다.

⌕

학습 습관

모르는 개념을 검색하고 출처를 검증하는 방법을 연습합니다.

  • 공식 문서와 신뢰할 수 있는 자료를 우선 확인
  • 서로 다른 출처를 비교하고 게시 날짜·버전을 확인
  • 확인한 사실과 불확실한 내용을 구분
기대 효과: 초보자의 막힘을 줄이고 잘못된 정보에 의존할 가능성을 낮춥니다.
⌘

공통 기초

Git 기초와 명령어 사용 연습을 작은 결과물로 연결합니다.

  • status, diff, log로 변경 내역 확인
  • 작은 단위로 커밋하고 README에 실행법 기록
  • 반복 실습에 쓸 명령어와 스크립트를 정리
기대 효과: 이후 모든 트랙에서 학습 기록과 실습 결과를 재사용할 수 있습니다.
◇

보안 사고방식

기능이 동작하는지만 보지 말고 위험 모델과 신뢰 경계를 함께 생각합니다.

  • 위험 모델과 공격 표면을 간단히 적기
  • 최소 권한 원칙을 적용할 위치 찾기
  • 사용자 입력과 신뢰 경계를 구분
기대 효과: 도구 사용을 넘어 보안 원리와 설계 이유를 이해하게 됩니다.
▣

실습 안전

실습 전에 환경·권한·데이터·복구 방법을 확인합니다.

  • 가상 머신 또는 로컬 랩 사용
  • 샘플 데이터와 허가된 대상만 사용
  • 실습 범위와 중단·복구 방법 확인
기대 효과: 안전하고 반복 가능한 실습 환경을 만들 수 있습니다.
⌁

분석 능력

관찰한 사실·추론·미확인 사항을 구분해 결론의 품질을 높입니다.

  • 원본 증거와 재현 절차를 보존
  • 사실과 가설을 분리하고 대안 설명 고려
  • 결론을 뒷받침하는 근거를 명시
기대 효과: 분석의 정확성과 보고서 품질을 높일 수 있습니다.
↗

결과물 관리

학습 결과를 다른 사람이 따라 할 수 있는 작은 포트폴리오로 바꿉니다.

  • README에 목표·환경·재현 절차 작성
  • 결과뿐 아니라 한계와 방어 방법 기록
  • 민감 정보·토큰·개인 데이터를 제거
기대 효과: 학습 결과를 포트폴리오로 전환하고 나중에 다시 활용할 수 있습니다.
