# 실제 FAT12 볼륨 실습 · 2026-11-09

원 감사의 실제 디스크 이미지 연결 과제를 진행했다. forensic.filesystem-records의 기존 inode/하드링크 JSON 모형을 유지하고, 별도 실제 FAT12 볼륨 구조 읽기를 연결했다. 153개 차시와 기존 ID는 유지한다.

## 추가 자료

fat12_lab.py와 FAT12-GUIDE.md를 원본·명시적 배포 목록·forensic.zip에 포함했다. Python 표준 라이브러리로 학습자의 새 폴더에 결정적인 1440 KiB(1,474,560바이트) FAT12 볼륨을 생성한다. 생성 표본은 실제 사용자 디스크의 획득물이 아니며 MBR 없는 단일 볼륨이다. 마운트/관리자 권한 없이 읽는다.

BPB 원시 바이트와 little-endian 해석, 섹터/바이트 위치 표, 루트 엔트리, 12비트 FAT, 조각 연결 2→5→3, 파일 논리 크기·슬랙을 설명한다. README 1100바이트를 추출하고 물리적 연속 복사와 다른 결과를 비교한다. 삭제 표시와 비할당 잔여 바이트는 단서로만 표시하며 자동 복구하지 않는다.

정상과 순환/이른 EOC/FAT 사본 불일치/잘린 볼륨을 비교한다. 기존 폴더·출력·입력 파일을 덮어쓰지 않는다. 표본 해시와 독립 도구의 추출 바이트를 함께 대조한다.

## 검증

WSL의 Sleuth Kit fsstat가 자동으로 FAT12를 식별했다. fls의 루트 목록과 icat의 README 추출이 Python 결과와 바이트 단위로 일치했다. 단순히 생성 스크립트가 자기 결과를 맞다고 판정한 것으로 끝내지 않았다.

새 7개 실행 검사는 BPB/엔트리 위치, 조각 연결/슬랙/빈 파일, 손상 사본, 기존 출력/원본 보존, 결정적 생성/잘못된 라벨, 잘못된 클러스터/교차 연결, 독립 도구를 다룬다. CI에 Sleuth Kit 설치와 실행 검사를 추가했다.

기존 모의고사 한 문항의 근거 문단이 개편 전 문구를 정확히 고정해 검사에서 실패했다. 문제·정답은 바꾸지 않고 forensic-m05-q18의 근거를 같은 주장과 모형/FAT12 범위를 구분한 현재 강의 문단으로 갱신했다. 원래의 정확한 근거 일치 검사는 유지한다.

## 지원 범위와 남은 일

검사기는 제공한 FAT12 지오메트리와 루트의 ASCII 8.3 archive 파일만 지원한다. 긴 이름·하위 디렉터리·다른 FAT 형식·NTFS/ext4·삭제 복구·전체 파일시스템 검증은 범위 밖이다. FAT의 로컬 시각에 없는 시간대 정보를 임의 UTC로 채우지 않는다.

실제 EVTX·레지스트리·Prefetch/Amcache·RAM 이미지는 아직 미완료다. PDF/JPEG/ZIP 전체 구조 실습도 별개다. 미제작 모의고사 32개 모듈과 웹 업로드/클라우드 kind 실행 검증은 이번 범위에 포함하지 않았다.
