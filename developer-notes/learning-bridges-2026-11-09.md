# 공통 기초 → C/GDB → 어셈블리 연결 실습 · 2026-11-09

기준: learning-content-audit-2026-11-05.md의 권장 순서 2번. 153개 차시와 기존 영구 ID는 유지하고 5개 차시를 보강했다.

- foundation.python-flow: 목록 위치/사전 키/키 생략, 회차별 누적 표, 실행 예측, 빈칸, 직접 함수 작성과 세 사례 검사. 미완성 파일은 실패하도록 제공하며 참조 구현은 분리한다.
- foundation.c-memory: 실제 배열·원소 개수·함수 인자/반환·문자열 NUL, 반복별 합계 표, 원소 수/문자열 변경 사본 과제. 범위 밖 읽기와 포인터 sizeof를 원소 수로 오해하지 않도록 구분한다.
- pwn.debugger: 동일한 call_bridge 예제로 C 값 → main/adjust 프레임 → 인자/반환 레지스터 → 스택 메모리/복귀 주소 → 호출자 결과를 연결한다. +3을 +4로 바꾼 예측/재실행도 제공한다. 정적 코드/데이터와 힙 관찰의 범위를 명시한다.
- rev.assembly: 짧은 자체 제작 x86-64 AT&T 어셈블리와 EAX·CF·ZF 상태표. unsigned 비교/분기·경계·wrap, 직접 C 번역과 새 입력을 대조한다.
- rev.dynamic: 현재 Linux 아키텍처에서 자체 제작 ELF를 빌드하고 일반 심볼을 제거한다. 소스 열람 전 함수/입력 조건을 복원하고 정상 두 개·반례 세 개로 검증한다. 재현용 소스는 ZIP에 포함되므로 완전히 소스가 비공개인 과제는 아니다.

14개 실습 원본을 명시적 배포 목록에 등록하고 해당 분야 ZIP·SHA256 목록·차시 다운로드 링크에 포함했다. 새 파일은 원본 보존/새 작업 폴더 원칙을 따른다. 코드와 상태표는 강의의 단계별 실습 및 해설에 연결했다.

## 검증

WSL Linux x86-64에서 새 실행 검사 6개를 모두 통과했다. Python 미완성/완성, C 원본/변경본, 실제 GDB 프레임·저장된 복귀 주소·반환 레지스터, 어셈블리 경계와 wrap, strip된 ELF 정상/거부/인자 수/덮어쓰기 방지를 실행했다. CI에 검사와 GDB 설치를 추가했다.

기존 전체 JavaScript 검사, 실습 생성 재현·패키징 검사, 425문항 정답 검사, 분야 확장 검사, 독립 프로젝트와 기존 C 실습도 재실행한다. 공통 기초·리버싱도 과목별 JS 해시를 사용해 변경 과목의 번들만 캐시를 갱신한다. 다른 분야의 공유 자산 캐시 버전은 유지한다.

## 남은 범위

이 작업은 입문에서 후속 실습으로 가는 중간 다리다. 모든 공통 기초나 시스템·리버싱 주제를 전면 개편하거나 고급 익스플로잇, PE/Windows 분석, 디컴파일러 과정을 완성한 것은 아니다. x86-64 어셈블리와 프레임 포인터 관찰 절차는 해당 빌드·ABI·멈춤 위치에 한정한다. 학습자 성취도/실제 소요 시간은 아직 측정하지 않았다.
