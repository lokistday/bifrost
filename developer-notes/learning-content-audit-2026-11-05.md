# 학습 콘텐츠 재검토 · 2026-11-05

## 범위와 판단 기준

9개 분야, 49개 모듈, 153개 차시의 구성과 예제·과제 유형을 대조하고, 주요 차시의 개념·단계별 설명 및 실습 원본을 읽었다. 검토 대상은 content/courses, scripts/lab_sources, 프로젝트 자료, 모의고사 구성이다. 실제 학습자를 대상으로 한 완주·성취도 실험이나 모든 예제의 새 실행 검증은 이번 검토에 포함하지 않았다. 사이트 수정·추가 배포는 하지 않았다.

판단은 기초 학습자가 제공 예제를 따라간 뒤 처음 보는 자료에 적용할 수 있는지에 초점을 두었다. 실습 모형은 유용한 입문 단계이며, 모형 뒤에 실제 형식·도구로 이어지는 단계가 부족한 것을 별도 문제로 본다. 고급 주제 전체를 필수 과목으로 간주하지 않는다.

## 유지할 장점

- 원본 보존, 근거 기록, 정상·오류·경계값 비교가 반복적으로 연결된다.
- 기대 출력과 단계별 실행 안내, 조건 변경 과제, 프로젝트 A/B 자료가 있다.
- 모형의 PASS를 실제 안전성이나 악성 판정으로 확대하지 않도록 범위를 명시한다.
- 시스템·리버싱은 실제 C 빌드와 GDB를 사용한다. 암호학은 실제 AES-GCM·Ed25519 검증이 있고 네트워크에는 실제 TLS 1.3 협상으로 제작한 PCAP과 교육용 키로그가 있다.

## 분야별 발견과 보완 방향

### 디지털 포렌식 · 높은 우선순위

- forensic.file-signatures: BF 2바이트 + 길이 2바이트의 가상 형식, 15바이트 fragments.hex를 검색한다. 오프셋·잘림·후보의 한계는 설명하지만 실제 PNG/JPEG/PDF의 헤더·구조·검증으로 이어지지 않는다.
- misc.container-identification에 gzip/ZIP 후보 설명이 있으나 포렌식의 실제 파일 구조 읽기 과정을 대신할 정도는 아니다.
- forensic.windows-events는 실제 EVTX가 아닌 합성 XML, forensic.filesystem-records는 파일시스템 기록의 JSON 모형, forensic.memory-triage는 실제 RAM 덤프가 아닌 JSON 영역 모형이다. 브라우저 SQLite 실습처럼 실제 저장 형식으로 연결된 부분도 있다.
- 보완: 실제 형식의 교육용 정상/손상 파일 → Hex/ASCII/오프셋 표 → 확장자·형식·구조 대조 → 작은 연속 표본 추출 → 열림/파싱 검증 → 보존·해시·보고.
- 다음 단계: 작은 디스크 이미지의 파일시스템 구조, 실제 이벤트·레지스트리·실행 흔적, 교육용 메모리 덤프를 순차 추가한다. MFT/USN/Prefetch/Amcache 등은 확장 과정으로 배치한다.
- 헤더·푸터 암기만으로 모든 파일을 복구할 수 있다고 가르치지 않는다. 형식별 구조, 길이/검사값, 조각화·덮어쓰기와 복구 가능 범위를 구분한다.

### 웹 보안 · 높은 우선순위

- web.flow/output의 실제 DOM 비교와 SQL 바인딩 예제는 유지할 가치가 있다.
- web.sessions는 requests.txt와 개념 흐름, CSRF/CORS/CSP는 Python 모형·체크리스트 비중이 크다. web/LAB-GUIDE.md도 외부 요청·서버·실제 쿠키·계정이 없다고 명시한다.
- 결과를 이해해도 브라우저에서 요청을 찾고 수정·재전송하거나 서버 응답과 연결하는 경험이 부족할 수 있다.
- 보완: 로컬 교육용 앱에 두 사용자·세션·개인 자료를 넣고, 실제 로그인/로그아웃/인가 실패/CSRF/CORS/CSP를 요청·응답·DOM 증거로 검증한다.
- 추가 후보: 비밀번호 저장·검증과 로그인 시도 제한, 파일 업로드의 multipart·형식·저장 정책. OAuth/OIDC/JWT는 기초 흐름 정착 후 선택 확장한다.

### 클라우드 보안 · 높은 우선순위

- cloud.iam은 교육 식별자 ReadObject와 review.py, cloud.kubernetes-rbac는 단일 Role/Binding의 JSON 모형이다. 실제 정책 엔진·클러스터 검증을 수행하지 않는다.
- 고급 권한 조합 주제에 비해 클라우드 기본 구조와 실제 설정 문서를 읽는 연결 단계가 얕다.
- 보완: 계정·리전·네트워크·신원의 관계 그림 → 실제 형식의 IAM 정책 JSON/Role YAML 해설 → 정상·거부 사례 → 선택형 격리 환경 실습으로 이어간다.
- 실제 자원 생성을 필수화하기 전에 오프라인 문서 분석 과정을 제공하고, 실행형 과정에는 비용·정리 절차와 예상 결과를 포함한다.

### 시스템 보안 · 중상 우선순위

- 실제 C 예제와 경계·정수·소유권·부분 I/O 실습은 탄탄하다.
- foundation.c-memory에서 포인터를 접한 뒤, 호출 스택·레지스터·반환 주소·메모리 구간을 연결해 관찰하는 중간 다리가 얕다. pwn.debugger는 소스 수준 변수 관찰이 중심이다. 레지스터 관찰은 리버싱 호출 규약 차시에도 분산돼 있다.
- 보완: C 배열·문자열·함수 복습, 한 번의 호출 전후 스택 그림, GDB의 레지스터/메모리/호출 스택 관찰을 하나의 예제에 묶는다.
- Pwn 명칭으로 기대하는 취약점 분석을 제공하려면 교육용 오류 재현 → 상태 관찰 → 원인 설명 → 수정 검증을 강화한다. 고급 우회·익스플로잇 체계는 별도 확장 범위다.

### 리버싱 · 중상 우선순위

- ELF·호출 규약·최적화·재배치까지 다루지만 rev.assembly에서 명령어를 처음 읽는 학습자에게 필요한 레지스터·메모리 피연산자·플래그·조건 분기 설명이 압축돼 있다.
- 직접 빌드한 소스와 심볼이 있는 프로그램에서 출발하므로, 소스 없는 분석으로 넘어가는 연습을 보강해야 한다.
- 보완: 10줄 내외 어셈블리를 단계별 상태표로 읽기 → 심볼 없는 자체 제작 바이너리 → 함수 경계·흐름 복원 → 입력 반례로 검증.
- PE·Windows 분석과 디컴파일러 사용은 Linux ELF 입문과 구별되는 선택 확장 과정으로 제시한다.

### 네트워크 보안 · 중간 우선순위

- Wireshark 표본, TLS 1.3 자료, IPv6·MTU·재조립·DNS 캐시까지 있다. TLS나 패킷 실습 자체가 없다는 평가는 부정확하다.
- 초반 일반 PCAP은 8프레임의 단순 합성 통신이고, 후반 경로·상태·정책은 Python 모형 비중이 높다. 실제 설정/장애를 확인하는 연결 단계가 부족하다.
- 보완: CIDR 계산·ARP/ICMP/UDP 등 기초 보충, 잡음·복수 연결·실패 패킷이 섞인 자료, 격리 환경의 실제 경로/방화벽 변경 전후 비교.

### 공통 기초 · 중상 우선순위

- Python 조건·반복·함수를 한 차시에서 시작하고, 이후 JSON 계약·깊은 복사·원자적 출력까지 빠르게 진행한다.
- dict/list 인덱싱·순회·키 조회와 C 배열·함수·문자열 같은 기본 조작은 후속 차시를 읽기 전에 별도 짧은 연습이 있으면 좋다.
- 보완: 차시 수부터 늘리기보다 작은 실행 예측·빈칸 완성·직접 작성 과제를 앞부분에 넣고, 후반 개념에 필요한 기본 조작을 먼저 연결한다.

### 암호학 · 중간 우선순위

- 실제 라이브러리 기반 AEAD·서명, nonce·키 수명·재전송·문맥 결합은 강점이다.
- 모듈러 역원 이후 공개키·대칭키의 작동 원리를 직관적으로 이해하는 다리가 짧다. 주어진 암호문·서명을 검증하는 경험과 직접 작은 프로그램을 구성하는 경험도 구분해야 한다.
- 보완: 해시·MAC·서명·암호화 비교도, 작은 수의 RSA/키 교환 원리 예제, 라이브러리로 독립적인 생성→저장→검증 왕복 과제. 장난감 수학 예제를 운영용 구현으로 재사용하지 않도록 범위를 명시한다.

### 문제 해결·자동화 · 중간 우선순위

- 변환·정규식·컨테이너·그래프 탐색·제약·압축 한도·재개까지 구성돼 있다.
- 미리 제공된 실행 모드를 따라가는 과정에서 어떤 도구와 해석 경로를 선택할지 스스로 결정하는 훈련이 약해질 수 있다. 이미지 형식은 작은 PPM, 컨테이너는 작은 메모리 표본 중심이다.
- 보완: 확장자를 가린 다양한 정상·손상 자료, 분석 경로를 선택해야 하는 혼합 과제, 작은 완전 탐색에서 후보 증가·가지치기를 비교하는 과제. 고급 스테가노그래피/SMT는 선택 확장한다.

## 공통 보완

1. 설명의 한계 고지는 유지하되, 실제 바이트/요청/설정 문서로 연결하는 한 단계씩을 추가한다.
2. 같은 예제의 값 변경 외에 도구 선택부터 해야 하는 새 자료를 제공한다. 기존 프로젝트 A/B는 유지한다.
3. 모의고사는 현재 공통 기초 5개 모듈에 25문항씩 있다. 다른 44개 모듈은 미완성이다. 분야별 독립 과제·프로젝트가 이미 있으므로 평가가 전혀 없는 것으로 표현하지 않는다.
4. 신뢰 경계·형식 검증·한계 설명이 반복되는 장점은 유지하면서 각 분야 고유의 기본 지식과 아티팩트에 더 많은 학습 시간을 배정한다.
5. 내용을 늘릴 때 '왜 이렇게 판정하는지'를 설명하는 도식·Hex 주석·전후 상태표를 먼저 추가한다. 텍스트 양만 늘리지 않는다.

## 권장 작업 순서

## 확인한 외부 기준

- PNG 구조: https://www.w3.org/TR/PNG-Structure.html — 시그니처와 IHDR/IEND를 포함한 구조가 별개로 필요함.
- NIST SP 800-86: https://csrc.nist.gov/pubs/sp/800/86/final — 파일·운영체제·네트워크·응용 자료와 처리 절차.
- OWASP WSTG: https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/ — 인증·인가·세션·입력·업무 로직의 시험 범주.
- GDB: https://sourceware.org/gdb/current/onlinedocs/gdb — 레지스터·메모리·호출 스택 관찰.
- Kubernetes RBAC: https://kubernetes.io/docs/reference/access-authn-authz/rbac/ — 실제 Role/Binding과 정책 형식.
- Volatility 3: https://volatility3.readthedocs.io/en/stable/ — 실제 메모리 이미지 분석으로 이어지는 후속 도구 범위.
