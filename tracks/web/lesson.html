WHAT YOU WILL BUILD

이 과정을 마치면

로컬 표본으로 필드·권한·수명·공유·재시도의 경계를 분석하고 정상 기능과 거부·복구 상태를 함께 검증합니다.

01 · 웹의 동작과 데이터

브라우저 예제는 파일을 직접 열고, Python 예제는 오프라인 메모리 DB에서 실행합니다.

  1. HTML·DOM과 요청 흐름브라우저가 문서를 해석하는 과정과 데이터가 코드가 되는 지점을 구분합니다.↗
  2. SELECT·WHERE와 매개변수데이터 조회 조건을 작성하고 SQL 문법과 값을 분리합니다.↗
  3. 쿠키·세션·인증신원 확인과 상태 유지가 어느 쪽에서 처리되는지 설명합니다.↗

02 · 권한·입력 처리·검증

예제는 sqlite3 메모리 DB와 함수 호출에서만 동작합니다. 네트워크에 취약한 서버를 열지 않습니다.

  1. 리소스 단위 인가로그인 사용자라도 다른 사람의 자료에 접근하지 못하게 검사합니다.↗
  2. SQL Injection과 바인딩입력이 쿼리 문법에 섞이는 경우와 값으로만 전달되는 경우를 비교합니다.↗
  3. 출력 컨텍스트와 XSS 방어브라우저에서 데이터를 코드로 해석하지 않도록 출력 방법을 고릅니다.↗
  4. 수정·반례·회귀 테스트취약한 동작만 막는 것이 아니라 정상 기능도 유지되는지 확인합니다.↗

03 · 브라우저와 서버의 신뢰 경계

CSRF·CORS·CSP가 서로 다른 질문에 답한다는 것을 요청·응답 표본으로 구분합니다.

  1. CSRF와 상태 변경 요청로그인 쿠키의 존재와 사용자 의도 확인을 구분하고 정상·위조 상태 변경을 비교합니다.↗
  2. 동일 출처·CORS·응답 읽기 권한브라우저의 교차 출처 응답 접근과 서버의 인증·인가를 분리해서 설명합니다.↗
  3. CSP·보안 헤더와 적용 범위정책 전달·보고 전용·브라우저 집행을 구분하고 CSP의 보완 역할을 검토합니다.↗

04 · 파일과 외부 요청의 경계

파일 이름과 URL을 좁은 계약으로 검사하고 실제 저장·연결에서 남는 검증을 정리합니다.

  1. 파일 이름·경로 이탈·저장 경계파일 이름을 신뢰 경계로 다루고 허용 이름·정규화 경로·인가의 역할을 분리합니다.↗
  2. SSRF·서버 요청과 출구 통제서버가 대신 요청하는 기능의 신뢰 경계를 분석하고 URL 구문 검사만의 한계를 설명합니다.↗

05 · 요청 계약과 제한된 권한

수정 필드·세션 수명·복구 토큰의 범위를 명시하고 정상·거부·재사용 상태를 비교합니다.

  1. 요청 계약과 Mass Assignment클라이언트가 수정할 필드와 서버가 관리하는 필드를 나누고 임의 필드 덮어쓰기를 거부합니다.↗
  2. 세션 갱신·만료·서버 무효화로그인 전후 식별자 교체와 로그아웃·만료의 서버 측 상태 변화를 추적합니다.↗
  3. 일회 토큰·목적 결합·만료복구용 권한을 사용자·목적·만료·한 번 사용이라는 계약에 묶어 검증합니다.↗

06 · 공유와 거래의 일관성

개인 응답의 캐시 재사용과 거래 재시도에서 지켜야 할 상태 불변 조건을 검증합니다.

  1. 개인 응답·공유 캐시·Cache-Control개인화된 응답의 잘못된 공유를 재현하고 no-store·private·no-cache의 뜻을 구분합니다.↗
  2. 거래 불변 조건·트랜잭션·재시도재고 변경과 주문 기록을 함께 처리하고 같은 요청의 재시도를 중복 효과 없이 검증합니다.↗
