01 / UNDERSTAND

먼저 이해하기

HTML은 문서 구조, CSS는 표현, JavaScript는 동작을 담당합니다. 브라우저는 HTML을 DOM이라는 노드 구조로 만듭니다. 서버가 문자열을 반환하는 일과 브라우저가 그것을 HTML로 해석하는 일은 서로 다른 단계입니다.

browser.html은 같은 문자열을 textContent와 innerHTML에 넣습니다. 전자는 문자 그대로 표시하고 후자는 태그를 해석합니다. 예제는 고정된 문자열만 사용합니다. 사용자 데이터를 innerHTML에 넣는 습관이 왜 위험한지는 출력 차시에서 이어 봅니다.

브라우저의 Elements 화면은 현재 DOM을 보여 줍니다. 원본 HTML에 비어 있던 p 요소도 JavaScript 실행 후에는 자식을 가질 수 있습니다. 따라서 원본 파일을 읽은 결과와 실행 뒤 DOM 관찰을 같은 것으로 취급하지 않습니다.

서버가 있는 웹에서는 사용자 동작 → HTTP 요청 → 서버 처리와 필요한 DB 조회 → 응답 → DOM 갱신 같은 흐름이 생깁니다. 이 파일 예제는 마지막 DOM 해석의 차이를 따로 떼어 관찰합니다. DB를 직접 브라우저가 읽는 것처럼 화살표를 그리지 않도록 요청 경계를 표시하세요.

같은 데이터라도 어느 API로 어느 위치에 넣느냐에 따라 의미가 달라집니다. 굵은 글씨가 보인다는 사실만으로 스크립트 실행을 입증한 것은 아닙니다. 이번 비교의 관찰 결론은 태그 해석 유무입니다.

자주 헷갈리는 지점

Elements와 원본 파일이 언제나 동일하다고 생각한다.
JavaScript 실행과 사용자 동작으로 DOM이 달라질 수 있으므로 관찰 시점을 적습니다.
고정된 b 태그의 해석을 곧바로 XSS 성공이라고 부른다.
이번 결과는 HTML 해석 여부입니다. 신뢰 경계와 실행 가능한 문맥은 출력 보안 차시에서 추가로 검토합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 같은 입력값을 확인하기

    browser.html의 sample이 두 대입문에서 동일하게 사용되는지 읽습니다. 입력을 고정하면 출력 차이가 자료 자체가 아니라 API 선택에서 왔음을 비교하기 쉽습니다.

    작게 나눠 확인하기
    const sample = '<b>Bifrost</b>';
    관찰할 결과
    두 대상에 같은 문자열을 전달합니다.

  2. 화면과 DOM을 함께 보기

    Elements에서 p#text를 펼치면 태그 기호가 포함된 텍스트가 보이고 p#markup 아래에는 b 요소가 생깁니다. 화면의 굵기와 DOM 요소의 존재를 같은 기록에 남깁니다.

    작게 나눠 확인하기
    document.querySelector("#text").textContent = sample;
document.querySelector("#markup").innerHTML = sample;
    관찰할 결과
    첫 결과는 <b>Bifrost</b> 문자, 두 번째는 b 요소 안의 Bifrost입니다.

  3. 한 가지 태그로 재확인하기

    sample의 b를 em으로 바꾼 뒤 저장하고 새로고침합니다. #text는 <em>Bifrost</em>를 표시하고 #markup에는 em 요소가 생깁니다. 기울기 모양은 스타일에 따라 다를 수 있으므로 DOM을 근거로 삼습니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
browser.html을 브라우저에서 엽니다.
개발자 도구 Elements에서 #text와 #markup의 자식 노드를 비교합니다.

예상 결과와 해석

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

고정 문자열의 b를 em으로 바꾸세요. 화면과 DOM의 차이를 적고 브라우저→서버→DB→응답 흐름을 별도로 그립니다.

막혔을 때 힌트 보기

file://로 연 문서는 HTTP 서버에서 내려받은 문서가 아닙니다. 이 실습의 관찰 범위를 DOM 해석으로 한정합니다.

과제 해설과 예시 답안 보기
  1. const sample = '<em>Bifrost</em>';로 변경하고 두 API는 그대로 유지합니다.
  2. Elements에서 #text 아래의 텍스트와 #markup 아래의 em 요소를 구분해서 기록합니다.
  3. 별도 도식은 브라우저 → HTTP 요청 → 서버 → DB 조회 → 서버 응답 → 브라우저 DOM으로 그립니다. 파일 실습에서 서버·DB 단계는 실제 실행하지 않았다고 표시합니다.

결과를 판단하는 기준

#text는 태그 문자를 그대로 보여 주고 #markup에는 em 자식 요소가 있습니다. HTTP·DB 흐름 도식과 이번 로컬 DOM 관찰 범위를 구분해야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
