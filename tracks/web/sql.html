01 / UNDERSTAND

먼저 이해하기

SQL SELECT는 결과에 넣을 열을 고르고 WHERE는 행의 조건을 정합니다. users에서 name이 alice인 행을 찾는 일과 모든 사용자를 찾는 일은 조건이 다릅니다. SQL Injection을 보기 전에 정상 조회부터 설명할 수 있어야 합니다.

Python sqlite3에서 ?는 값이 들어갈 자리입니다. execute의 두 번째 인자에 튜플로 값을 넘기면 드라이버가 값으로 처리합니다. 테이블 이름이나 열 이름까지 ?로 바꿀 수 있는 것은 아니므로 동적 식별자는 별도 허용 목록이 필요합니다.

CREATE TABLE은 표의 열 구조를 정하고 INSERT는 행을 넣습니다. SELECT name은 결과의 열을 정하고 WHERE name = ?는 반환할 행을 좁힙니다. fetchall()의 결과는 행들의 목록이며 각 행은 튜플입니다. [("alice",)]는 한 행·한 열, []는 결과 행이 없다는 뜻입니다.

쿼리의 ?는 입력값을 놓을 위치이며 Python 변수 이름을 SQL에 그대로 쓰는 표기가 아닙니다. execute(SQL, (값,))처럼 SQL 텍스트와 값을 별도로 전달합니다. 값이 따옴표를 포함해도 SQL 구조를 직접 이어 붙이지 않는 규칙을 유지합니다.

행의 순서는 ORDER BY를 지정하지 않으면 의도한 정렬을 보장하지 않습니다. 여러 행을 비교할 때는 ORDER BY name으로 기준을 정하거나 집합·행 수를 비교하세요. 지금의 핵심은 결과의 열 수와 조건에 따른 행 수입니다.

자주 헷갈리는 지점

[]를 DB 연결 실패라고 해석한다.
성공적으로 조회했지만 조건에 맞는 행이 없는 결과일 수 있습니다.
여러 행이 우연히 입력 순서로 나왔으니 항상 그 순서라고 생각한다.
순서가 학습 결론에 필요하면 ORDER BY를 명시합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

Python 코드 · 안내된 .py 파일에 저장해 실행 · Python 3 · 내장 sqlite3 · sql.py
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE users (name TEXT)")
db.executemany("INSERT INTO users VALUES (?)", [("alice",), ("bob",)])
print(db.execute("SELECT name FROM users WHERE name = ?", ("alice",)).fetchall())

변경 전 예상 결과와 해석

[('alice',)]

이제 단계별로 바꾸고 관찰하기

  1. 표의 상태를 그리기

    CREATE와 INSERT 두 단계를 읽고 name 열에 alice와 bob 두 행이 있다고 적습니다. :memory:는 이름이 memory인 파일을 만드는 설정이 아닙니다.

  2. 조회값 하나만 바꾸기

    테이블 생성·삽입 부분은 두고 마지막 조회값만 bob으로 바꿉니다. 다음에는 nobody로 바꿔 결과 없음과 실행 오류를 구분합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · Python 3 · 내장 sqlite3 · sql.py
    print(db.execute("SELECT name FROM users WHERE name = ?", ("bob",)).fetchall())
print(db.execute("SELECT name FROM users WHERE name = ?", ("nobody",)).fetchall())
    관찰할 결과
    [('bob',)]
[]

  3. 행 조건을 제거해 비교하기

    WHERE가 없으면 두 행이 대상입니다. 정렬까지 명시하면 재현하기 쉬운 출력이 됩니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · Python 3 · 내장 sqlite3 · sql.py
    print(db.execute("SELECT name FROM users ORDER BY name").fetchall())
    관찰할 결과
    [('alice',), ('bob',)]
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

조회값을 bob과 nobody로 바꿔 결과를 비교하고, WHERE가 없을 때 행 수를 예측하세요.

막혔을 때 힌트 보기

원소 하나인 튜플에도 쉼표가 필요합니다: ("alice",).

과제 해설과 예시 답안 보기
  1. 본문의 DB 준비 뒤 bob 조회와 nobody 조회를 각각 실행합니다. 결과는 한 행과 빈 목록입니다.
  2. WHERE를 제거한 조회에서는 name 열 하나·두 행을 얻습니다. 여러 행 순서를 설명하려면 ORDER BY를 추가합니다.
  3. ("bob",)는 한 항목 튜플입니다. ("bob")는 문자열 자체여서 매개변수 묶음과 같지 않음을 적습니다.

결과를 판단하는 기준

bob은 [('bob',)], nobody는 [], WHERE 없는 조회는 두 행입니다. 입력값이 없어서 0행인 상황은 쿼리 실패가 아닙니다.

05 / VERIFY

이 정도면 다음으로

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. SELECT name FROM users WHERE name = ?에서 SELECT와 WHERE의 역할은?

정답과 이유 읽기

정답: SELECT는 결과 열, WHERE는 포함할 행의 조건을 정한다.

열 선택과 행 필터링을 나눠 읽어야 조회 결과의 모양과 개수를 예측할 수 있습니다.

2. 사용자가 정렬 열 이름을 선택하게 할 때 ?로 열 이름을 넘기면 될까요?

정답과 이유 읽기

정답: 식별자는 값 매개변수와 달라 허용할 열 이름 목록을 별도로 정해야 한다.

바인딩은 데이터 값을 전달합니다. 열·테이블 등 SQL 식별자를 동적으로 고를 때는 서버가 정한 허용 목록에서 선택하도록 설계해야 합니다.

내 결과물 확인하기

  • 열 선택과 행 조건을 구분했다.
  • 조건에 맞는 1행과 없는 0행을 확인했다.
