WHAT YOU WILL BUILD

이 과정을 마치면

계정 없이 신뢰 조건·변경 영향·이미지 근거·로그 공백·복구 목표를 검증하고 남은 불확실성을 기록합니다.

01 · 책임과 접근 설계

모든 실습은 로컬 JSON·CSV 분석입니다. 실제 클라우드 계정·결제 수단·자원 생성이 필요하지 않습니다.

  1. IaaS·PaaS·SaaS와 공동 책임서비스 모델에 따라 달라지는 책임과 사용자가 계속 맡는 통제를 구분합니다.↗
  2. IAM 최소 권한과 명시적 거부누가 어떤 자원에 무슨 작업을 할지 좁힙니다.↗
  3. VPC·서브넷·보안 경계클라우드의 통신 경로와 공개 노출을 구성 관점에서 검토합니다.↗

02 · 데이터·비밀·감사

설정 변경과 실제 보장 사이의 차이를 검증 계획으로 메웁니다.

  1. 오브젝트 저장소와 데이터 공개데이터 분류·공개 범위·암호화·복구 정책을 함께 검토합니다.↗
  2. 장기 키·임시 신원·교체코드 밖의 비밀 관리와 키 수명을 설계합니다.↗
  3. 감사 로그와 공개 변경 추적정책 변경과 이후 자료 접근을 근거로 검토합니다.↗
  4. 중간 종합: 구성 수정과 검증 계획구성 위험을 업무 영향·권한·데이터·감사 관점에서 해결합니다.↗

03 · 배포·공급망·복구 운영

워크로드 신뢰와 변경 계획에서 시작해 이미지 출처·감사 범위·복구 목표까지 연결합니다.

  1. 워크로드 신원과 역할 신뢰 조건단기 자격 증명 발급 전의 신뢰 조건과 발급 후 권한을 나누어 검토합니다.↗
  2. 인프라 변경 계획과 영향 범위선언된 구성의 변경점을 읽고 노출·데이터 손실·되돌리기 조건을 검토합니다.↗
  3. 컨테이너 이미지와 공급망 근거이미지 식별·출처·취약점·실행 권한을 서로 다른 검토로 나눕니다.↗
  4. 중앙 감사 로그의 범위와 중복감사 기록의 중복·계정 경계·수집 공백을 구분합니다.↗
  5. 백업 무결성과 RPO·RTO 복구 연습복구 가능한 데이터 시점과 서비스 복구 시간을 별도로 검증합니다.↗

04 · 권한 조합과 워크로드 경계

권한 상한·Kubernetes 주체·메타데이터·사설 경로·긴급 접근을 서로 다른 신뢰 경계로 검토합니다.

  1. 실효 권한과 허용 범위의 교집합권한 부여와 권한 상한을 나누고 평가하지 못하는 정책은 명시적으로 유보합니다.↗
  2. Kubernetes 네임스페이스와 RBAC워크로드 주체·역할·바인딩·요청 범위를 연결해 권한을 검토합니다.↗
  3. 메타데이터 서비스와 자격 증명 경계메타데이터 접근 통제와 역할 권한을 나누어 자격 증명 노출 영향을 검토합니다.↗
  4. 프라이빗 엔드포인트와 DNS 경로이름 해석·네트워크 경로·엔드포인트 정책·신원 권한을 분리합니다.↗
  5. 긴급 접근의 만료·회수·증거사고 대응 권한의 범위와 시간 경계를 정하고 사용 후 검토까지 계획합니다.↗
