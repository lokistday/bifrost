01 / UNDERSTAND

먼저 이해하기

이미지 태그는 사람이 읽기 쉽지만 같은 태그가 가리키는 내용이 바뀔 수 있습니다. digest로 고정하면 특정 콘텐츠를 지정할 수 있어 재현과 검토에 도움이 됩니다. 그러나 해시는 해당 콘텐츠가 안전하거나 신뢰한 제작자가 만들었다는 사실까지 보장하지 않습니다.

출처 증명은 어느 소스와 빌드 과정에서 산출물이 나왔는지 추적하는 근거입니다. 파일이 있다는 사실과 서명·신뢰한 빌더·소스 연결을 검증했다는 사실은 다릅니다. 표본의 authored-example.json은 존재 표시 문자열일 뿐 실제 증명 파일이 아닙니다.

컨테이너의 실행 권한도 별개입니다. root 사용자, privileged 모드, 호스트 마운트·소켓, capability와 네트워크 권한이 영향 범위를 바꿉니다. non-root와 privileged 비활성화가 도움이 되어도 모든 격리 탈출·애플리케이션 결함을 막는다는 뜻은 아닙니다.

실습 I2는 모양이 올바른 가상 digest와 출처 표시, uid=10001, privileged=false를 가집니다. 실제 레지스트리에 접근하거나 이미지를 내려받지 않고 취약점 스캔·서명 검증도 하지 않습니다. 네 체크가 True라는 결과를 공급망 보안 인증으로 해석하지 않습니다.

자주 헷갈리는 지점

해시가 있으면 출처도 안전하다고 한다.
콘텐츠 일치와 출처 신뢰·취약점을 분리합니다.
컨테이너라 호스트 권한을 줘도 완전히 격리된다고 한다.
호스트 공유 자원·권한·런타임 경계를 따로 검토합니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 모델 실습 · Python 3.10 이상

이제 단계별로 바꾸고 관찰하기

    I1은 latest 태그이고 I2는 가상 SHA-256 digest입니다.

  2. 네 검토 축 관찰

    present는 존재 표시이며 verified가 아님을 확인합니다.

  3. 실행 권한만 변경

    같은 digest라도 root·privileged 실행이면 두 권한 체크가 달라집니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 모델 실습 · Python 3.10 이상
    python3 -c "from operations import load,review_image;i=dict(load()['images'][1]);i.update(uid=0,privileged=True);print(review_image(i))"
    관찰할 결과
    {'pinned': True, 'provenance_present': True, 'non_root': False, 'privileged_disabled': False}
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

I2가 네 체크를 통과해도 남아 있는 검증을 세 가지 쓰세요. 사본에서 uid를 0, privileged를 true로 바꾸어 콘텐츠 고정과 실행 권한이 독립적인지도 확인합니다.

막혔을 때 힌트 보기

digest는 콘텐츠 식별, provenance는 제작 경로, 실행 권한은 영향 범위와 연결됩니다.

과제 해설과 예시 답안 보기
  1. I2의 digest는 형식만 확인했으며 실제 산출물의 바이트를 받지 않았다고 적습니다.
  2. 출처 증명의 서명·빌더·소스 연결, 의존성 취약점과 패치 정책이 남아 있다고 설명합니다.
  3. uid와 privileged 변경은 pinning을 바꾸지 않으므로 실행 경계는 별도로 검토합니다.

결과를 판단하는 기준

변경 후 pinned·provenance_present는 True, non_root·privileged_disabled는 False입니다. 식별·출처·취약점·실행 경계를 각각 기록합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
