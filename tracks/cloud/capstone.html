구성 위험을 업무 영향·권한·데이터·감사 관점에서 해결합니다.

01 이해02 따라하기03 직접 변경04 검증

준비와 연결

종합 구성 검토 · Python 3.10 이상

  • config.json을 config-work.json으로 복사하고 로컬 검사·보고서 작성만 진행합니다. 실제 클라우드 계정은 필요하지 않습니다.
  • config-reviewed.json은 모델 기준을 만족하는 참고 답안입니다. 실제 배포 설정이나 안전성 인증이 아닙니다.
  • INVALID는 종료 코드 2, 형식이 유효한 PASS/REVIEW는 코드 0입니다. 종료 코드는 자동 배포 승인 점수가 아닙니다.

막히는 개념만 연결해서 복습하세요. 선행 차시 완료 여부로 강의를 잠그지 않습니다.

01 / UNDERSTAND

먼저 이해하기

review.py는 형식 오류(INVALID)와 8개 교육 위험 조건(REVIEW/PASS)을 구분합니다. PASS가 많아도 실제 IAM·라우팅·키·로그·복구를 확인한 것은 아닙니다. 필요한 업무와 거부 조건이 남는지 별도 검증 계획이 필요합니다.

원본 config.json을 보존하고 config-work.json을 만듭니다. 각 수정에 위험, 좁힌 범위, 기대 동작, 실제 환경에서의 검증 방법, 롤백을 붙입니다. 계정 없이 진행하는 이 과정의 결과물은 배포가 아니라 근거 있는 구성 검토 보고서입니다.

먼저 설정이 검사 가능한지 확인하고 그다음 모델의 위험 기준을 봅니다. 참/거짓은 문자열이 아닌 JSON 불리언, 보존 일수는 정수, 관리 대역은 유효한 CIDR이어야 합니다. 값을 지워 경고를 없애는 시도는 INVALID이며 개선이 아닙니다.

8개 항목은 저장소 공개/암호화, 신원 범위/장기 키, DB 공개/관리 출발지, 감사 활성화/보존입니다. 각 항목의 PASS는 좁은 조건 만족일 뿐 실제 최소 권한·노출·로그 전달·키 회수·복구를 검사하지 않습니다. 특히 유효한 넓은 CIDR도 /0이 아니라면 PASS일 수 있어 업무 근거가 필요합니다.

보고서에는 위험→수정→기대 정상/거부 동작→실제 검증 자료→롤백을 연결합니다. Network 종합 설계의 경계·서비스 신원과 일치하는지 확인하고 과거 audit.csv의 익명 읽기를 현재 구성 변경으로 지워 버리지 않습니다.

자주 헷갈리는 지점

config-reviewed.json을 실제 클라우드에 그대로 배포하려 한다.
가상 식별자·문서용 CIDR이 들어 있는 교육 답안입니다. 실제 서비스의 문법·범위·승인·시험이 필요합니다.
PASS가 된 뒤 INVALID 반례나 거부 테스트를 생략한다.
성공 사례와 실패 경계를 모두 검증해야 설정 누락·오해를 찾을 수 있습니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 변경 전 기준과 사본 확보

    원본 8개 REVIEW 요약을 기록하고 작업 사본을 만듭니다. Windows는 Copy-Item config.json config-work.json을 사용할 수 있습니다.

    작게 나눠 확인하기
    python3 review.py config.json
python3 review.py config-reviewed.json
    관찰할 결과
    원본: passed=0/8 review=8 invalid=0
참고 답안: passed=8/8 review=0 invalid=0

  2. 수정과 반례를 함께 시험

    작업 사본을 8개 조건에 맞게 수정합니다. 그 뒤 별도 오류 사본에 빈 action, 문자열 false, 잘못된 CIDR, 보존 불리언을 넣어 INVALID가 되는지 확인합니다.

    관찰할 결과
    정상 참고 구성과 형식 오류가 분리됩니다. 빈 값으로 8/8을 만들 수 없습니다.

  3. 운영 검증·복구 계획으로 완성

    정상 읽기/배포 유지, 익명 읽기·과도한 작업·외부 DB 거부, 임시 신원 만료, 감사 수집·복원 시험을 씁니다. 담당·추가 자료·실패 시 복구 조건도 적습니다.

    관찰할 결과
    로컬 점수에 더해 실제 환경에서 확인할 조건과 미검증 위험이 남습니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
cp config.json config-work.json
# 사본의 8개 검토 항목을 수정합니다.
python3 review.py config-work.json

예상 결과와 해석

모델의 모든 조건을 만족하면 요약은 passed=8/8 review=0 invalid=0입니다. 형식 오류는 INVALID와 종료 코드 2로 구분합니다. 보고서에는 모델 밖 미검증 사항을 남깁니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

8개 수정의 이유와 정상/거부 검증표를 만들고 Network 종합 과제의 망·신원 설계와 연결하세요.

막혔을 때 힌트 보기

검사기를 통과시키는 문자열 변경과 실제 정책 검증을 같은 성과로 쓰지 마세요.

과제 해설과 예시 답안 보기
  1. 원본을 보존하고 사본에서 유효한 구체 값으로 8개 조건을 수정합니다.
  2. config-reviewed.json과 차이를 설명하고 INVALID 반례가 실제로 거부되는지 비교합니다.
  3. 각 수정에 업무 근거·정상/거부 시험·증거·담당·롤백을 붙이고 모델 밖의 IAM/라우팅/키/로그/복구 한계를 씁니다.

결과를 판단하는 기준

모델 요약 passed=8/8 review=0 invalid=0과 근거 있는 검증 계획이 모두 있습니다. 이를 실제 운영 안전성의 인증으로 제시하지 않습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

정답과 이유 읽기

정답과 이유 읽기
