01 / UNDERSTAND

먼저 이해하기

정책에 Allow 한 줄이 있다는 사실만으로 실제 접근을 허용한다고 결론 내릴 수 없습니다. 어떤 주체·자원·조건·정책 종류가 평가에 참여하는지 확인해야 합니다. 권한 경계는 허용을 새로 부여하는 정책이 아니라 신원 정책이 부여할 수 있는 최대 범위를 제한하는 역할을 합니다.

실습은 한 가상 주체의 신원 허용 행동과 경계 허용 행동의 교집합을 계산합니다. ReadNotes는 양쪽에 있어 허용하고 WriteNotes는 신원 목록에만 있어서 경계가 제한합니다. 명시적 거부가 표시된 요청은 다른 허용보다 먼저 거부합니다.

실제 AWS에서는 자원 정책, 주체 종류와 세션 ARN, 조직 정책, 세션 정책과 조건에 따라 조합 규칙이 달라집니다. 특히 자원 정책의 직접 부여를 단순 교집합 하나로 일반화하면 오류입니다. 그래서 P4처럼 자원 정책 부여가 표시된 경우 모형은 허용·거부를 추측하지 않고 UNMODELED_RESOURCE_POLICY로 남깁니다.

이 JSON은 AWS IAM 형식과 평가기를 구현하지 않습니다. 행동 문자열의 정확 일치만 사용하고 자원·조건·와일드카드·교차 계정을 생략했습니다. 어떤 경로를 평가했는지와 무엇을 평가하지 못했는지를 결과에 함께 기록하는 연습입니다.

자주 헷갈리는 지점

Allow만 찾고 다른 정책을 읽지 않는다.
참여 정책과 주체·조건을 먼저 확인합니다.
간단한 교집합을 모든 AWS 자원 정책에도 적용한다.
자원 부여·주체·세션의 공식 예외와 범위를 따로 검토합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상

변경 전 예상 결과와 해석

P1 ALLOW_MODEL
P2 DENY_BOUNDARY
P3 DENY_EXPLICIT
P4 UNMODELED_RESOURCE_POLICY

이제 단계별로 바꾸고 관찰하기

  1. 네 가지 평가 결과 구분

    허용·상한 제한·명시적 거부·평가 미지원이 다른 출력입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 boundary_models.py effective
    관찰할 결과
    P1 ALLOW_MODEL
P2 DENY_BOUNDARY
P3 DENY_EXPLICIT
P4 UNMODELED_RESOURCE_POLICY

  2. 상한은 권한을 부여하지 않음 확인

    신원 허용이 없는 DeleteNotes를 경계에만 넣어도 권한이 생기지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 -c "from boundary_models import effective_permission;print(effective_permission({'action':'DeleteNotes'},[],['DeleteNotes']))"
    관찰할 결과
    DENY_NO_IDENTITY_ALLOW

  3. 교집합에 행동 추가

    WriteNotes가 양쪽 목록에 있으면 모형 범위에서 허용됩니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 -c "from boundary_models import load,effective_permission;d=load();print(effective_permission(d['permission_requests'][1],d['identity_allow'],d['boundary_allow']+['WriteNotes']))"
    관찰할 결과
    ALLOW_MODEL
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

boundary_allow에 WriteNotes를 추가하면 P2가 어떻게 바뀌는지 확인하세요. 같은 변경으로 P3나 P4를 해결했다고 주장할 수 없는 이유도 각각 적습니다.

막혔을 때 힌트 보기

상한을 넓히면 교집합은 바뀌지만 명시적 거부와 미구현 정책은 별도입니다.

과제 해설과 예시 답안 보기
  1. P2는 두 목록에 행동이 존재해 ALLOW_MODEL로 바뀝니다.
  2. P3는 명시적 거부가 유지되므로 DENY_EXPLICIT입니다.
  3. P4는 실제 자원 정책·주체·세션 조건 검토가 필요하므로 미지원 상태를 유지하고 공식 평가 규칙을 확인합니다.

결과를 판단하는 기준

P2만 모형상 허용으로 바뀝니다. 경계의 허용만으로 권한을 새로 주지 않으며 지원하지 않는 정책을 자동 안전·위험 판정하지 않습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
