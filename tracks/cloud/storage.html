01 / UNDERSTAND

먼저 이해하기

저장소의 공개 설정은 데이터가 누구에게 읽히는지에 영향을 주고 암호화는 지정한 경계에서 기밀성을 보호합니다. 저장 시 암호화를 켰더라도 서비스가 익명 읽기를 허용하면 공개 요청자에게 평문을 제공할 수 있습니다.

버전 관리와 백업도 목적이 다릅니다. 실수로 덮어쓴 자료 복구, 삭제 방지, 보존 기간, 복원 시험을 함께 정해야 합니다. 개인 데이터와 공개 교육 자료를 같은 정책으로 묶지 말고 분류부터 시작합니다.

읽기 권한과 저장 시 암호화는 서로 다른 질문에 답합니다. 공개 요청자에게 읽기 권한이 있으면 저장소 서비스는 암호화된 자료를 복호해 전달할 수 있습니다. 따라서 암호화를 켠 뒤에도 누가 어떤 객체를 읽을 수 있는지 검증해야 합니다.

데이터 분류부터 시작하면 정책 목적이 명확해집니다. 공개 학습 자료는 공개 배포가 목적일 수 있지만 개인 노트·계정 자료·로그는 다른 접근·보존 기준이 필요합니다. 모든 공개 설정을 무조건 오답으로 외우지 말고 이 모델이 비공개 노트라는 가정을 확인합니다.

버전 관리는 이전 객체 버전을 복원하는 기능의 한 예이고 독립 백업·삭제 방지·장애 복구를 모두 대신하지 않습니다. 복원할 시점·대상·권한·소요 시간과 실제 복원 시험을 정해야 데이터 보호 주장이 완성됩니다.

자주 헷갈리는 지점

public=false만 확인하고 다른 리소스 정책의 허용을 보지 않는다.
실제 공급자의 정책 조합·공개 차단·공유 링크·교차 계정 접근을 검토합니다.
백업 파일이 존재하니 복원은 성공한다고 가정한다.
권한·키·의존성·복원 시점과 실제 검증을 포함합니다.

변경 전 예상 결과와 해석

storage.public과 storage.encrypted가 PASS로 바뀝니다. 익명 읽기·권한·복구는 이 로컬 검사만으로 검증되지 않습니다.

이제 단계별로 바꾸고 관찰하기

  1. 데이터별 읽기 주체 정하기

    공개 교육 자료와 비공개 학습 노트를 나누고 익명·학습자·운영자의 읽기/변경 권한을 표로 만듭니다.

    관찰할 결과
    비공개 노트는 익명 읽기 거부, 공개 자료는 목적에 맞는 배포 조건이 명시됩니다.

  2. 접근·암호화 설정 분리

    사본에서 storage.public=false와 storage.encrypted=true를 JSON 불리언으로 저장하고 검사합니다. "false" 문자열은 INVALID 비교 사례입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 가상 저장소 정책 검토 · Python 3.10 이상
    python3 review.py config-work.json
    관찰할 결과
    storage.public과 storage.encrypted가 PASS입니다. 문자열로 바꾸면 자료형 오류로 INVALID입니다.

  3. 복원 검증 추가

    삭제/덮어쓰기/권한 변경을 사고 시나리오로 정하고 어느 버전·백업으로 누가 복원할지 씁니다. 복원 뒤 해시·읽기 권한도 확인하도록 설계합니다.

    관찰할 결과
    접근 통제·암호화·보존·복원이 다른 항목으로 기록됩니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

공개 자료와 비공개 학습 노트의 읽기 주체·보존·백업·복원 시험을 표로 작성하세요.

막혔을 때 힌트 보기

암호화 활성화만으로 공개 접근 문제가 사라지는 것은 아닙니다.

과제 해설과 예시 답안 보기
  1. 비공개 노트라는 모델 가정에 따라 익명 접근을 막고 저장 암호화 의도를 켭니다.
  2. 정상 권한 읽기 성공·익명 읽기 거부·무권한 변경 거부를 실제 검증 항목으로 씁니다.
  3. 보존·버전·독립 백업·복원 권한/시험을 표로 정하고 로컬 검사로 완료되지 않았음을 표시합니다.

결과를 판단하는 기준

암호화만으로 공개 접근이 해결됐다고 하지 않습니다. 자료 분류별 정책과 복원 계획이 있습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
