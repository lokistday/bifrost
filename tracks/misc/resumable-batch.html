01 / UNDERSTAND

먼저 이해하기

여러 입력을 배치로 처리할 때 파일이 있다는 이유만으로 완료라고 보면 입력 변경이나 도구 버전 변화를 놓칠 수 있습니다. 이 실습은 작업 ID와 ASCII 텍스트 목록을 받고 변환 버전+구분 바이트+원문의 해시로 캐시 키를 만듭니다. 변환은 작은 대문자화 모형이며 외부 작업을 수행하지 않습니다.

체크포인트는 schema와 transform 버전, 작업별 입력 키와 결과를 갖습니다. 동일 키와 예상 결과가 맞으면 SKIP, 새 입력이나 값 변경이면 RUN입니다. 이 저렴한 모형은 캐시 결과 변조를 확인하려고 예상 대문자도 다시 계산하므로 실제 고비용 작업의 성능 효과를 측정하는 벤치마크가 아닙니다.

J02 텍스트만 바꾸면 J01/J03은 SKIP이고 J02만 RUN이어야 합니다. 중복 작업 ID나 지원하지 않는 체크포인트 버전은 조용히 덮어쓰지 않고 오류로 거부합니다. 해시만 맞고 결과 문자열이 틀리면 이 모형은 재계산해 완료 기록을 갱신합니다.

선택한 체크포인트는 같은 폴더의 고정 .tmp에 쓴 뒤 교체합니다. 이는 통제된 폴더의 단일 작성자를 전제로 하며 동시 작업 잠금·충돌 해결·fsync 내구성·트랜잭션을 보장하지 않습니다. 원본 입력과 코드 버전·명령·환경도 함께 남기고 체크포인트를 신원/출처 인증으로 해석하지 않습니다.

자주 헷갈리는 지점

체크포인트가 있으면 입력 변경과 관계없이 완료이다.
작업 ID·입력 키·변환 버전·캐시 결과를 검증합니다.
replace 한 번으로 분산 트랜잭션이 완성된다.
단일 작성자·충돌·복구·내구성을 별도로 설계합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

새 작업 폴더에서 체크포인트를 만들어 두 번 실행한 뒤 J02 텍스트만 바꾼 사본으로 다시 실행하세요. RUN/SKIP 변화와 입력/변환 버전의 역할을 설명하세요.

막혔을 때 힌트 보기

원본 자료 폴더에 기존 체크포인트가 있다면 덮어쓰지 말고 새 파일명을 사용합니다. 실습은 단일 작성자 기준입니다.

과제 해설과 예시 답안 보기
  1. 비어 있는 체크포인트의 첫 실행은 3 RUN, 동일 입력 재실행은 3 SKIP입니다.
  2. J02 입력 해시가 달라지면 이 작업만 RUN이며 다른 작업의 키/결과는 유지됩니다.
  3. 체크포인트의 schema/transform을 확인하고 단일 작성자·교체 내구성의 한계를 기록합니다.

결과를 판단하는 기준

최초/재개/부분 변경의 실행 표와 입력 식별·버전·동시성 한계를 적습니다.
