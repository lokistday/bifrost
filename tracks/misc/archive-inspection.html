01 / UNDERSTAND

먼저 이해하기

압축 파일을 받으면 확장자를 믿고 바로 풀기보다 내부 목록과 크기·압축 방식·경로를 먼저 확인합니다. 이 실습은 zipfile로 메모리 안에 notes.txt와 ../outside.txt 두 항목을 만든 뒤 목록만 읽습니다. 디스크에는 아무 파일도 추출하지 않습니다.

../outside.txt 같은 상대 경로는 의도한 폴더의 밖을 가리킬 수 있습니다. safe_member는 역슬래시를 슬래시로 정규화하고 절대경로·..·콜론을 거부하는 최소한의 이름 검사입니다. Windows 드라이브 경로도 콜론을 포함하므로 이 모형에서는 후보에서 제외됩니다.

정상처럼 보이는 이름이 CANDIDATE가 되는 것은 안전한 추출을 보장하지 않습니다. 심볼릭 링크, Windows 장치 이름, 기존 파일 덮어쓰기, 대소문자 충돌, 실제 대상 경로 확인 등은 이 작은 함수가 다루지 않습니다. 따라서 PASS나 SAFE 대신 CANDIDATE로 표시합니다.

작은 압축 파일도 해제 뒤 큰 자원을 요구할 수 있습니다. 개별/총 해제 크기, 파일 수, 중첩 깊이, 시간 제한과 압축비를 함께 고려해야 합니다. 헤더의 file_size만 신뢰하지 말고 실제 읽기 한도도 적용해야 하지만 이 실습은 고정 소형 ZIP 목록 검사만 하며 안전한 범용 추출기를 구현하지 않습니다.

자주 헷갈리는 지점

경로 검사 한 함수가 안전한 압축 해제를 완성한다.
파일시스템 의미·링크·충돌·자원 한도를 별도로 다룹니다.
압축 파일의 용량만 보고 처리 자원을 정한다.
해제 크기·개수·깊이·시간과 실제 읽기량을 제한합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

safe_member에 /tmp/a, C:\temp\a, notes/../a, notes/a.txt를 전달해 판정을 표로 만드세요. CANDIDATE인 이름도 추출 전 필요한 추가 조건 세 가지를 쓰세요.

막혔을 때 힌트 보기

도구는 파일을 풀지 않습니다. CANDIDATE는 이름 검사 한 단계를 통과했다는 뜻입니다.

과제 해설과 예시 답안 보기
  1. 절대경로 /tmp/a, 드라이브 경로 C:\temp\a, 상위 이동 notes/../a는 False이며 notes/a.txt는 True입니다.
  2. 추가 조건으로 링크/장치 이름, 실제 대상 경로와 기존 파일 충돌, 전체/개별 자원 한도를 적습니다.
  3. CON의 True는 의도한 최소 이름 검사의 한계이며 실제 파일로 만들거나 추출하지 않습니다.
