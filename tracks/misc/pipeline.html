01 / UNDERSTAND

먼저 이해하기

변환 파이프라인은 각 단계의 입력 형식과 출력 형식을 정한 연결입니다. Base64→바이트→다시 Base64→텍스트처럼 중첩할 수 있으므로 한 번 변환하고 사람이 읽히지 않는다고 즉시 실패로 단정하지 않습니다.

그러나 출력이 나올 때까지 무한히 디코딩하는 접근도 재현성이 약합니다. 이 예제는 두 단계라는 가설을 세우고 각 중간 결과와 ASCII 해석을 기록합니다. validate=True는 허용되지 않은 Base64 문자를 오류로 처리합니다.

이 파이프라인의 첫 입력은 ASCII Base64 표현이고 첫 출력은 다시 Base64처럼 보이는 바이트 Qmlmcm9zdA==입니다. 두 번째 디코딩 뒤 Bifrost 바이트를 ASCII 문자열로 표시합니다. 디코딩과 문자 해석은 다른 연산입니다.

validate=True는 잘못된 문자·패딩을 조용히 버리지 않도록 검사합니다. 그러나 올바른 Base64라고 해서 UTF-8/ASCII 문장이나 안전한 프로그램이라는 뜻은 아닙니다. 결과 타입과 다음 단계의 허용 입력을 따로 검증합니다.

실패는 어느 단계에서 어떤 조건이 깨졌는지 분리합니다. 파일 읽기 실패, payload 누락, ASCII 변환 실패, Base64 검증 실패, 출력 문자 해석 실패는 고칠 위치가 다릅니다. 오류를 전부 “풀이 실패” 한 줄로 뭉개면 재현과 개선이 어렵습니다.

자주 헷갈리는 지점

첫 출력이 단어가 아니어서 가설을 바로 폐기한다.
타입·문자 집합·패딩을 보고 미리 정한 다음 가설을 검증합니다.
출력이 읽힐 때까지 무한 디코딩한다.
단계 수·중간값·중단 조건을 명시하고 역변환으로 결과를 확인합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 첫 중간값 예상

    UW1sbWNtOXpkQT09를 한 번 디코딩하면 Qmlmcm9zdA==가 됩니다. 사람이 읽히는 단어가 아니어도 두 번째 Base64 가설과 맞는지 확인합니다.

    작게 나눠 확인하기
    import base64
first = base64.b64decode("UW1sbWNtOXpkQT09", validate=True)
print(type(first).__name__, first.decode("ascii"))
    관찰할 결과
    bytes Qmlmcm9zdA==

  2. 두 번째 변환과 타입 확인

    첫 단계의 bytes를 그대로 디코더에 넘기고 최종 bytes만 ASCII로 해석합니다. 단계 수와 각 입력 길이를 기록합니다.

    작게 나눠 확인하기
    second = base64.b64decode(first, validate=True)
print(len(first), len(second), second.decode("ascii"))
    관찰할 결과
    12 7 Bifrost

  3. 실패를 예상하고 재현

    payload 사본에 !를 삽입하고 solve.py에 경로를 넘깁니다. 오류가 난 단계와 원인을 기록하고 원본으로 다시 정상 결과가 나는지 확인합니다.

    작게 나눠 확인하기
    python3 solve.py puzzle-invalid.txt
    관찰할 결과
    엄격한 Base64 검증 오류가 발생합니다. 오류 문구 자체는 Python 버전에 따라 다를 수 있습니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차

step=2: Bifrost

04 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. Base64 디코딩 결과가 bytes라는 사실의 의미는?

정답과 이유 읽기

정답: 문자 인코딩 해석은 별도이며 임의 바이너리일 수 있다.

Base64는 임의 바이트 표현입니다. 디코딩 성공만으로 문자 인코딩·의미·안전성이 보장되지 않습니다.

2. validate=True를 사용하는 주된 목적은?

정답과 이유 읽기

정답: 허용되지 않은 Base64 입력을 오류로 구분한다.

엄격한 형식 검증을 위한 옵션입니다. 입력을 무작정 정리해 의미가 바뀌는 일을 피하고 오류 원인을 남길 수 있습니다.
