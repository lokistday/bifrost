01 / UNDERSTAND

먼저 이해하기

문제 풀이에서 그럴듯한 답 하나를 찾는 것과 조건을 모두 만족하는 해가 하나뿐임을 확인하는 것은 다릅니다. clues.json은 alice,bob,carol을 1,2,3 위치에 중복 없이 배치하는 작은 논리 문제입니다. 후보 수는 3! = 6으로 전체 탐색이 충분히 작습니다.

itertools.permutations로 서로 다른 위치의 모든 순열을 만들고 before와 not_at 조건을 AND로 검사합니다. alice는 bob보다 앞서고 alice는 1이 아니며 carol은 3이 아닙니다. 이 세 조건을 모두 적용하면 alice=2,bob=3,carol=1만 남습니다.

조건 하나를 제거하면 여러 답이 남을 수 있고 서로 충돌하는 조건을 추가하면 답이 0개가 될 수 있습니다. 도구는 첫 답에서 멈추지 않고 모두 세므로 조건 부족과 모순을 구분할 수 있습니다. 답이 0일 때 프로그램 오류와 입력 모순도 따로 점검해야 합니다.

완전 탐색은 작은 공간에서 명확하지만 사람 수가 늘면 팩토리얼로 후보가 급격히 늘어납니다. 대규모 문제에는 더 이른 가지치기나 제약 해결 도구가 필요합니다. 이 예제는 범위가 작은 합성 논리 퍼즐이며 암호를 무제한으로 깨는 방법을 제공하지 않습니다.

자주 헷갈리는 지점

답 하나가 나오면 모든 조건이 충분하다고 결론 낸다.
해 개수를 세어 유일성과 조건 부족을 확인합니다.
순열 탐색을 사람 수에 관계없이 같은 비용으로 생각한다.
후보 수 n! 증가와 가지치기 필요성을 검토합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본에서 not_at 조건을 모두 제거해 답 수를 확인하세요. 다른 사본에는 bob이 alice보다 앞선다는 before 조건을 추가해 답 수를 비교하세요.

막혔을 때 힌트 보기

첫 답을 출력하고 종료하지 않습니다. 해가 0개·1개·여러 개인 경우를 나눠 해석하세요.

과제 해설과 예시 답안 보기
  1. 원본에서 alice는 1이 아니며 bob보다 앞서므로 2, bob은 3, carol은 1입니다.
  2. not_at을 없애면 (alice,bob,carol) 위치는 (1,2,3),(1,3,2),(2,3,1) 세 개입니다.
  3. 반대 before를 추가하면 엄격한 선후 관계가 모순이라 해가 0입니다. 조건과 코드 오류 여부를 각각 확인합니다.
