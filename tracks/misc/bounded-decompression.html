01 / UNDERSTAND

먼저 이해하기

압축 파일의 작은 크기가 해제 후 자원 사용량을 보장하지 않습니다. 이전 압축 목록 차시의 이름 검사와 별도로 입력 바이트 수·출력 바이트 수·파일 수·시간 등의 예산이 필요합니다. 이 실습은 단일 zlib 스트림과 바이트 예산만 다루며 중첩 압축의 전체 보호를 구현하지 않습니다.

bounded_decompress는 입력 상한을 먼저 확인하고 decompressobj.decompress에 출력 한도+1만 요청합니다. 한 바이트의 초과를 탐지하되 무제한 flush로 나머지를 한꺼번에 풀지 않습니다. 예제의 실제 본문은 A 32개라 한도 32는 허용, 31은 거부돼야 합니다.

출력이 예산 안에 있어도 eof가 거짓이면 잘린 스트림일 수 있습니다. unused_data가 있으면 뒤의 여분이나 연결된 다른 스트림을 이 계약은 거부합니다. unconsumed_tail은 출력 한도 때문에 처리하지 못한 입력이 남았다는 신호일 수 있으므로 초과 처리와 함께 검사합니다.

이 코드는 이미 메모리에 있는 입력에 바이트 예산을 적용합니다. 거대한 파일을 읽기 전에 제한하거나 CPU 시간·메모리 할당 전체를 강제하는 격리 장치가 아닙니다. 실제 도구에는 입력 읽기 단계의 한도·작업 시간·중첩과 동시성·출력 저장 정책도 필요하며 본 표본의 통과를 범용 안전 해제로 주장하지 않습니다.

자주 헷갈리는 지점

입력 압축 크기만 제한하면 안전하다.
출력과 시간·중첩 등 별도 자원 축을 검토합니다.
길이 검사만으로 정상 스트림 완료를 인정한다.
eof·여분·미처리 입력을 함께 검사합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리
python3 media_tools.py decompress --limit 32
python3 media_tools.py decompress --limit 31

변경 전 예상 결과와 해석

accepted=True output=32 limit=32
accepted=False reason=output budget limit=31

이제 단계별로 바꾸고 관찰하기

  1. 경계 양쪽의 출력 예산 시험

    압축 표본은 고정하고 출력 상한만 32와 31로 바꿉니다. 명령은 판정 결과를 출력하며 이 CLI의 거부 표시는 종료 상태 0입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리
    python3 media_tools.py decompress --limit 32
python3 media_tools.py decompress --limit 31
    관찰할 결과
    accepted=True output=32 limit=32
accepted=False reason=output budget limit=31

  2. 여분 스트림 거부 확인

    함수는 ValueError로 계약 위반을 표시합니다. 아래 명령은 원본 zlib 스트림 뒤에 !를 붙입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리
    python3 -c "import zlib; from media_tools import bounded_decompress; bounded_decompress(zlib.compress(b'A'*32)+b'!')"
    관찰할 결과
    ValueError: trailing/concatenated stream, 0이 아닌 종료 상태

  3. 잘린 스트림의 완료 검사

    예산은 충분해도 체크섬/끝부분이 없는 스트림을 완료로 보면 안 됩니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리
    python3 -c "import zlib; from media_tools import bounded_decompress; bounded_decompress(zlib.compress(b'A'*32)[:-1])"
    관찰할 결과
    ValueError: truncated stream, 0이 아닌 종료 상태
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

같은 압축 자료에서 한도 0/32/33을 비교하고, 압축 끝 한 바이트를 빼거나 뒤에 !를 붙인 자료를 함수에 넣으세요. 예산 초과·잘림·여분을 다르게 기록하세요.

막혔을 때 힌트 보기

정상 압축 본문은 32바이트입니다. eof/unused_data와 출력 길이는 각각 다른 조건입니다.

과제 해설과 예시 답안 보기
  1. 한도 0은 output budget으로 거부하고, 32/33은 32바이트 출력으로 허용합니다.
  2. 끝 바이트 삭제는 eof가 거짓이라 truncated stream, 뒤의 ! 추가는 unused_data로 trailing/concatenated stream입니다.
  3. 이 함수는 메모리 내 입력의 단일 스트림 예산이며 CPU/중첩/파일 읽기 전체 한도는 별도로 필요하다고 적습니다.
