01 / UNDERSTAND

먼저 이해하기

Misc를 모든 남은 주제의 잡동사니로 다루기보다, 낯선 입력을 분해하는 방법을 연습합니다. 파일 이름·확장자는 단서일 뿐 형식의 증거는 아닙니다. 텍스트인지 바이트인지, 필드가 있는지, 출력 목표가 무엇인지부터 확인합니다.

puzzle.txt에는 label, payload, noise가 있습니다. =를 경계로 보되 payload 내부의 Base64 패딩도 =일 수 있습니다. 따라서 첫 =에서만 나누어 키와 값을 보존해야 합니다.

분류는 바로 정답 변환을 고르는 일이 아니라 입력과 목표를 줄이는 과정입니다. 이 자료의 입력은 키=값 줄들이고 목표는 payload의 의미를 재현 가능한 단계로 설명하는 것입니다. label과 noise를 왜 처리 대상에서 제외하는지도 근거를 남깁니다.

payload의 문자가 Base64 알파벳처럼 보인다는 것은 가설의 출발점입니다. 문자 집합·길이·패딩·디코딩 결과를 확인해야 형식 주장을 보강할 수 있습니다. 길이가 4의 배수라는 조건만으로 Base64라고 확정할 수는 없습니다.

한 줄에 여러 =가 있을 수 있으므로 split("=",1)로 첫 경계만 나눕니다. 정상 예제 하나가 우연히 통과했다고 파서가 모든 입력을 처리한다고 생각하지 말고 빈 줄·중복 키·필드 누락을 다음 실험 항목으로 기록합니다.

자주 헷갈리는 지점

확장자가 txt이므로 모든 바이트가 정상 UTF-8이라고 가정한다.
이 자료는 UTF-8 텍스트로 제공되지만 일반 입력은 인코딩 오류를 구분해 처리합니다.
결과가 나오는 변환을 무작위로 계속 시도하고 기록하지 않는다.
한 번에 한 가설을 시험하고 중간값과 실패 이유를 남깁니다.

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 입력 분류 · 편집기와 Python 3
cat puzzle.txt
# payload의 형식과 길이를 기록하고 바로 변환하기 전 가설을 적습니다.

변경 전 예상 결과와 해석

payload는 UW1sbWNtOXpkQT09이며, 해독 전에는 Base64처럼 보이는 표현이라는 관찰까지만 할 수 있습니다.

이제 단계별로 바꾸고 관찰하기

  1. 입력·목표·제약 쓰기

    puzzle.txt의 세 필드를 읽고 입력은 텍스트, 처리할 필드는 payload, 원본 보존이 제약이라고 적습니다. 아직 Bifrost를 결과로 가정하지 않습니다.

    관찰할 결과
    관찰과 추측이 나뉜 문제 정의가 생깁니다.

  2. 첫 구분자만 분리

    패딩 =가 값에 들어가도 손실되지 않는지 작은 한 줄로 확인합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 입력 분류 · 편집기와 Python 3
    line = "payload=Qmlmcm9zdA=="
key, value = line.split("=", 1)
print(key, value)
    관찰할 결과
    payload Qmlmcm9zdA==

  3. 가설에 반증 입력 붙이기

    Base64 가설이라면 허용되지 않은 문자 !를 넣었을 때 엄격한 디코더가 실패해야 합니다. 두 번 중첩 가설은 각 중간 결과와 역변환으로 다음 차시에서 확인합니다.

    관찰할 결과
    가설·시험 입력·예상 결과·관찰 결과 네 칸을 남깁니다.

1. "payload=Qmlmcm9zdA=="를 안전하게 키와 값으로 나누는 방법은?

정답과 이유 읽기

정답: 첫 =에서 한 번만 나눈다.

=는 키·값 구분자이면서 Base64 값 내부의 패딩일 수 있습니다. 첫 구분자 뒤 값 전체를 보존해야 합니다.

2. Base64 문자와 길이 조건이 맞아 보이면 어떤 단계가 적절한가요?

정답과 이유 읽기

정답: 가설로 기록하고 엄격한 디코딩·중간 결과로 확인한다.

외형은 단서입니다. 다른 텍스트도 조건을 만족할 수 있으므로 변환과 검증 결과가 필요합니다.

내 결과물 확인하기

  • 관찰과 가설을 구분했다.
  • 필드 추출에서 값의 =를 보존했다.
