01 / UNDERSTAND

먼저 이해하기

메모리 분석은 프로세스 목록 외에 주소 영역·권한·백킹 자료 등을 연결할 수 있습니다. 이 차시는 그 개념을 흉내 낸 JSON 스냅샷만 읽습니다. 실제 RAM 덤프를 획득하거나 Windows VAD 구조·커널 객체를 파싱하지 않으며 주소 안의 기계어 내용도 없습니다.

각 영역은 시작 주소와 크기로 반열린 구간 [start,start+size)을 표시합니다. M2는 8192에서 4096바이트이므로 [8192,12288)이며 끝 주소 12288은 범위에 포함하지 않습니다. 시작/크기의 자료형과 음수·0을 검사해 잘못된 범위 연산을 피합니다.

이 모형은 private 백킹이면서 쓰기 w와 실행 x가 함께 있는 영역만 REVIEW로 표시합니다. JIT 등 정상 기능에서도 이런 영역이 발생할 수 있고, 악성 동작은 RX나 기타 영역에도 숨을 수 있습니다. 이 규칙은 조사 우선순위의 단서이지 악성 분류기나 완전 탐지기가 아닙니다.

후속 확인에는 프로세스 출처·시작 시각·모듈/스레드 관계·실제 바이트·페이지 상태·로그 등이 필요합니다. 표본의 권한을 rwx에서 rx로 바꾸면 규칙 검토 수는 0이 되지만 위협 부재가 증명되지는 않습니다. 관찰 범위와 규칙의 거짓 양성/음성 가능성을 보고합니다.

자주 헷갈리는 지점

쓰기와 실행이 모두 가능하면 항상 악성이다.
JIT 등 정상 기능과 독립 근거를 함께 검토합니다.
범위 끝 start+size를 포함한다.
반열린 구간으로 계산하고 경계 주소를 확인합니다.

  2. 규칙 조건 하나만 변경

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본의 M2 권한을 rwx에서 rx로 바꾸고 검토 수를 비교하세요. 그다음 size=0인 사본을 실행하세요. 규칙 불일치와 잘못된 자료를 구분하고 추가 증거 세 가지를 적으세요.

막혔을 때 힌트 보기

REVIEW의 반대는 안전 판정이 아닙니다. 범위의 끝 주소는 포함되지 않습니다.

과제 해설과 예시 답안 보기
  1. M2를 rwx에서 rx로 바꾸면 w 조건이 빠져 검토 수는 0이지만 안전하다고 쓰지 않습니다.
  2. size=0은 빈 자료를 정상 영역으로 해석하지 않고 입력 오류로 분류합니다.
  3. 실제 바이트/역어셈블·프로세스/모듈 출처·스레드 시작/실행 기록 등 추가 근거를 요청하고 정상 JIT 가능성도 남깁니다.

결과를 판단하는 기준

영역 범위·규칙 일치·입력 오류·악성 판정의 차이와 추가 증거 세 가지를 기록합니다.
