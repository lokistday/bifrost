01 / UNDERSTAND

먼저 이해하기

파일 내용에 case=BF-001이 있다는 것과 파일 시스템의 수정 시각은 다른 출처의 정보입니다. 다운로드나 압축 해제로 시각이 달라질 수 있습니다. 특히 생성·수정·접근 시각은 OS·파일 시스템·마운트 설정에 따라 의미가 다릅니다.

stat는 현재 파일 시스템의 정보를 보여 줍니다. 이 실습에서 추출된 시각을 원 사건 발생 시각으로 쓰면 안 됩니다. 해시·크기·파일명은 현재 관찰값으로 기록하고, 사건 시각은 출처가 명시된 로그와 비교합니다.

같은 파일을 설명하는 정보도 계층이 다릅니다. 파일 안의 owner=alice는 작성자가 넣은 텍스트이고, 파일 시스템 소유자는 OS가 관리하는 속성입니다. 한 값의 이름이 익숙하다고 다른 계층의 의미로 바꾸어 해석하지 않습니다.

수정 시각은 내용 수정의 단서가 될 수 있지만 복사 도구의 시각 보존 옵션이나 압축 해제 방식에 영향을 받습니다. 접근 시각도 마운트 설정과 캐시에 따라 읽을 때마다 갱신되지 않을 수 있습니다. 관찰 환경과 도구를 함께 기록해야 비교가 가능합니다.

크기와 내용 해시가 같고 메타데이터가 다르면 내용은 같은 사본일 수 있습니다. 반대로 파일 크기가 같아도 바이트 하나를 다른 바이트로 치환하면 내용은 달라집니다. 하나의 속성만으로 무결성·작성자·사건 시각을 한꺼번에 판단하지 않습니다.

자주 헷갈리는 지점

압축을 푼 시각을 사건 시각으로 타임라인에 넣는다.
추출 과정의 시각과 사건 로그의 시각에 출처를 붙여 분리합니다.
Windows의 ctime과 Unix의 ctime을 같은 뜻으로 외운다.
플랫폼별 속성 정의를 확인합니다. 이름만으로 생성·변경 시각을 판단하지 않습니다.

변경 전 예상 결과와 해석

이제 단계별로 바꾸고 관찰하기

  1. 바이트와 텍스트를 따로 읽기

    바이트 길이는 디스크 내용의 크기이고 문자열 길이는 디코딩된 문자 수입니다. 먼저 현재 파일의 바이트와 내부 필드를 확인합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 파일 속성 비교 · Linux/WSL 또는 Python 3
    from pathlib import Path
p = Path("evidence.txt")
print(len(p.read_bytes()))
print(p.read_text(encoding="utf-8"))
    관찰할 결과
    내용에 case=BF-001과 owner=alice가 있습니다. 표시되는 크기는 바이트 단위입니다.

  2. 현재 환경의 속성 표시

    stat 결과를 UTC 표시로 바꾸어 기록하되 이를 사건 발생 시각으로 부르지 않습니다. st_mtime은 이 파일 시스템에서 관찰된 수정 시각입니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 파일 속성 비교 · Linux/WSL 또는 Python 3
    from datetime import datetime, timezone
s = p.stat()
print("size=", s.st_size)
print("mtime=", datetime.fromtimestamp(s.st_mtime, timezone.utc).isoformat())
    관찰할 결과
    size와 mtime이 출력됩니다. mtime은 추출 환경마다 달라질 수 있습니다.

  3. 사본 비교표 작성

    보존한 원본과 작업 사본의 이름·크기·해시·mtime을 열로 나눕니다. 값이 다른 칸에는 가능한 원인과 확인 방법을 붙입니다.

    관찰할 결과
    내용 해시와 파일 속성의 관찰 범위를 구분한 비교표가 남습니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

원본과 사본의 크기·해시·메타데이터를 비교하고 값이 같거나 달라질 수 있는 이유를 적으세요.

막혔을 때 힌트 보기

owner=alice라는 내부 문자열은 OS 소유자도 실제 작성자 증명도 아닙니다.

과제 해설과 예시 답안 보기
  1. 내부 owner 문자열과 OS 소유자 속성을 다른 출처로 표시합니다.
  2. 크기는 바이트 단위로, 내용 동일성은 SHA-256으로 비교합니다.
  3. mtime은 추출·복사 환경의 관찰값으로 적고 사건 시각은 auth.csv처럼 출처가 있는 기록으로 확인합니다.

결과를 판단하는 기준

해시가 같고 수정 시각이 달라도 모순이라고 하지 않습니다. 크기가 같다는 이유만으로 파일 내용이 같다고 결론 내리지 않습니다.

1. 내용에 owner=alice가 보일 때 가장 적절한 기록은?

정답과 이유 읽기
