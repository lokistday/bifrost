01 / UNDERSTAND

먼저 이해하기

경로 이름은 파일 객체 자체와 같지 않습니다. 같은 파일시스템에서 여러 이름이 하나의 inode를 가리키는 하드링크가 있을 수 있습니다. 이 표본은 하나의 합성 파일시스템·한 시점에 한정하며 실제 NTFS/ext4나 디스크 이미지 구조를 읽지 않습니다.

R1의 notes.txt와 R2의 alias.txt는 inode42를 공유하고 links=2입니다. 따라서 관찰한 이름 두 개와 객체 한 개를 구분합니다. 서로 다른 장치의 inode 번호는 같을 수 있고 시간이 지나 재사용될 수도 있으므로 실제 분석은 장치/파일시스템·스냅샷 범위를 함께 식별해야 합니다.

Linux 계열의 ctime은 일반적으로 메타데이터 상태 변경 시각이며 생성 시각이라고 고정하지 않습니다. birth가 제공되지 않으면 UNKNOWN으로 남깁니다. mtime과 ctime의 차이는 권한·링크 등 여러 변화로 생길 수 있어 이 표만으로 특정 명령이나 조작을 단정하지 않습니다.

수집 목록에서 이름 하나가 빠졌다고 파일 내용이 삭제되거나 복구 불가능함이 증명되지 않습니다. 관찰 누락과 실제 unlink는 다른 주장입니다. 실제 마지막 하드링크 삭제도 열린 참조·파일시스템·덮어쓰기에 따라 후속 상태가 달라집니다. 이 실습은 자료 해석을 연습하며 실제 파일을 삭제하지 않습니다.

자주 헷갈리는 지점

inode 숫자만 같으면 장치와 시점에 관계없이 같은 파일이다.
파일시스템/장치와 스냅샷 범위를 포함합니다.
수집 목록에서 사라진 이름을 실제 삭제 증거로 쓴다.
관찰 누락과 변경 사실은 별도 근거로 검증합니다.

이제 단계별로 바꾸고 관찰하기

  1. 이름 수와 객체 수 분리

    한 스냅샷의 R1/R2가 같은 inode를 가리킨다는 설정을 읽고 출력을 비교합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리
    python3 artifacts_round2.py filesystem
    관찰할 결과

  2. 불완전한 수집 목록의 반례

    사본의 records 배열에서 R2 객체만 제거합니다. 남은 R1의 links=2는 수정하지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리

    관찰할 결과
    inode42 observed-names=1 declared-links=2, birth-unknown=1. 관찰 범위와 선언 값이 불일치합니다.

  3. 생성 시각 누락의 한계 확인

    별도 사본에서 R3의 birth를 null로 바꿉니다. ctime을 생성 시각으로 대체하지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리

    관찰할 결과

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본 목록에서 R2 행만 빼고 links 값은 그대로 두세요. 관찰 이름 수와 선언 링크 수가 다를 때 왜 실제 삭제를 단정할 수 없는지 쓰고, 추가 확인 자료를 제안하세요.

막혔을 때 힌트 보기

입력 목록 편집은 실제 파일시스템 명령이 아닙니다. inode 번호의 비교 범위도 적으세요.

과제 해설과 예시 답안 보기
  1. R2를 목록에서 제거하면 관찰 이름은 한 개지만 선언 links는 2이므로 부분 수집 가능성을 적습니다.
  2. 동일 스냅샷의 전체 디렉터리 목록·파일시스템 식별자·삭제/변경 기록과 수집 범위를 추가로 확인합니다.
  3. birth 부재는 UNKNOWN으로 두며 ctime을 생성 시각으로 채우거나 특정 사용자의 삭제로 단정하지 않습니다.

결과를 판단하는 기준

이름·객체·링크 선언·관찰 범위와 ctime/birth의 의미가 분리되어야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
