01 / UNDERSTAND

먼저 이해하기

09:00+09:00은 00:00+00:00과 같은 순간입니다. 화면의 문자열만 정렬하면 서로 다른 시간대를 잘못 배열할 수 있습니다. timezone-aware datetime으로 파싱하고 UTC로 변환한 뒤 비교해야 합니다.

timeline.py는 ISO 8601 오프셋을 읽어 실제 시각으로 정렬합니다. 원본 문자열은 CSV에 남겨 두고 분석 결과에 정규화한 시각을 사용합니다. 시스템 시계 오차와 로그 수집 지연은 시간대 변환만으로 해결되지 않습니다.

오프셋은 표시된 지역 시각과 UTC의 차이입니다. +09:00이면 지역 시각에서 9시간을 빼면 UTC가 됩니다. 날짜가 바뀌는 경우도 있으므로 시·분 숫자만 잘라 수동 정렬하는 방식은 피합니다.

aware datetime은 오프셋 정보를 가진 시각입니다. 서로 다른 오프셋이어도 실제 순간을 기준으로 비교할 수 있습니다. 오프셋이 없는 naive datetime에는 시간대 가정이 빠져 있으므로 출처의 설정을 확인한 다음 변환해야 합니다.

타임라인은 정렬된 관찰 목록이며 원인 설명은 추가 단계입니다. 1분 먼저 기록된 일이 뒤 사건의 원인이라고 자동 판단하지 않습니다. 시계 오차, 수집 지연, 기록 누락을 고려해 같은 시각이나 가까운 시각은 불확실성을 함께 표시합니다.

자주 헷갈리는 지점

time 열을 문자 순서로 정렬한다.
오프셋을 포함한 datetime으로 파싱하고 순간을 비교합니다.
정렬한 순서를 곧바로 공격 단계로 붙인다.
관찰 목록과 원인 가설을 분리하고 공통 세션·요청 ID 등을 확인합니다.

이제 단계별로 바꾸고 관찰하기

  1. E05의 오프셋 계산

    09:02+09:00에서 9시간을 빼면 같은 날짜 00:02 UTC입니다. 변환은 표시만 바꾸고 실제 순간은 보존합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 시간대 정규화 · Python 3
    from datetime import datetime, timezone
t = datetime.fromisoformat("2026-10-20T09:02:00+09:00")
print(t.astimezone(timezone.utc).isoformat())
    관찰할 결과
    2026-10-20T00:02:00+00:00

  2. 문자열 정렬과 순간 정렬 구분

    auth.csv에는 +09:00와 +00:00가 섞여 있습니다. time 문자열 대신 fromisoformat으로 파싱한 값을 정렬 키로 사용해야 E01이 처음에 옵니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 시간대 정규화 · Python 3

    관찰할 결과

  3. 원본과 정규화 값을 함께 보관

    보고서에는 원본 time, 정규화 UTC, 증거 ID, 이벤트를 연결합니다. 시계 동기화 상태는 이 자료에 없으므로 별도 확인 항목에 적습니다.

과제 해설과 예시 답안 보기
  1. E05 원본 2026-10-20T09:02:00+09:00과 UTC 2026-10-20T00:02:00+00:00을 모두 기록합니다.
  2. 스크립트의 첫·마지막 행과 전체 ID 순서를 비교합니다.
  3. 로그 순서는 관찰된 시간 순서이며 시계 오차와 인과관계는 추가 검토가 필요하다고 적습니다.
