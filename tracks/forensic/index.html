Forensic

남아 있는 디지털 흔적으로 어떤 일이 있었는지 설명할 수 있을까?

주로 다루는 문제
로그와 이벤트 분석, 파일 흔적 보존, 증거 상관관계와 사건 시간순서 재구성
만나는 개념
증거 보존·수집 계획, 로그·시간, 호스트 표본, SQLite 기록, 파일 시그니처, 대응 의사결정
잘 맞을 수 있는 관심
관찰한 사실을 꼼꼼히 비교하고, 증거와 추측을 구분해 설명하는 것이 좋다.
도움 되는 기초
파일 시스템, 타임스탬프, 로그 형식과 증거 보존의 기초가 도움이 된다. 네트워크 분석은 별도 Network Security 트랙에서 깊게 다룬다.
첫 실습
교육용 샘플 로그와 파일 메타데이터를 분석해 사건 타임라인을 만들고, 증거와 추론 및 한계를 구분해 기록한다.
학습 경로 보존·수집·상관 → Windows·Linux 흔적 → 파일시스템·메모리 표본 → 관측 범위와 시계 오차 검토

WHAT YOU WILL BUILD

이 과정을 마치면

증거 ID·관찰 범위·불확실성을 기록하며 합성 사건의 단서를 연결하고 근거 기반 대응·복구 검증 계획을 작성합니다.

01 · 보존과 증거 읽기

모든 자료는 합성 데이터입니다. 파일 해시는 다운로드 묶음과 SHA256SUMS.txt에서 확인할 수 있습니다.

  1. 원본·작업 사본·해시분석 전후 파일의 일치 여부를 검증하고 보관 절차를 기록합니다.↗
  2. 로그 필드와 사건 가설실패·성공·자료 접근 이벤트의 연결을 관찰합니다.↗
  3. 파일 정보와 시간의 한계파일 내부 내용과 파일 시스템 메타데이터의 의미를 나눕니다.↗

02 · 시간 정규화와 보고

서로 다른 시간대의 기록을 UTC로 맞춘 뒤 근거와 한계를 함께 정리합니다.

  1. UTC로 타임라인 맞추기오프셋을 포함한 시각을 같은 기준으로 정렬합니다.↗
  2. 근거가 추적되는 사건 보고서각 결론을 증거와 연결하고 확인되지 않은 사항을 분리합니다.↗

03 · 수집과 호스트 근거

수집 계획부터 프로세스·연결·응용 기록까지 관찰 범위를 넓힙니다.

  1. 수집 우선순위와 증거 인계 기록휘발성·업무 영향·분석 목적을 기준으로 수집 계획과 인계 기록을 작성합니다.↗
  2. 프로세스·부모·연결의 교차 확인한 시점의 프로세스와 연결 표를 결합하고 확인 불가능한 항목을 남깁니다.↗
  3. SQLite 방문 기록과 행위 해석의 한계합성 SQLite 기록을 질의하고 필터 결과와 사용자의 실제 행위를 구분합니다.↗

04 · 조각·상관·사고 대응

불완전한 근거를 연결하고 범위·조치·복구를 분리한 대응 계획을 만듭니다.

  1. 파일 시그니처와 조각 복원의 한계바이트 오프셋에서 후보 시그니처를 찾고 선언 길이와 실제 잔여 길이를 비교합니다.↗
  2. 호스트·세션을 잇는 다중 로그 상관시간을 정규화한 뒤 호스트·세션 키로 사건 흐름을 좁히고 인과 추론의 한계를 표시합니다.↗
  3. 사건 범위·격리·복구 검증 계획관찰 사실과 미확인 가설을 분리하고 대응의 승인·영향·증거·복구 조건을 작성합니다.↗

05 · 운영체제 기록의 의미

Windows XML·Linux 인증·파일 이름과 객체를 출처 범위와 함께 해석합니다.

  1. Windows 이벤트 XML의 원시 필드 읽기네임스페이스와 이름 있는 필드로 이벤트를 읽고 시각·로그온 유형·기록 범위를 구분합니다.↗
  2. Linux 인증과 sudo 요청의 증거 연결성공/실패·계정·세션을 분리하고 권한 요청과 명령 완료의 차이를 설명합니다.↗
  3. 파일 이름·링크·시간 기록의 의미한 파일시스템 스냅샷의 이름과 객체 식별자를 구분하고 시간·삭제 추론의 한계를 기록합니다.↗

06 · 메모리 단서와 관측 한계

영역 규칙과 시계/로그 범위를 명시해 주장의 강도를 조절합니다.

  1. 메모리 영역 모형과 우선 조사 단서프로세스별 영역·권한·백킹 정보를 읽고 검토 규칙과 악성 판정의 차이를 설명합니다.↗
  2. 시계 오차·관측 범위·사건 순서시간 보정의 불확실 구간과 로그 설정 범위를 근거로 주장 강도를 조절합니다.↗
