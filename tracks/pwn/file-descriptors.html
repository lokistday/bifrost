01 / UNDERSTAND

먼저 이해하기

파일 디스크립터는 프로세스가 열린 객체를 참조하는 작은 정수입니다. 정수 값을 변수에 복사한다고 새 디스크립터가 생기지는 않습니다. dup는 새 디스크립터를 만들지만 같은 열린 파일 설명을 가리키므로 파일 오프셋 같은 일부 상태를 공유합니다.

표본은 자신이 만든 임시 파일에 ABCDEF를 쓰고 offset=0으로 되돌린 뒤 dup합니다. 원본에서 AB를 읽으면 다음 위치는 2이고, 복제 디스크립터에서 다음 읽기는 CD가 됩니다. 파일 내용 자체를 독립 복사한 결과가 아닙니다.

원본 디스크립터를 닫아도 복제 디스크립터가 남아 있으면 열린 객체를 계속 사용할 수 있습니다. 이후 EF를 읽고 마지막 read가 0을 반환하면 EOF입니다. 디스크립터 변수의 정수 값과 커널 객체의 수명을 따로 그려야 합니다.

read와 write는 요청한 크기보다 적게 처리하거나 신호로 중단될 수 있습니다. 이 표본은 남은 길이를 추적하고 EINTR을 다시 시도하는 작은 도우미를 씁니다. 다른 오류와 EOF를 무조건 성공으로 바꾸지 않으며, 비차단 I/O의 EAGAIN 처리는 별도 설계입니다.

임시 파일 이름은 생성 직후 unlink해도 열린 FD를 통한 접근은 유지됩니다. 이 실습은 자기 파일만 다루며 다른 사용자 파일을 지우지 않습니다. dup와 별도 open은 오프셋 공유 방식이 다르고, 프로그램 실행으로 FD가 상속되는 정책은 별도 CLOEXEC 검토 대상입니다.

자주 헷갈리는 지점

int duplicate=fd를 dup와 같은 동작이라고 생각한다.
숫자 복사는 같은 FD의 별칭일 뿐 새 참조를 만들지 않습니다.
dup가 파일 내용과 offset까지 독립 복제한다고 생각한다.
같은 열린 파일 설명을 공유해 offset이 함께 움직입니다. 별도 open과 구분합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본의 입력 ABCDEF를 123456으로 바꿔 세 읽기를 예상하세요. 다른 사본에서 dup(fd)를 fd 정수 대입으로 바꾸면 원본 close 뒤 계속 읽을 수 없음을 실패 상태로 확인한 뒤 복구하세요.

막혔을 때 힌트 보기

정수 별칭과 실제 dup는 다릅니다. 닫힌 FD를 read하면 오류가 나지만 이 실험에는 메모리 범위 밖 접근이나 외부 파일이 필요하지 않습니다.

과제 해설과 예시 답안 보기
  1. 입력만 바꾸면 first=12, via_dup=34, after_close=56, 마지막 EOF입니다. 두 참조가 공유하는 offset을 0→2→4→6으로 기록합니다.
  2. duplicate=fd로 만든 결함 사본은 새 FD가 없습니다. close(fd) 뒤 duplicate도 같은 닫힌 번호라 읽기가 실패하고 상태 2로 끝나야 합니다.
  3. dup를 복구한 뒤 상태 0과 정상 순서를 확인합니다. 다른 open으로 얻은 독립 offset을 이 실험에서 검증했다고 주장하지 않습니다.

결과를 판단하는 기준

입력 변경의 세 쌍과 EOF가 맞아야 하며 dup 누락 결함은 정상 종료 기대를 깨뜨려야 합니다. FD 숫자는 실행마다 달라도 됩니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
