01 / UNDERSTAND

먼저 이해하기

printf 계열 함수에서 첫 번째 서식 인자는 출력할 데이터가 아니라 변환 규칙입니다. 신뢰할 수 없는 입력을 그 위치에 놓으면 %를 규칙으로 해석할 수 있습니다. printf("%s", text)처럼 서식은 코드가 정한 리터럴로 두고 입력은 별도 데이터 인자로 전달합니다.

문자열을 먼저 안전하게 만들었어도 나중에 그 문자열을 서식 인자로 다시 넘기면 새로운 해석 경계가 생깁니다. 출력 함수가 여러 번 이어지는 코드에서는 마지막 호출까지 서식과 데이터를 분리했는지 추적해야 합니다.

이 예제는 %s%n이라는 문자열도 데이터로 전달하므로 그대로 출력합니다. 메모리 내용을 읽거나 쓰는 취약한 호출은 실행하지 않습니다. 형식 구문처럼 보이는 입력이 변환 규칙으로 승격되지 않는지 관찰하는 실험입니다.

snprintf의 성공 반환값은 실제 저장한 길이가 아니라 충분한 공간이 있었다면 만들었을 바이트 수이며 끝의 NUL은 제외합니다. 반환값이 음수면 오류이고, 0 이상일 때 capacity 이상이면 출력이 잘렸습니다. 작은 버퍼에도 끝 문자가 들어갈 공간을 확보해야 합니다.

잘림이 메모리 경계 밖 쓰기를 막았다고 업무 결과가 올바른 것은 아닙니다. 식별자·경로·서명 대상이 잘리면 의미가 달라질 수 있으므로 재할당·명시적 오류 같은 정책을 정해야 합니다. 컴파일러 경고는 정적 단서를 주지만 모든 입력과 제어 흐름을 증명하지 않습니다.

자주 헷갈리는 지점

snprintf 반환값을 실제 버퍼에 저장된 문자 수라고 생각한다.
성공 반환값은 충분한 공간이 있다면 필요한 길이이며 NUL은 제외합니다. capacity와 비교해 잘림을 판단합니다.
한 번 문자열을 만들었으니 나중에 printf(message)로 출력해도 된다고 생각한다.
마지막 출력에서도 고정 서식과 데이터를 분리합니다. 중간 문자열에 입력의 %가 남을 수 있습니다.

서식처럼 보이는 데이터는 그대로 출력하고 긴 정상 문자열은 잘림으로 표시합니다.

이제 단계별로 바꾸고 관찰하기

  1. 서식처럼 생긴 값을 그대로 출력하기

    기본 데이터는 %s%n이며 고정된 [%s] 서식과 고정 literal=%s 서식에만 전달됩니다. 실제 %n 서식 실행이나 취약한 printf(text)는 없습니다.

    gcc -std=c11 -Wall -Wextra -Werror -Wformat=2 -g -O0 format_data.c -o format_data
./format_data
    관찰할 결과
    literal=%s%n
required=6 capacity=8 truncated=no
stored=[%s%n]

  2. 정상 문자열이 잘리는 경계 보기

    Bifrost는 7바이트이고 양쪽 괄호 2개를 더하면 9바이트가 필요합니다. capacity=8에는 데이터 최대 7바이트와 NUL이 들어가므로 마지막 t와 ]가 남지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GCC · C11 · 로컬 소스 실습
    ./format_data Bifrost
    관찰할 결과
    literal=Bifrost
required=9 capacity=8 truncated=yes
stored=[Bifros

  3. 정확히 맞는 길이와 한 칸 초과 비교하기

    입력 5바이트에 괄호 2개면 데이터 7바이트로 버퍼에 들어갑니다. 입력이 6바이트면 필요한 데이터 8바이트이므로 NUL까지는 담을 수 없습니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

버퍼 용량 8을 기준으로 입력 길이 4·5·6·7의 필요 길이와 잘림 여부를 예상하세요. 사본에서 capacity를 10으로 바꾼 뒤 Bifrost가 완전히 들어가는지도 확인하세요.

막혔을 때 힌트 보기

필요 길이는 괄호 2개를 포함하고 NUL은 제외합니다. 저장 용량은 NUL까지 포함하므로 needed < capacity여야 잘리지 않습니다.

과제 해설과 예시 답안 보기
  1. 입력 길이 4·5·6·7이면 needed는 6·7·8·9이고 capacity=8의 잘림은 no·no·yes·yes입니다.
  2. message[10]으로 바꾸면 Bifrost의 needed=9와 NUL 1바이트가 들어가 truncated=no, stored=[Bifrost]입니다.
  3. 서식 인자는 계속 리터럴로 두고 버퍼만 바꿉니다. 잘림을 거부해야 하는 실제 기능에서는 반환값을 오류로 처리해야 한다는 점을 적습니다.

결과를 판단하는 기준

길이 표와 capacity=10에서 required=9 truncated=no / stored=[Bifrost]를 확인합니다. 필요한 길이와 저장된 길이의 차이를 설명합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. 필요 데이터 길이가 8이고 버퍼 용량도 8입니다. snprintf 결과는?

정답과 이유 읽기

정답: NUL 공간이 별도 필요하므로 잘림이다.

snprintf의 필요 길이는 NUL을 제외하지만 용량은 NUL도 포함합니다. needed >= capacity이면 잘림입니다.

2. 입력에 %s%n이 있습니다. 이를 그대로 출력하는 구조는?

정답과 이유 읽기

정답: printf("%s", text)처럼 리터럴 서식의 데이터 인자로 전달한다.

이 차시는 서식과 데이터의 분리를 확인합니다. 임의 입력을 규칙 위치에 넣지 않고 출력 경계를 끝까지 추적해야 합니다.
