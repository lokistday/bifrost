01 / UNDERSTAND

먼저 이해하기

원소 3개의 인덱스는 0, 1, 2입니다. i <= 3은 인덱스 3도 읽으므로 배열 경계를 넘습니다. 바이트 길이와 원소 개수도 구분해야 합니다. sizeof values는 바이트 수이고 sizeof values / sizeof values[0]은 이 배열의 원소 개수입니다.

함수 인자의 int *values는 포인터이므로 sizeof로 호출자의 배열 길이를 복원할 수 없습니다. 함수에 길이를 함께 전달하고 접근 전에 범위를 검사하는 인터페이스가 필요합니다.

배열의 시작 인덱스는 0이고 원소가 n개일 때 마지막 유효 인덱스는 n-1입니다. n=3이면 3은 원소 개수이며 인덱스로 읽을 수 있는 위치가 아닙니다. 조건 i < 3은 0·1·2에서만 본문에 들어갑니다.

sizeof values / sizeof values[0]은 values가 실제 배열인 범위에서 전체 바이트 크기를 원소 하나의 바이트 크기로 나눕니다. int가 언제나 4바이트라고 가정할 필요가 없습니다. 함수 매개변수로 받은 포인터에서는 같은 계산이 호출자 배열 크기를 뜻하지 않습니다.

입력에서 받은 인덱스를 사용한다면 접근하기 전에 범위를 검사해야 합니다. 길이를 별도로 받는 인터페이스에서는 그 길이가 실제 할당 크기와 일치하는지도 호출 규약으로 지켜야 합니다. 길이 인자를 추가했다는 사실만으로 잘못된 길이가 자동 검출되지는 않습니다.

자주 헷갈리는 지점

프로그램이 충돌하지 않으면 경계 밖 읽기가 없다고 판단한다.
정의되지 않은 동작은 정상처럼 보일 수 있습니다. 인덱스 범위와 진단 근거를 확인합니다.
길이 0의 입력에서도 첫 원소를 먼저 읽고 나중에 검사한다.
원소가 있는지와 인덱스 범위를 접근 전에 확인하는 순서를 유지합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 조건을 표로 펼치기

    i=0,1,2,3일 때 i<3과 i<=3을 각각 적습니다. <=3은 마지막 경우도 본문을 실행하므로 values[3]을 읽는다는 것을 찾습니다.

    작게 나눠 확인하기
    i:       0  1  2  3
i < 3:   참 참 참 거짓
i <= 3:  참 참 참 참
    관찰할 결과
    배열 원소 3개와 유효 인덱스 0·1·2를 연결합니다.

  2. 사본의 조건만 고치기

    bounds-fixed.c에서 <= 3을 < 3으로 바꾸고 빌드합니다. 마지막 원소 30까지 나오고 네 번째 읽기가 없어야 합니다.

    작게 나눠 확인하기
    gcc -Wall -Wextra -g -O0 bounds-fixed.c -o bounds-fixed
./bounds-fixed
    관찰할 결과
    10
20
30

  3. 실제 배열 크기 계산 읽기

    본문 코드에서 sizeof values는 전체 바이트 수, sizeof values[0]은 한 원소 크기임을 표시합니다. 두 값의 비율이 원소 개수 3입니다. 포인터 인자와 배열 선언을 같은 것으로 바꾸어 읽지 않습니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
int values[3] = {10, 20, 30};
for (size_t i = 0; i < sizeof values / sizeof values[0]; ++i) {
    printf("%d\n", values[i]);
}

예상 결과와 해석

10
20
30
(코드는 main 내부에 넣고 stdio.h를 포함합니다.)
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

bounds.c를 복사하고 <= 3을 < 3으로 수정하세요. 원본은 다음 진단 실습용으로 유지합니다.

막혔을 때 힌트 보기

마지막 원소 번호와 원소 개수를 따로 적어 보세요.

과제 해설과 예시 답안 보기
  1. bounds.c를 복사하고 for의 조건만 i < 3으로 수정합니다.
  2. i=0·1·2가 각각 10·20·30을 출력하며 i=3은 본문에 들어가지 않는다고 설명합니다.
  3. 하드코딩된 3을 없애려면 실제 배열 선언이 있는 범위에서 sizeof 비율을 사용합니다. 함수로 분리한다면 길이를 별도 전달하는 계약을 정합니다.

결과를 판단하는 기준

수정 사본은 10 / 20 / 30 세 줄을 출력합니다. 원본은 진단 비교용으로 보존되어야 합니다.

04 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. int values[3]에서 읽을 수 있는 마지막 인덱스는?

정답과 이유 읽기

정답: 2

3은 개수입니다. 0부터 세면 유효 인덱스는 0, 1, 2입니다.

2. 함수 매개변수 int *values에서 sizeof values / sizeof values[0]을 계산하면 호출자 배열 길이가 복원될까요?

정답과 이유 읽기

정답: 아니다. 포인터 크기를 원소 크기로 나눈 것이어서 길이를 별도로 전달해야 한다.

실제 배열 객체의 sizeof와 포인터 변수의 sizeof는 다릅니다. 함수 인터페이스에서 길이 정보를 보존해야 합니다.
