01 / UNDERSTAND

먼저 이해하기

동적 할당 결과를 여러 포인터가 가리킬 수 있어도 같은 블록을 여러 번 해제하면 안 됩니다. 소유자는 해제 책임을 지고, 빌린 포인터는 정해진 수명 동안 읽거나 쓰기만 한다는 약속을 함수 인터페이스와 기록으로 드러내면 책임이 선명해집니다.

make_note는 문자열을 별도 힙 버퍼에 복사하고 호출자에게 소유권을 넘깁니다. show_note는 const char*를 빌려 출력하지만 해제하지 않습니다. const는 이 포인터를 통한 쓰기를 제한할 뿐 다른 별칭의 변경이나 수명 문제를 자동으로 없애지는 않습니다.

malloc 실패는 NULL로 표시할 수 있으므로 성공을 확인한 뒤에만 버퍼를 사용합니다. 이 예제는 짧고 고정된 Bifrost 표본을 복사하며 임의의 거대 입력을 다루는 범용 문자열 라이브러리가 아닙니다. 앞 차시의 크기 계산 제한도 별도 관심사입니다.

free는 할당된 블록을 반환하지만 그 주소를 담던 다른 포인터 변수들을 자동으로 지우지 않습니다. owner=NULL은 현재 변수의 실수 재사용을 줄이지만 이미 복사된 별칭까지 무효화하는 장치는 아닙니다. 빌린 포인터는 owner가 해제하기 전에만 사용해야 합니다.

Sanitizer는 실행한 경로의 수명 오류를 관찰하는 도구입니다. 진단이 없었다고 모든 경로에 누수나 해제 후 접근이 없음을 증명하지는 않습니다. 소유권 설계, 성공·실패 경로의 해제 책임, 정상 실행 검사와 함께 사용합니다.

자주 헷갈리는 지점

free가 포인터를 자동으로 NULL로 바꾼다고 생각한다.
free는 블록의 수명을 끝냅니다. 변수와 다른 별칭은 자동 변경되지 않습니다.
const char*이면 어떤 수명에서도 읽어도 된다고 생각한다.
const는 쓰기 제약이고 수명 보장은 아닙니다. 읽는 동안 객체가 유효해야 합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

owner·borrowed·힙 블록의 수명표를 그리세요. free 뒤 owner=NULL을 했어도, 미리 저장한 다른 별칭은 왜 사용할 수 없는지 설명하고 make_note 실패 경로에서 무슨 일이 일어나는지도 추적하세요.

막혔을 때 힌트 보기

포인터 변수의 수명과 포인터가 가리키는 객체의 수명은 다릅니다. 별칭 변수가 남아 있어도 힙 객체는 이미 해제되었을 수 있습니다.

과제 해설과 예시 답안 보기
  1. make_note 성공 시 힙 블록은 main 소유이고 show_note 호출 중 borrowed는 같은 블록을 잠깐 읽습니다. show_note는 해제하지 않습니다.
  2. free(owner) 뒤 블록 수명은 끝나고 owner=NULL은 owner 변수만 바꿉니다. 미리 복사한 별칭을 통해 읽는 동작은 금지됩니다. 실제 잘못된 접근을 실행할 필요는 없습니다.
  3. make_note가 NULL이면 main은 ALLOCATION_FAILED·상태 2로 끝나며 show_note와 free의 정상 경로에 들어가지 않습니다. 성공 경로의 출력과 실패 경로를 표에서 구분합니다.

05 / VERIFY

이 정도면 다음으로

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. owner를 free하고 NULL로 바꿨습니다. 미리 복사한 alias도 자동으로 NULL인가요?

정답과 이유 읽기

정답: 아니다. 다른 변수의 값은 남을 수 있지만 해제된 객체에 접근하면 안 된다.

포인터 변수의 값과 객체의 수명은 다릅니다. NULL 대입은 해당 변수 하나를 바꿉니다.

2. show_note(const char *borrowed)의 책임은 이 계약에서 무엇인가요?

정답과 이유 읽기

정답: 호출 중 유효한 버퍼를 빌려 읽고 소유권은 가져가지 않는다.

함수는 빌린 자료를 출력할 뿐 해제 책임은 main의 소유자에게 있습니다. const 자체가 이 소유권 계약을 강제하는 것은 아닙니다.
