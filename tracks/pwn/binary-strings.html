01 / UNDERSTAND

먼저 이해하기

바이너리 버퍼는 0을 포함한 바이트를 담을 수 있고 길이를 별도로 전달합니다. C 문자열은 첫 NUL 바이트를 종료로 해석합니다. 같은 배열을 두 규칙으로 읽으면 길이가 다를 수 있어, 파일·프로토콜 길이를 strlen으로 계산하면 입력 일부가 사라질 수 있습니다.

표본은 A B NUL C D의 5바이트이고 첫 NUL이 있기 때문에 strlen 호출은 2를 반환합니다. 뒤 C D가 메모리에서 지워진 것은 아닙니다. Hex를 명시적 sizeof 범위로 출력하면 다섯 바이트를 모두 볼 수 있습니다.

NUL 종료가 보장되지 않은 배열에 strlen이나 %s를 사용하면 유효 범위 밖까지 읽을 수 있습니다. 배열의 크기·실제 채운 길이·문자열 길이는 다른 값입니다. 이번 plain 배열은 종료 문자가 없으므로 strlen으로 읽지 않고 명시적 길이의 계약 함수에만 전달합니다.

ascii_text는 1~32바이트의 출력 가능한 ASCII만 허용하는 좁은 예제입니다. 중간 NUL·제어 문자·비ASCII는 거부합니다. UTF-8 텍스트 검증이나 모든 파일명·HTML·SQL의 안전 처리를 구현한 함수가 아니며 바이너리 자료에 일괄 적용해서는 안 됩니다.

같은 입력을 한 단계는 문자열로, 다음 단계는 원래 길이로 해석하면 검사한 대상과 사용한 대상이 달라질 수 있습니다. 인터페이스에서 바이트와 길이를 함께 전달하거나, 텍스트 계약을 검증한 뒤 명확히 변환하는 방식으로 해석 경계를 유지합니다.

자주 헷갈리는 지점

strlen 결과를 파일·네트워크의 실제 바이트 수로 사용한다.
C 문자열 종료와 명시적 버퍼 길이를 구분합니다. 바이너리는 길이를 별도로 전달합니다.
plain 배열도 영어 글자이므로 strlen으로 읽어도 된다고 생각한다.
문자 모양이 아니라 유효 NUL 종료가 전제입니다. 종료 없는 배열에는 명시적 길이 API를 사용합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

작업 사본의 data를 {'A','B','C','D',0}으로 바꾸고 strlen·Hex·전체 5바이트의 텍스트 계약 결과를 예상하세요. NUL을 완전히 없앤 뒤 strlen을 실행하는 실험은 하지 마세요.

막혔을 때 힌트 보기

끝에 NUL을 옮겨도 명시적 5바이트 필드에는 NUL이 포함됩니다. 문자열 길이와 텍스트 필드의 길이 계약을 따로 봅니다.

과제 해설과 예시 답안 보기
  1. data의 NUL을 끝으로 옮기면 buffer_bytes=5, string_length=4, hex=4142434400입니다. strlen은 여전히 유효 범위 안의 종료를 찾습니다.
  2. 전체 sizeof data=5를 ascii_text에 주면 NUL도 범위에 포함되므로 거부됩니다. plain의 네 바이트는 그대로 허용입니다.
  3. 문자열로 쓰려면 유효 종료 보장, 바이너리로 쓰려면 명시적 크기를 유지해야 한다고 정리합니다. NUL 없는 배열에 문자열 함수를 호출하지 않습니다.

결과를 판단하는 기준

5와 4라는 서로 다른 길이, Hex 4142434400, 전체 필드 거부를 확인합니다. NUL 위치를 바꾸는 것과 원래 버퍼 길이를 바꾸는 것은 다릅니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
