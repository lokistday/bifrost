01 / UNDERSTAND

먼저 이해하기

ASLR은 주소 배치를 바꾸고 NX는 실행 불가능한 메모리 영역의 코드 실행을 제한하며 스택 Canary는 일부 스택 손상을 함수 반환 전에 탐지합니다. 각각 다른 지점을 보호하며 입력 검증이나 수명 오류를 고쳐 주지는 않습니다.

완화 기법이 켜져 있어도 경계 밖 읽기 같은 오류는 남을 수 있습니다. 이 과정에서는 보호를 끄거나 우회하는 대신 진단한 원인, 안전한 수정, 빌드 보호, 재검증을 층으로 구분합니다. 보호 옵션은 컴파일러와 플랫폼에 따라 달라집니다.

ASLR은 주소 배치, NX는 메모리 영역의 실행 권한, Canary는 일부 스택 손상 탐지라는 서로 다른 지점에 관련됩니다. 배열 밖 읽기, 해제 후 접근 등 원인을 직접 제거하는 경계·수명 관리와는 역할이 다릅니다. 완화 하나가 다른 종류의 오류까지 자동으로 막는다고 연결하지 않습니다.

readelf -W -l은 ELF의 프로그램 헤더를 보여 줍니다. GNU_STACK의 플래그를 볼 때 R은 읽기, W는 쓰기, E는 실행입니다. 이 항목은 요청된 스택 실행 권한의 단서이며 실제 프로세스의 모든 메모리 권한·주소 랜덤화·모든 함수의 Canary 적용을 한꺼번에 증명하지 않습니다.

빌드 옵션과 실행 환경은 보호 결과에 함께 영향을 줍니다. 배포 환경의 보호를 평가하려면 컴파일·링크 옵션, 바이너리 특징, 운영체제 설정과 실제 실행을 각각 확인해야 합니다. 이 입문 실습은 관찰한 항목의 범위를 넘겨 전체 안전 판정을 하지 않는 것을 완료 기준으로 삼습니다.

자주 헷갈리는 지점

보호 기법 이름이 많으면 분석이 완성됐다고 생각한다.
각 보호 대상·관찰 근거·막지 못하는 오류를 함께 적습니다.
ELF 헤더만 보고 실제 모든 런타임 매핑을 단정한다.
정적 요청 정보와 실행 시 운영체제가 적용한 상태를 구분합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 보호 이름을 대상과 연결하기

    ASLR → 주소 배치 예측 감소, NX → 비실행 영역의 실행 제한, Canary → 일부 스택 덮어쓰기 탐지로 연결합니다. 각 칸 아래에 배열 경계 조건을 직접 고치는 것은 아님을 적습니다.

  2. GNU_STACK 한 항목 읽기

    readelf 출력의 GNU_STACK 행에서 권한 문자를 찾습니다. RW이며 E가 없으면 이 헤더가 스택 실행을 요청하지 않는다는 관찰로 기록합니다.

    작게 나눠 확인하기
    readelf -W -l memory
    관찰할 결과
    실제 GNU_STACK 플래그를 적습니다. 환경에 따라 출력과 항목 존재 여부가 다를 수 있습니다.

  3. 수정·완화·관찰을 세 칸으로 정리하기

    bounds.c의 i<=3을 i<3으로 고친 것은 원인 수정입니다. 빌드 보호는 악용 영향 완화의 층이고 Sanitizer 전후 비교는 오류를 관찰하는 방법입니다. 세 칸을 같은 성공 주장으로 합치지 않습니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
readelf -W -l memory
# GNU_STACK 항목이 있으면 권한 플래그를 관찰합니다.
# 이 출력 하나로 모든 보호 기법의 활성 여부를 판정하지 않습니다.

예상 결과와 해석

일반적인 Ubuntu 빌드에서 GNU_STACK은 RW이고 E가 없을 수 있습니다. 실제 결과를 기록하며 ASLR·Canary 여부는 이 항목으로 알 수 없습니다.

과제 해설과 예시 답안 보기
  1. 원인 수정: 유효 인덱스만 읽도록 반복 조건을 바꾸고 정상 원소 출력과 경계 조건을 검사합니다.
  2. 빌드 완화: ASLR·NX·Canary가 다루는 지점을 구분하고 이번 GNU_STACK 결과로 확인할 수 없는 항목도 적습니다.
  3. 런타임 관찰: 같은 입력·계측 옵션에서 오류 전후를 비교하고 검사한 범위의 한계를 남깁니다.

결과를 판단하는 기준

보고서는 원인 수정 / 보호 완화 / 진단 관찰을 구분하고 각 근거와 한계를 포함해야 합니다. GNU_STACK 한 줄로 ASLR·Canary까지 활성이라고 결론 내리면 미완성입니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
