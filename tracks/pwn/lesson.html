Pwn / System

프로그램과 운영체제 내부에서 무슨 일이 일어날까?

주로 다루는 문제
메모리 오류, 프로그램 실행 흐름, 권한 경계, 시스템 수준의 취약점
만나는 개념
C·포인터, 스택·힙, 디버거, 정수·크기 검증, 서식 문자열, 소유권, 완화 기법
잘 맞을 수 있는 관심
낮은 수준의 동작을 파고들고, 오류가 발생하는 정확한 조건을 추적하는 것이 좋다.
도움 되는 기초
C 문법, 주소·메모리 개념, Linux 터미널. 생소하면 C 기초부터 천천히 시작한다.
첫 실습
자신이 만든 작은 C 프로그램을 디버거로 실행하고 변수·주소·실행 흐름이 어떻게 바뀌는지 관찰한다.

WHAT YOU WILL BUILD

이 과정을 마치면

명시적 자료 계약과 시스템 호출 반환값을 바탕으로 파싱·수명·진행량·파일 객체 검증의 근거와 한계를 설명합니다.

01 · 실행과 메모리 모델

Ubuntu/WSL의 gcc와 x86-64 또는 ARM64 호스트를 사용합니다. 주소·레지스터 이름은 아키텍처에 따라 달라집니다.

  1. 소스·컴파일·실행 파일디버깅 가능한 실행 파일을 만들고 빌드 옵션을 기록합니다.↗
  2. 스택·힙과 수명지역 변수와 동적 할당 메모리의 수명을 구분합니다.↗
  3. 배열 경계와 길이배열의 유효 인덱스를 계산하고 반복 조건을 검증합니다.↗

02 · 관찰·진단·완화

주소를 외우는 대신 줄 번호·값·원인을 기록합니다. 의도된 오류는 제공한 작은 로컬 코드에서만 실행합니다.

  1. GDB 중단점과 변수실행을 멈추고 현재 코드와 변수의 값을 비교합니다.↗
  2. Sanitizer로 경계 오류 찾기잘못된 접근의 첫 발생 지점을 찾고 수정 후 재검증합니다.↗
  3. ASLR·NX·Canary의 역할과 한계메모리 오류 수정과 악용 완화의 차이를 설명합니다.↗

03 · 정수와 출력의 경계

숫자 변환·크기 계산·서식 문자열을 서로 다른 해석 경계로 분리하고 정상·거부 사례를 재현합니다.

  1. 숫자 입력·부호·범위 검증문자열을 C 정수로 바꾸는 과정의 오류와 허용 범위를 구분해 캐스팅 전에 검증합니다.↗
  2. 할당 크기와 정수 wrap 방지개수·원소 크기·헤더의 계산을 수행하기 전에 곱셈과 덧셈의 범위를 검증합니다.↗
  3. 서식 문자열·데이터·출력 잘림입력을 서식으로 실행하지 않고 고정 서식에 전달하며 snprintf의 반환값을 검증합니다.↗

04 · 소유권과 작은 파서

할당된 객체의 수명과 바이너리 길이 계약을 명시하고 실행 경로를 계측해 확인합니다.

  1. 메모리 소유권·빌림·해제누가 할당된 버퍼를 해제하는지 명시하고 해제 이후 별칭의 수명을 추적합니다.↗
  2. 바이너리 길이·엔디언·파서 경계작은 바이너리 형식의 헤더를 바이트 단위로 읽고 잘린 입력과 여분 바이트를 거부합니다.↗

05 · 메모리 표현과 데이터 계약

호스트 구조체 배치와 전송 바이트, 명시적 버퍼 길이와 NUL 문자열을 분리합니다.

  1. 구조체 배치와 명시적 직렬화호스트 구조체의 padding·오프셋과 전송 형식의 바이트 계약을 분리합니다.↗
  2. 바이너리 길이와 중간 NUL명시적 버퍼 길이와 C 문자열 종료 규칙을 구분하고 자료형 계약을 지킵니다.↗

06 · 열린 객체와 스트림 경계

FD 수명·부분 I/O·파일 열기 전제를 결정적 로컬 표본으로 검증합니다.

  1. 파일 디스크립터·dup·공유 오프셋디스크립터 숫자와 열린 파일 상태를 구분하고 중복 핸들의 오프셋·종료를 추적합니다.↗
  2. 부분 I/O·누적 읽기·메시지 경계한 번의 읽기·쓰기를 한 메시지로 가정하지 않고 길이와 진행량을 누적합니다.↗
  3. 파일 열기·TOCTOU·객체 검증이름을 두 번 확인하는 가정과 열린 객체를 검증하는 절차를 구분합니다.↗
