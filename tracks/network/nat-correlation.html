01 / UNDERSTAND

먼저 이해하기

NAPT는 여러 내부 통신을 하나의 외부 주소와 서로 다른 포트에 대응시킬 수 있습니다. 외부 로그의 공인 IP 하나만으로 내부 호스트를 고를 수 없습니다. 원래 주소·포트, 변환 주소·포트, 목적지와 기록 시점이 함께 필요합니다.

실습에서 40001은 10.20.1.7, 40002는 10.20.1.8에 연결됩니다. 두 내부 호스트의 원래 포트가 51000으로 같아도 변환 포트가 다르면 구분됩니다. 실습은 TCP만 가정하고 destination 문자열에 목적지 주소와 포트를 묶었습니다. 실제 분석에서는 프로토콜도 키에 포함합니다.

변환은 영구 정보가 아닙니다. 포트 재사용과 상태 삭제가 있으므로 사건 시각을 변환의 유효 구간과 비교합니다. 표본은 같은 길이의 UTC 형식이며 start 이상 end 미만입니다. 종료 뒤의 NAT02는 현재 자료로 연결할 수 없어 UNKNOWN입니다.

현장에서는 시계 오차, 이중 NAT, 프록시, 장비 식별자와 로그 공백을 더 검토합니다. 여러 매핑이 일치하면 하나를 임의로 고르지 않고 모호함을 보고합니다. 호스트 주소를 알아도 사람이나 계정의 행위자는 별도 증거가 필요합니다.

자주 헷갈리는 지점

공인 IP를 곧바로 사용자 ID로 쓴다.
주소·호스트·세션·신원을 별도 증거로 연결합니다.
매핑을 시간 제한 없는 정보로 본다.
생성·만료 시각과 포트 재사용을 확인합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본에서 NAT01의 public_port를 40002로 바꾸고 결과를 비교하세요. NAT02의 UNKNOWN을 사건 부재로 단정할 수 없는 이유와 실제로 더 필요한 연결 필드를 적습니다.

막혔을 때 힌트 보기

포트뿐 아니라 목적지와 시간도 일치해야 합니다. 종료 시각은 포함하지 않습니다.

과제 해설과 예시 답안 보기
  1. NAT01의 포트만 바꾼 작업 사본을 --input으로 읽습니다.
  2. NAT01이 10.20.1.8과 일치하는지 확인하고 원본 결과와 비교합니다.
  3. UNKNOWN의 대안으로 매핑 만료·시간 오차·기록 유실을 적고 추가 장비·프로토콜·신원 기록을 구분합니다.

결과를 판단하는 기준

변경한 NAT01은 matches=1 private=10.20.1.8입니다. 일치 없음과 활동 없음, 호스트 식별과 사람 식별을 각각 구분합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

1. 두 외부 접속의 공인 IP가 같으면 같은 내부 호스트인가요?

2. 매핑 종료 뒤 관측이 UNKNOWN입니다. 적절한 해석은?

정답과 이유 읽기
