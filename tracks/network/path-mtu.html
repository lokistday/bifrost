01 / UNDERSTAND

먼저 이해하기

경로상의 링크가 모두 같은 MTU를 갖는 것은 아닙니다. 작은 TCP 연결과 짧은 응답이 성공해도 큰 패킷에서 실패할 수 있습니다. 이때 단순히 서비스 포트가 열려 있다는 확인만 반복하지 않고 패킷 크기·경로·재전송과 제어 메시지를 봅니다.

IPv6의 중간 라우터는 출발지 대신 패킷을 조각내지 않습니다. 너무 큰 패킷과 Packet Too Big 메시지를 통해 출발지가 경로 MTU를 조정하는 동작을 이해해야 합니다. ICMPv6를 모두 금지하는 정책은 필요한 제어 통신까지 막을 수 있습니다.

표본은 경로 MTU1280, IPv6 기본 헤더40, TCP 기본 헤더20이라 단순 TCP payload 예산은 1220입니다. TCP 옵션·IPv6 확장 헤더·터널이 있으면 예산이 더 줄어듭니다. MTU와 애플리케이션 메시지 크기를 같은 숫자로 취급하지 않습니다.

ptb_blocked=STALLED는 PMTUD 피드백에 의존하고 다른 회복이 없다고 정한 학습 시나리오입니다. 실제 스택은 PLPMTUD·재시도·작은 세그먼트 같은 다른 동작을 할 수 있습니다. 실제 패킷을 전송하지 않고 헤더 예산과 조사 가설만 연습합니다.

자주 헷갈리는 지점

필요한 ICMPv6까지 전부 차단한다.
제어 메시지의 역할과 검증·필터 조건을 구분합니다.
MSS를 항상 MTU와 같은 값으로 둔다.
IP·TCP·옵션·터널 헤더를 포함한 예산을 계산합니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상

    1500 패킷이 1280 경로보다 큰 상황을 봅니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상

    관찰할 결과
    packet=1500 path_mtu=1280 oversized=True

  2. 계열별 기본 헤더 차이

    같은 MTU여도 IPv4와 IPv6의 기본 헤더 예산이 다릅니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 -c "from protocol_models import tcp_budget;print(tcp_budget(1500,4),tcp_budget(1500,6))"
    관찰할 결과
    1460 1440

  3. 옵션의 바이트 비용 반영

    추가 헤더를 생략하지 않고 계산합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

path_mtu를 1500으로 바꾸어 oversized와 payload 예산이 어떻게 바뀌는지 확인하세요. TCP 옵션 12바이트가 있으면 1280 경로의 예산이 얼마인지도 계산합니다.

막혔을 때 힌트 보기

MTU는 IP 패킷 기준입니다. IPv6 40 + TCP 20 + 추가 옵션을 뺍니다.

과제 해설과 예시 답안 보기
  1. 1500 MTU 사본에서 oversized=False와 기본 TCP 예산1440을 확인합니다.
  2. 1280-40-20-12=1208을 옵션 포함 예산으로 적습니다.
  3. 작은 통신 성공을 큰 전송 보장으로 확대하지 않고 PTB·터널·확장 헤더·재전송과 스택 회복 방식을 추가 확인합니다.

결과를 판단하는 기준

사본은 ptb_blocked=FITS와 예산1440입니다. STALLED는 정한 모형 조건이며 모든 실제 장비의 필연적 결과가 아닙니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
