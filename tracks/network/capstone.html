01 / UNDERSTAND

먼저 이해하기

이 종합 과제는 Web, DB, 관리 경로가 있는 가상 서비스입니다. PCAP은 정상 프로토콜 관찰용, flows.csv는 별도의 합성 정책 검토용입니다. 두 파일을 같은 실제 세션의 증거로 결합해서는 안 됩니다.

결과물은 통신 구조도, 최소 허용표, N06 판단 근거, 탐지 조건과 오탐, 신원 검사, 변경 검증과 롤백 계획입니다. 클라우드 구성과 Web 인가 원칙을 참고해 한 계층의 통제만으로 끝내지 않습니다.

먼저 보호할 자산·업무·위협을 정합니다. 사용자가 Web을 이용하고 Web이 DB를 읽는 정상 기능을 유지하면서 인터넷→DB와 과도한 관리 접근을 줄이는 것이 이 과제의 목표입니다. 통제의 개수보다 어떤 위험을 줄이는지가 중요합니다.

설계의 주장은 확인 방법과 짝을 이룹니다. “DB는 비공개”에는 외부 경로·필터·리슨·권한 검증, “변조를 막음”에는 TLS·응용 검증, “이상을 감지함”에는 기준선·경계값·오탐 검토를 붙입니다. 현재 자료로 확인하지 못하는 항목은 계획으로 남깁니다.

변경 계획에는 롤백 조건이 있어야 합니다. 정상 N01·N02가 실패하거나 관측 경로가 사라지면 어떤 설정으로 되돌리고 어떤 로그로 회복을 확인할지 적습니다. 미관측 영역과 운영 환경에서 추가로 필요한 자료를 남기는 것이 완성도의 일부입니다.

자주 헷갈리는 지점

출력 캡처만 붙이고 설계 근거를 쓰지 않는다.
위험·변경·예상 효과·검증·한계를 연결합니다.
모델 PASS/MATCH를 운영 안전성 인증으로 사용한다.
모델이 다루는 조건과 실제 환경의 추가 검증을 명확히 분리합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 주장과 근거 목록 만들기

    구조도에 정상 N01·N02, 거부 N03~N05, 검토 N06을 표시합니다. PCAP 관찰과 정책 로그 근거를 다른 표로 둡니다.

    관찰할 결과
    자료 출처가 섞이지 않은 자산·흐름·관측 표입니다.

  2. 최소 변경 후 회귀 비교

    N06 업무 필요를 판단하고 작업 사본의 policy.json을 수정하거나 DENY 유지 근거를 씁니다. evaluate.py와 detect.py의 결과를 변경 전후 비교합니다.

    관찰할 결과
    N01·N02 유지, N03~N05 거부 유지, N06 근거와 조치, REVIEW의 조사 조건이 있습니다.

  3. 다층 검증과 복구 채우기

    TLS 관측 한계, Web/DB 인가, 서비스 신원, 감사·백업, 관리 경로를 검토합니다. 각 변경마다 정상/거부/실패 복구의 성공 기준을 씁니다.

    관찰할 결과
    미검증 항목·담당·추가 자료·롤백 조건이 보고서에 포함됩니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
python3 evaluate.py
python3 detect.py
# 설계 사본의 변경 전·후 결과를 design.md에 연결합니다.

예상 결과와 해석

N01·N02 업무 흐름이 유지되고 N03~N05는 거부되며, N06은 근거 있는 처리와 재검증 계획이 있습니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

design.md를 완성하세요. 각 변경에 예상 영향, 검증 입력, 성공 기준, 실패 시 복구 절차를 하나씩 적고 미관측 영역을 명시합니다.

막혔을 때 힌트 보기

종합 과제의 완료는 도구 실행 횟수가 아니라 근거로 설계 결정을 설명할 수 있는지로 판단합니다.

과제 해설과 예시 답안 보기
  1. 정상 업무와 보호 자산을 먼저 정의하고 경계별 흐름·최소 권한을 작성합니다.
  2. 정책 모델 결과와 탐지 임계값을 재현하고 예외 N06은 좁힌 근거로 처리합니다.
  3. TLS·신원·응용 권한·운영 관측을 연결하되 모델 밖의 실제 장비 검증은 미완료라고 표시합니다.

결과를 판단하는 기준

평가 기준: 구조도/허용표의 일치, 정상·거부 회귀 근거, N06 판단, 탐지 한계·오탐, 신원·감사, 변경 영향·복구가 모두 설명됩니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

1. 종합 보고서에서 PCAP과 flows.csv를 어떻게 다뤄야 하나요?

정답과 이유 읽기

정답: 두 자료는 별도 합성 자료임을 표시하고 각자의 관찰 근거로 사용한다.

출처와 연결 키 없이 자료를 한 사건으로 합치면 잘못된 인과관계를 만들 수 있습니다. 이 과정의 두 자료는 별도 교육 표본입니다.

2. 안전한 정책 변경 계획의 완성 조건으로 적절한 것은?

정답과 이유 읽기

정답: 정상·거부·관측·복구 기준과 미검증 영역이 명시된다.

피해 범위를 줄이면서 업무를 유지하고 실패 시 복구할 수 있어야 합니다. 통제 개수나 출력 하나만으로 검증을 대신할 수 없습니다.
