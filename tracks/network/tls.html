준비와 연결

실제 TLS 1.3 비교 · Python 3와 선택 Wireshark

  • network 폴더에서 python3 analyze_tls.py를 실행하면 표준 라이브러리만으로 저장된 레코드의 관찰 요약을 봅니다. Windows는 py -3을 사용합니다. 실제 통신·캡처·서버 계정은 필요하지 않습니다.
  • Wireshark에서 traffic.pcap과 tls13.pcap을 각각 엽니다. 처음에는 TLS 키로그를 설정하지 않고 비교합니다.
  • 선택 복호 비교는 tls-notes.txt를 따라 오직 이 공개 교육용 tls13.keys를 사용합니다. 키로그를 추가한 조건과 키 없는 관측을 보고서에 분리합니다. 개인·서비스 키를 넣지 않습니다.
  • TLS 표본은 ECH 없는 bifrost.test SNI를 보여 줍니다. 이 가시성을 모든 HTTPS·QUIC·암호화 DNS 환경으로 일반화하지 않습니다.

01 / UNDERSTAND

먼저 이해하기

TLS는 통신 상대 인증과 기밀성·무결성을 제공하도록 설계됩니다. HTTPS에서 HTTP 경로·본문은 일반적인 수동 관측만으로 읽을 수 없지만 주소·포트·길이·시점 같은 메타데이터는 남습니다. DNS와 서버 이름의 노출 여부는 실제 암호화 설정에 따라 다릅니다.

traffic.pcap은 평문 HTTP 표본이고 tls13.pcap은 메모리 안에서 OpenSSL로 만든 실제 TLS 1.3 협상과 암호화 HTTP 자료입니다. 두 파일은 별도 합성 표본입니다. TLS 표본의 검증용 키로그를 제공해 키 없는 관찰과 키를 준 복호 비교를 나눠 볼 수 있습니다.

TLS 연결을 관찰할 때는 주소·포트·패킷 길이와 애플리케이션 내용의 가시성을 구분합니다. 일반 수동 관측자는 암호화된 HTTP 경로와 본문을 그대로 읽을 수 없지만 언제 어느 주소로 얼마나 통신했는지에 관한 단서는 남습니다.

TLS 1.3에서는 ServerHello 이후의 주요 협상 메시지도 암호화됩니다. 패킷 상세에 TLS가 보인다고 인증서 검증 성공이나 응용 로그인의 성공까지 확인한 것은 아닙니다. ClientHello의 제안 버전과 서버가 선택한 버전도 구분합니다.

TLS는 전송 구간의 보호입니다. TLS를 종료하는 프록시나 서버는 처리에 필요한 평문을 볼 수 있고 저장된 데이터나 응용 권한은 다른 통제가 필요합니다. 이 때문에 네트워크 관찰과 서버 접근 로그·신원 기록을 함께 설계합니다.

자주 헷갈리는 지점

TLS 1.3의 레코드 버전 값만 보고 협상 버전을 정한다.
호환용 필드와 supported_versions 등 실제 협상 근거를 구분합니다.
교육용 키로 복호한 결과를 일반 수동 관측자의 가시성이라고 한다.
키 없는 관찰과 키를 제공한 비교 실험의 조건을 명시합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 평문 표본과 TLS 표본 분리

    traffic.pcap은 8프레임이고 HTTP 스트림에서 GET /lesson이 읽힙니다. tls13.pcap은 별도 TLS 1.3 표본입니다. 파일 이름·키 제공 여부를 표 첫 열에 씁니다.

    관찰할 결과
    평문 tls 필터 0, HTTP 경로 보임 / TLS 키 없는 표본은 HTTP 경로 평문 보이지 않음입니다.

  2. 실제 레코드 요약과 협상 비교

    analyze_tls.py로 프레임·Hello·SNI·선택 버전·암호화 레코드를 확인합니다. 암호화 레코드 9개를 HTTP 요청 9건이라고 해석하지 않습니다.

    작게 나눠 확인하기
    python3 analyze_tls.py
    관찰할 결과
    frames=15, client_hello=1 server_hello=1, sni=bifrost.test, negotiated=TLS1.3, encrypted_records=9, plaintext_http_visible=False

  3. 선택 복호와 관측 조건 비교

    tls-notes.txt를 따라 교육용 tls13.keys를 Wireshark에 제공하면 암호화된 HTTP를 비교할 수 있습니다. 이는 세션 키 없는 수동 관측자가 원래 읽을 수 있다는 뜻이 아닙니다. TLS 1.3의 인증서도 협상 암호화 뒤에 있음을 확인합니다.

    관찰할 결과
    키 없음/키 제공의 가시성 차이를 적고 인증서 신뢰·사용자 인가가 별도 검증임을 남깁니다.

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
python3 analyze_tls.py
# Wireshark: traffic.pcap → http / tls 필터 비교
# Wireshark: tls13.pcap → tls.handshake.type == 1 / tls.record.content_type == 23

예상 결과와 해석

frames=15
client_hello=1 server_hello=1
sni=bifrost.test
negotiated=TLS1.3
encrypted_records=9
plaintext_http_visible=False
평문 traffic.pcap은 별도 8프레임이며 tls 필터 결과는 0입니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

두 PCAP의 HTTP 경로 가시성·협상·주소/길이를 비교하세요. TLS 분석 요약을 재현하고 키 없는 관찰 4개, 추가 로그/키가 필요한 항목 3개를 적습니다. 선택 복호 비교를 했다면 교육 키를 제공했다는 조건을 표시합니다.

막혔을 때 힌트 보기

TLS 1.3의 outer record type 23에는 암호화된 협상·알림도 들어갈 수 있어 encrypted_records를 HTTP 요청 수로 세면 안 됩니다. 키로그 없이 인증서 내용·HTTP 본문을 읽었다고 쓰지 않습니다.

과제 해설과 예시 답안 보기
  1. traffic.pcap 8개 평문 프레임과 tls13.pcap 15개 TLS 프레임을 별도 표본으로 기록합니다.
  2. 주소·포트·길이·시점 및 이 표본의 SNI는 관찰 가능, HTTP 경로·본문·서버 인증서 내용은 키 없는 TLS 1.3 표본에서 그대로 읽지 못함으로 분류합니다.
  3. analyze_tls.py 요약을 재현하고 선택 복호는 공개 교육용 키를 제공한 조건으로 표시합니다. 실제 인증서 신뢰·응용 인가는 추가 근거를 요구합니다.

결과를 판단하는 기준

평문과 TLS, 키 없는 관찰과 교육 키 복호, 외부 레코드 개수와 응용 요청 수가 명확히 구분됩니다. SNI 가시성을 모든 TLS 환경으로 일반화하지 않습니다.
