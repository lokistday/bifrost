01 / UNDERSTAND

먼저 이해하기

한 서비스가 IPv4와 IPv6를 함께 사용하면 두 주소 계열의 경로와 정책을 각각 검토해야 합니다. IPv4의 192.0.2.0/24 허용 규칙이 2001:db8:20::5까지 뜻하지는 않습니다. 문자열 접두사가 아니라 주소를 파싱하고 같은 계열의 CIDR 안에 있는지 비교합니다.

IPv6의 loopback ::1, link-local fe80::/10, unique-local fc00::/7은 서로 다른 범위를 가집니다. link-local 주소는 어떤 링크·인터페이스인지 함께 알아야 연결 대상을 해석할 수 있습니다. 인터페이스를 안다는 사실은 해당 접근을 허용한다는 뜻과도 다릅니다.

F2는 IPv6 허용 규칙이 없어서 DENY, F3는 link-local인데 인터페이스가 없어서 SCOPE_REQUIRED입니다. F4는 unique-local이지만 그 이유만으로 신뢰하지 않고 기본 거부합니다. 이 출력은 모형의 결정이며 실제 장비가 자동으로 같은 기본값을 갖는다는 뜻은 아닙니다.

scope 함수는 학습에 필요한 몇 범주만 분류합니다. unspecified·multicast·전환 주소 등 IPv6 전체 분류를 구현하지 않았고 other-ipv6를 공인·인터넷 도달 가능으로 해석하면 안 됩니다. 문서용 2001:db8::/32 표본에는 실제 접속하지 않습니다.

자주 헷갈리는 지점

unique-local이면 모두 신뢰한다.
주소 범위와 신원·정책은 별도 판단입니다.
other-ipv6를 공인 주소라고 표시한다.
이 함수는 일부 범주만 구분하며 완전한 주소 분류가 아닙니다.

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상

변경 전 예상 결과와 해석

F1 scope=ipv4 decision=ALLOW
F2 scope=other-ipv6 decision=DENY
F3 scope=link-local decision=SCOPE_REQUIRED
F4 scope=unique-local decision=DENY

이제 단계별로 바꾸고 관찰하기

  1. 두 주소 계열 결과 비교

    F1의 IPv4 허용이 F2로 전파되지 않는지 확인합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 protocol_models.py ipv6
    관찰할 결과
    F1 scope=ipv4 decision=ALLOW
F2 scope=other-ipv6 decision=DENY
F3 scope=link-local decision=SCOPE_REQUIRED
F4 scope=unique-local decision=DENY

  2. 명시적 IPv6 규칙 적용

    메모리의 규칙에 지정한 IPv6 범위와 포트만 추가합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 -c "from protocol_models import load,family_policy;d=load();print(family_policy(d['family_requests'][1],d['family_rules']+[{'network':'2001:db8:20::/64','port':443}]))"
    관찰할 결과
    ALLOW

  3. 인터페이스와 허용 분리

    링크를 지정해도 허용 규칙이 없으면 기본 거부입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 로컬 파일 실습 · Python 3.10 이상
    python3 -c "from protocol_models import load,family_policy;d=load();r=dict(d['family_requests'][2]);r['interface']='lab0';print(family_policy(r,d['family_rules']))"
    관찰할 결과
    DENY
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본에 2001:db8:20::/64의 443 허용만 추가해 F2가 바뀌는지 확인하세요. F3에 interface=lab0만 넣으면 왜 여전히 허용이 아닌지, IPv6에서 추가로 확인할 제어 메시지·경로 조건도 적습니다.

막혔을 때 힌트 보기

주소 계열, 링크 범위, 허용 정책은 별도 항목입니다. 실제 IPv6에서는 필요한 ICMPv6 처리도 검토합니다.

과제 해설과 예시 답안 보기
  1. F2에 필요한 최소 IPv6 CIDR·포트 규칙을 사본에 추가합니다.
  2. F3은 interface 추가로 범위 누락이 해결돼도 허용 규칙 부재 때문에 DENY임을 설명합니다.
  3. 실제 적용에서는 IPv6 경로·바인딩·필요한 ICMPv6와 두 계열의 거부 반례를 별도로 검증한다고 씁니다.

결과를 판단하는 기준

F2만 ALLOW로 바뀌고 다른 계열·범위는 그대로 남습니다. other-ipv6는 인터넷 주소 분류나 도달 가능성의 증명이 아닙니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
