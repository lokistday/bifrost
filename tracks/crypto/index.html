Cryptography

데이터의 비밀과 진위를 어떤 보장으로 지킬 수 있을까?

주로 다루는 문제
기밀성·무결성·인증, 암호 프로토콜과 키 관리
만나는 개념
정수·모듈러 연산, 대칭키·공개키, 해시·MAC, nonce와 키 수명
잘 맞을 수 있는 관심
규칙을 찾고 가설을 시험하거나, 작은 도구를 만들어 문제를 해결하는 것이 재미있다.
도움 되는 기초
기초 수학과 Python이 유용하지만, 처음에는 Base64와 간단한 치환 문제부터 시작할 수 있다.

WHAT YOU WILL BUILD

이 과정을 마치면

암호 도구의 보장과 한계를 구분하고 키·nonce·태그·비밀번호 저장 설계를 검토합니다.

01 · 표현·수학·고전 암호

고전 암호는 원리 관찰용입니다. 직접 만든 암호를 실제 보호 기능에 쓰지 않습니다.

  1. 바이트·Hex·Base64표현을 바꾸는 인코딩과 비밀을 지키는 암호화를 구분합니다.↗
  2. 나머지와 모듈러 역원순환하는 값의 연산과 역원이 존재하는 조건을 확인합니다.↗
  3. 치환과 작은 키 공간시저 이동의 암·복호를 구현하고 실제 보호에 부적합한 이유를 설명합니다.↗

02 · 무결성과 진위

해시와 MAC을 분리합니다. 변경 검출과 신뢰할 수 있는 발신자 확인은 같은 보장이 아닙니다.

  1. SHA-256과 파일 무결성해시의 길이와 입력 변경 효과를 확인합니다.↗
  2. HMAC과 태그 검증공유 키가 있는 변경 검출과 단순 해시를 비교합니다.↗

03 · 현대 암호 설계와 키 수명

목적과 키 역할을 구분한 뒤 검증된 cryptography 라이브러리의 AES-GCM·Ed25519 API로 정상·변조·잘못된 키를 비교합니다. 표준 라이브러리 기초 실습과 선택 패키지 실습의 준비 환경을 나누어 안내합니다.

  1. 대칭키·AEAD·인증 태그실제 AES-GCM 자료의 정상 복호와 암호문·태그·AAD·nonce·키 변경 거부를 비교합니다.↗
  2. 공개키 암호화와 서명실제 Ed25519 서명의 정상·변조·잘못된 공개키 검증을 비교하고 키 소유자 신뢰와 구분합니다.↗
  3. 난수·nonce와 재사용같은 키 아래 nonce 제약을 어겼을 때 보장이 깨질 수 있음을 설명합니다.↗
  4. 비밀번호 KDF·salt·비용비밀번호 저장을 일반 해시·암호화와 구분합니다.↗
