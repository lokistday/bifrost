WHAT YOU WILL BUILD

이 과정을 마치면

키 수명·유도 문맥·서버 신뢰·신선도·인증할 바이트를 구분하고 표준 시험값과 반례로 설계를 검토합니다.

01 · 표현·수학·고전 암호

고전 암호는 원리 관찰용입니다. 직접 만든 암호를 실제 보호 기능에 쓰지 않습니다.

  1. 바이트·Hex·Base64표현을 바꾸는 인코딩과 비밀을 지키는 암호화를 구분합니다.↗
  2. 나머지와 모듈러 역원순환하는 값의 연산과 역원이 존재하는 조건을 확인합니다.↗
  3. 치환과 작은 키 공간시저 이동의 암·복호를 구현하고 실제 보호에 부적합한 이유를 설명합니다.↗

02 · 무결성과 진위

해시와 MAC을 분리합니다. 변경 검출과 신뢰할 수 있는 발신자 확인은 같은 보장이 아닙니다.

  1. SHA-256과 파일 무결성해시의 길이와 입력 변경 효과를 확인합니다.↗
  2. HMAC과 태그 검증공유 키가 있는 변경 검출과 단순 해시를 비교합니다.↗

03 · 현대 암호 설계와 키 수명

목적과 키 역할을 구분한 뒤 검증된 cryptography 라이브러리의 AES-GCM·Ed25519 API로 정상·변조·잘못된 키를 비교합니다. 표준 라이브러리 기초 실습과 선택 패키지 실습의 준비 환경을 나누어 안내합니다.

  1. 대칭키·AEAD·인증 태그실제 AES-GCM 자료의 정상 복호와 암호문·태그·AAD·nonce·키 변경 거부를 비교합니다.↗
  2. 공개키 암호화와 서명실제 Ed25519 서명의 정상·변조·잘못된 공개키 검증을 비교하고 키 소유자 신뢰와 구분합니다.↗
  3. 난수·nonce와 재사용같은 키 아래 nonce 제약을 어겼을 때 보장이 깨질 수 있음을 설명합니다.↗
  4. 비밀번호 KDF·salt·비용비밀번호 저장을 일반 해시·암호화와 구분합니다.↗

04 · 키 수명과 프로토콜 검증

키의 생애와 문맥 분리에서 인증서·재전송·메시지 표현의 함정까지 연결합니다.

  1. 키 상태·교체·침해 대응키의 생성·사용·퇴역·침해·폐기를 구분하고 데이터 복구 영향까지 검토합니다.↗
  2. HKDF 추출·확장과 용도 분리공통 비밀에서 서로 다른 용도의 키를 유도하고 표준 시험 벡터로 확인합니다.↗
  3. 인증서 이름·기간·신뢰 경로서버 이름 확인과 인증서 경로 검증의 역할을 구분합니다.↗
  4. 메시지 경계와 인증할 바이트필드의 모호한 결합을 찾고 인증할 메시지 표현을 명확히 만듭니다.↗
  5. 유효한 태그와 재전송 방지메시지 진위 확인과 한 번만 처리할 상태 관리를 구분합니다.↗

05 · 암호 레코드와 안전한 사용

레코드 문맥·저장값 이전·키 포장·서명 인가·난수 변환을 실제 연산과 경계 사례로 검증합니다.

  1. AEAD와 레코드 문맥의 결합암호문을 테넌트·문서·버전에 연결하고 인증 실패 시 평문을 사용하지 않습니다.↗
  2. 비밀번호 검증값의 버전과 재해시저장 형식을 검증하고 성공한 후보만 새 정책으로 이전합니다.↗
  3. 봉투 암호화와 DEK 재포장데이터 키와 포장 키를 분리하고 키 교체와 데이터 재암호화의 차이를 검증합니다.↗
  4. 서명 문맥과 업무 권한서명된 행동·자원·문맥과 현재 요청의 인가를 각각 확인합니다.↗
  5. 난수의 예측 가능성과 나머지 편향보안용 난수와 시험용 입력을 구분하고 균등 선택의 바이트 경계를 계산합니다.↗
