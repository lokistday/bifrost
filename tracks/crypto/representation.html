01 / UNDERSTAND

먼저 이해하기

문자열은 인코딩을 통해 바이트로 변환됩니다. Hex는 바이트를 16진수 문자로, Base64는 64개 문자 집합으로 표현합니다. 누구나 규칙으로 되돌릴 수 있고 비밀키가 없으므로 Base64를 암호화라고 부르지 않습니다.

Bifrost의 UTF-8 바이트는 ASCII 영역이라 각 글자가 한 바이트이지만 한글은 다를 수 있습니다. .encode()와 .decode()의 경계를 명확히 하고 이미 인코딩된 문자열을 몇 번 처리했는지 기록합니다.

Hex는 한 바이트를 두 개의 16진수 문자로 표현합니다. 예를 들어 문자 B의 UTF-8 바이트는 0x42입니다. 따라서 Bifrost의 7바이트는 Hex 14문자로 표시되며 표현이 길어졌어도 정보가 암호화된 것은 아닙니다.

Base64는 바이너리를 문자 전송 경로에 넣기 위한 표현입니다. 보통 3바이트를 4문자로 나타내며 끝의 =는 패딩입니다. Base64 문자열의 길이와 원본 바이트 길이를 같은 수치로 비교하지 않습니다.

한글을 UTF-8로 인코딩할 때는 한 글자가 여러 바이트일 수 있습니다. 먼저 문자열을 bytes로 만들고 Hex·Base64를 적용한 뒤, 역변환한 바이트를 올바른 문자 인코딩으로 해석합니다. 잘못된 인코딩은 글자가 깨지거나 예외를 만들 수 있습니다.

자주 헷갈리는 지점

Base64 값 끝의 =를 불필요한 기호라고 지운다.
패딩 규칙과 해당 인코딩 형식을 지키고 검증된 디코더로 처리합니다.
Hex 문자열을 다시 Hex로 바꾸면서 원본 바이트라고 생각한다.
각 단계의 타입·길이를 적고 bytes.fromhex 또는 Base64 디코딩으로 역변환합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 바이트 길이와 Hex 길이 비교

    같은 데이터가 바이트와 Hex에서 어떻게 보이는지 계산합니다. Hex 문자열의 글자 수는 바이트 수의 두 배입니다.

    작게 나눠 확인하기
    data = b"Bifrost"
print(len(data), len(data.hex()))
print(data.hex())
    관찰할 결과
    7 14
426966726f7374

  2. 왕복으로 표현 검증

    Base64로 인코딩한 바이트를 다시 디코딩하고 원본과 비교합니다. 비밀키 없이 누구나 이 변환을 수행할 수 있습니다.

    작게 나눠 확인하기
    import base64
encoded = base64.b64encode(data)
print(encoded.decode("ascii"))
print(base64.b64decode(encoded, validate=True) == data)
    관찰할 결과
    Qmlmcm9zdA==
True

  3. 느낌표와 한글의 차이 관찰

    Bifrost!은 8바이트이고 비프로스트는 UTF-8에서 15바이트입니다. 문자 수·바이트 수·표현 문자 수를 표의 다른 열로 둡니다.

    작게 나눠 확인하기
    print(len(b"Bifrost!"))
s = "비프로스트"
print(len(s), len(s.encode("utf-8")))
    관찰할 결과
    8
5 15

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

data를 b"Bifrost!"로 바꿔 길이와 결과를 비교하세요. 한글 문자열은 "비프로스트".encode("utf-8")로 만들어 바이트 길이를 확인합니다.

막혔을 때 힌트 보기

Base64 끝의 =는 패딩일 수 있으며 무조건 지우는 규칙을 만들면 안 됩니다.

과제 해설과 예시 답안 보기
  1. data=b"Bifrost!"로 바꾸고 len(data), data.hex(), Base64 결과를 각각 기록합니다.
  2. 한글은 문자열을 먼저 UTF-8로 encode하고 바이트 길이를 측정합니다.
  3. 디코딩을 거꾸로 수행해 원본 bytes가 복원되는지 검증하고 이를 암호화라고 부르지 않습니다.

결과를 판단하는 기준

Bifrost! 8바이트, 비프로스트 5문자/UTF-8 15바이트입니다. 표현 길이가 변해도 데이터의 기밀성을 제공하지 않습니다.

1. Base64를 비밀 저장에 쓸 수 없는 가장 직접적인 이유는?

정답과 이유 읽기

정답: 비밀키 없이 정해진 규칙으로 누구나 원문 바이트를 복원할 수 있어서

Base64는 전송용 표현입니다. 데이터를 숨기려면 별도의 암호화와 키 관리가 필요합니다.

2. UTF-8 한글 문자열의 len(str)과 len(str.encode("utf-8"))는?

정답과 이유 읽기

정답: 문자 수와 바이트 수를 세므로 다를 수 있다.

문자와 바이트는 다른 단위입니다. 비프로스트는 5문자지만 UTF-8 인코딩은 15바이트입니다.
