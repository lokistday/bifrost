01 / UNDERSTAND

먼저 이해하기

비밀번호 저장값은 해시 바이트만이 아니라 알고리즘·형식 버전·비용·salt와 검증값을 포함해야 검증과 이전을 할 수 있습니다. 형식을 구분하지 못하면 같은 바이트를 다른 매개변수로 계산하거나 오래된 값을 더 이상 검증하지 못할 수 있습니다.

실습은 PBKDF2-SHA256 형식1과 비용1000의 공개 검증값을 읽습니다. 저장된 형식·알고리즘·salt 길이·비용 범위를 확인한 뒤 후보를 계산하고 compare_digest로 비교합니다. 잘못된 후보를 새 값으로 저장하면 공격자가 비밀번호를 바꾸는 결과가 될 수 있으므로 성공 전에는 재해시하지 않습니다.

검증 성공 뒤 현재 정책2000보다 오래된 비용이면 새 salt로 다시 계산할 계획을 냅니다. 새 값의 정상 검증과 재해시 불필요 상태를 확인합니다. 이미 더 높은 비용이면 낮추지 않고, 실제 알고리즘 변경은 명시적 형식·지원 정책과 안전한 라이브러리로 계획해야 합니다.

1000·2000과 최대100000은 빠른 관찰과 무제한 입력 방지용 교육 숫자이며 운영 권장 비용이 아닙니다. 실제 알고리즘·비용은 최신 지침과 하드웨어·지연·용량을 기준으로 정합니다. 이 파일은 계정·로그인·데이터베이스 저장을 만들지 않고 공개 가상 비밀번호로만 계산합니다.

자주 헷갈리는 지점

형식·비용을 외부 입력대로 무제한 실행한다.
지원 형식과 비용 상한을 검사하고 실제 용량 정책을 적용합니다.
교육 비용을 최신 운영 권장값으로 소개한다.
최신 지침·검증된 라이브러리·실측 성능으로 선택합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

비용3000의 교육 검증값을 만들어 목표2000에서 needs_rehash가 False인지 확인하세요. 지원하지 않는 알고리즘이나 bool 비용을 사본에 넣었을 때 추측 실행하지 않고 거부해야 하는 이유를 적습니다.

막혔을 때 힌트 보기

이전 조건은 검증 성공 AND 저장 비용이 목표보다 낮음입니다. 새 정책으로 비용을 내리지 않습니다.

과제 해설과 예시 답안 보기
  1. 비용3000 레코드의 검증은 True, needs_rehash는 False임을 실행합니다.
  2. 알 수 없는 알고리즘·형식과 bool·과도한 비용은 허용 목록과 형식 검증에서 거부해야 한다고 적습니다.
  3. 실제 저장 시에는 성공한 원본 검증값이 그대로인 경우만 원자적으로 갱신하고 동시 비밀번호 변경·재시도·감사를 설계합니다.

결과를 판단하는 기준

고비용 값을 목표2000으로 낮추지 않습니다. 예제의 숫자·공개 비밀번호·고정 시험 salt를 운영 설정으로 복사하지 않습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
