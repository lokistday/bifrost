01 / UNDERSTAND

먼저 이해하기

대칭키 암호는 같은 비밀을 공유해 내용을 보호합니다. 암호화만으로 변조가 항상 검출되는 것은 아니므로 인증된 암호화(AEAD)를 고려합니다. AES-GCM 같은 구성에서는 키, nonce, 암호문, 인증 태그와 선택적 추가 인증 데이터(AAD)의 역할을 구분합니다.

envelope.json은 실제 AES-GCM 교육 암호문과 태그를 Base64로 담습니다. key_id는 키 조회용 식별자이고 비밀키는 별도의 공개 교육용 teaching-key.json에 있습니다. 이 고정 키는 실습 재현용이며 실제 데이터 보호용이 아닙니다.

AEAD는 암호문 기밀성과 인증을 함께 다루고 AAD의 무결성도 확인합니다. AAD는 숨기지 않아도 되지만 암호문이 어떤 레코드에 속하는지 묶고 싶을 때 유용합니다. record-id=17이 바뀌면 원래 태그로는 검증되지 않아야 합니다.

AES-GCM의 nonce는 비밀일 필요가 없지만 같은 키에서 재사용하면 안 됩니다. 새 암호화를 할 때 안전한 nonce 관리가 필요하고, 키 식별자는 올바른 비밀키를 찾는 이름일 뿐 비밀키 자체가 아닙니다.

이 실습은 실제 라이브러리로 제공된 암호문을 검증하고 암호문·태그·AAD·nonce·키 중 하나만 바꾼 실패를 비교합니다. 인증 실패 시 복호한 내용을 사용하지 않습니다. 고정 교육 자료 검증과 새 키·nonce로 새 암호문을 만드는 왕복 실험을 구분합니다.

자주 헷갈리는 지점

인증 실패 예외를 무시하고 받은 내용을 처리한다.
인증 성공 전에 내용을 신뢰하지 않으며 실패 시 전체 처리를 거부합니다.
공개된 교육 키와 고정 nonce를 새 서비스에 복사한다.
새 키·안전한 nonce 생성·중복 방지·권한·교체를 별도로 설계하고 검증된 라이브러리를 사용합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

실습 환경을 준비하고 원본·암호문·태그·AAD·nonce·키 변경 결과를 비교하세요. 레코드 ID를 AAD에 묶는 이유, 인증 실패 처리, 공개 교육 키를 실제 서비스에서 쓰면 안 되는 이유를 기록합니다.

막혔을 때 힌트 보기

AAD는 암호화되지 않지만 인증에 포함할 수 있는 정보입니다.

과제 해설과 예시 답안 보기
  1. 키는 비밀, nonce·태그·암호문은 공개 저장 가능, AAD는 공개되지만 인증되는 값으로 분류합니다.
  2. record-id를 AAD에 묶어 다른 레코드로 바꿔 끼우는 상황을 검증 실패와 연결합니다.
  3. 누락·잘못된 태그·키·nonce·AAD는 모두 처리 거부로 기록하고 인증되지 않은 평문은 사용하지 않습니다.

결과를 판단하는 기준

원본만 ACCEPT하고 개별 변조는 REJECT입니다. 이 실험이 키 보관·권한·교체·재전송 방지까지 자동 검증한 것은 아니라고 남깁니다.

1. AAD의 레코드 ID를 바꾸고 원 태그를 그대로 사용하면?

정답과 이유 읽기

정답: 태그 검증이 실패해야 한다.

AAD는 숨기지는 않지만 인증 범위에 포함합니다. 값이 달라지면 동일 암호문·태그로 복호 검증을 통과할 수 없습니다.

2. AES-GCM에서 피해야 하는 것은?

정답과 이유 읽기

정답: 같은 키로 서로 다른 새 메시지를 암호화하면서 nonce를 재사용

nonce는 공개 가능하지만 같은 키에서 재사용하면 기밀성·인증 안전성이 손상됩니다. 제공된 고정 자료의 검증과 새 암호화는 구분해야 합니다.
