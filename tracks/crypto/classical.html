01 / UNDERSTAND

먼저 이해하기

시저 암호는 각 문자를 고정된 수만큼 이동시킵니다. 이 예제는 대문자 A~Z만 다루므로 공백·한글·기호가 있는 입력에 그대로 적용할 수 없습니다. 입력 범위를 먼저 정하는 것도 알고리즘 설명의 일부입니다.

가능한 이동량이 26개뿐이라 모두 시도할 수 있습니다. 암호문을 잘 숨긴다고 키 공간이 커지는 것도 아닙니다. 현대 암호의 안전성을 고전 치환 예제의 난도나 눈에 복잡해 보이는 정도로 판단하지 않습니다.

문자를 숫자로 바꾸면 A=0, B=1, …, Z=25입니다. 이동량 k로 암호화할 때 (x+k)%26을 계산하고 복호할 때 (y-k)%26을 계산합니다. ord와 chr는 문자 코드와 문자를 오가는 함수입니다.

여기서 키 후보는 0~25 총 26개입니다. 키를 모르는 사람이 전부 시도해도 작아서 전수 탐색이 쉽습니다. 출력이 읽히는지 확인할 수 있는 자연어·문맥은 올바른 후보를 고르는 추가 단서입니다.

키 공간의 크기와 알고리즘 구조는 별개 조건입니다. 단순 치환의 키 후보를 늘려도 통계적 구조가 남을 수 있습니다. 고전 예제는 원리와 한계를 배우기 위한 것이며 현대 암호의 안전성을 보기 복잡한 문자 배열로 판단하지 않습니다.

자주 헷갈리는 지점

공백·한글에도 ord(c)-65 공식을 그대로 적용한다.
지원 입력을 검증하거나 알파벳 외 문자를 어떻게 처리할지 명시적으로 정합니다.
알고리즘을 숨기면 작은 키 공간이 안전해진다고 생각한다.
분석자가 구조를 안다고 가정하고 키 후보·통계 구조 등 실제 한계를 평가합니다.

이제 단계별로 바꾸고 관찰하기

  1. 한 문자로 경계 이해

    Z를 3만큼 이동하면 25+3을 26으로 나눈 나머지 2가 되어 C입니다. 경계 처리 없이 문자 코드에 3만 더하면 알파벳 밖으로 나갑니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 고전 치환 관찰 · Python 3
    print(chr((ord("Z") - ord("A") + 3) % 26 + ord("A")))
    관찰할 결과
    C

  2. 이동량을 일관되게 변경

    k=5로 바꾼 뒤 복호에서도 같은 k를 뺍니다. 한쪽만 바꾸면 원문이 복원되지 않습니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 고전 치환 관찰 · Python 3
    text, k = "BIFROST", 5
enc = lambda s, step: "".join(chr((ord(c)-65+step)%26+65) for c in s)
cipher = enc(text, k)
print(cipher)
print(enc(cipher, -k))
    관찰할 결과
    GNKWTXY
BIFROST

  3. 작은 키 공간 전수 검사

    생성한 암호문에 26개 복호 이동량을 적용합니다. 정답 후보를 고른 근거와 입력 범위를 기록합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 고전 치환 관찰 · Python 3
    for candidate in range(26):
    print(candidate, enc(cipher, -candidate))
    관찰할 결과
    candidate=5일 때 BIFROST가 나옵니다.

1. 시저 암호의 이동량을 3에서 5로 바꾸면 전수 탐색이 어려워지나요?

정답과 이유 읽기

정답: 키 후보가 여전히 26개라 큰 방어가 되지 않는다.

선택한 키 값과 가능한 키 개수는 다릅니다. 이 모델은 이동량이 0~25라 전체 후보를 쉽게 검사할 수 있습니다.

2. Z에 이동량 3을 적용했을 때 C가 되는 이유는?

정답과 이유 읽기

정답: 26개 알파벳 범위를 모듈러로 순환하기 때문에

Z=25에 3을 더해 28%26=2, 즉 C가 됩니다.
