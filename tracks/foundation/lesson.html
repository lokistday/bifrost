WHAT YOU WILL BUILD

이 과정을 마치면

자료·설정·자식 프로세스·로그의 경계를 구분하고 원본 보존과 명시적 실패를 테스트하는 작은 도구를 만듭니다.

01 · 실습 환경과 파일

Windows는 WSL Ubuntu, Linux는 Ubuntu 터미널을 기준으로 합니다. Python 차시는 macOS와 Windows Python에서도 진행할 수 있습니다.

  1. 실습 환경 준비와 첫 실행명령을 입력할 환경과 도구 버전을 구분하고 Python 예제를 실행합니다.↗
  2. 경로와 작업용 사본현재 경로를 기준으로 파일을 만들고 사본을 구분합니다.↗

02 · Python을 작은 단계로

값 → 분기와 반복 → 파일 처리 순서로 진행합니다. 코드는 파일에 저장한 후 python3 파일이름.py로 실행합니다.

  1. 변수·문자열·자료형이름에 값을 담고 숫자 계산과 문자열 출력을 구분합니다.↗
  2. 조건·반복·함수반복되는 판정을 함수로 묶고 결과를 셉니다.↗
  3. CSV 읽기와 오류 좁히기파일을 행 단위 데이터로 읽고 조건에 맞는 항목을 추출합니다.↗

03 · 시스템·통신·기록

C·Linux는 설치된 Ubuntu/WSL 환경을 사용합니다. 이후 관심 분야와 병행할 수 있습니다.

  1. C 컴파일과 주소·포인터소스와 실행 파일을 구분하고 값과 주소의 관계를 확인합니다.↗
  2. Linux 권한과 파이프파일의 읽기·쓰기 권한과 명령 사이의 데이터 흐름을 확인합니다.↗
  3. IP·포트·DNS와 전송이름 조회와 서비스 연결이 서로 다른 단계임을 설명합니다.↗
  4. HTTP 요청과 응답 읽기메서드·경로·헤더·본문을 실제 형식에서 찾습니다.↗
  5. Git과 재현 가능한 README변경 내용을 커밋하고 다른 사람이 따라 할 실행 기록을 만듭니다.↗

04 · 데이터 경계와 도구 만들기

문자열·바이트에서 JSON 계약, 명시적 실패, 명령행 옵션과 경계 테스트까지 같은 작은 도구를 단계적으로 완성합니다.

  1. 문자열·바이트·UTF-8의 경계화면의 글자와 저장되는 바이트를 구분하고 인코딩 오류를 손실 없이 진단합니다.↗
  2. JSON 파싱과 데이터 계약JSON 문법이 맞는 것과 학습 데이터의 구조·자료형이 맞는 것을 별도로 검증합니다.↗
  3. 예외·오류 메시지·종료 상태입력 오류를 구분해서 보고하고 실패를 성공 결과로 숨기지 않는 프로그램을 만듭니다.↗
  4. 재사용 가능한 명령행 도구입력 파일과 옵션을 명시하고 도움말·정상 동작·잘못된 옵션을 검증합니다.↗
  5. 경계값 테스트와 실패 실험고정된 기대값으로 경계를 검사하고 고의 오류를 넣어 테스트의 검출력을 확인합니다.↗

05 · 상태와 실행 경계 다루기

복사·파일 교체·설정 출처·자식 실행·구조화 로그를 통해 작은 도구가 실패해도 근거를 보존하도록 설계합니다.

  1. 변경 가능한 자료와 방어적 복사별칭·얕은 복사·깊은 복사의 차이를 추적하고 원본 입력을 보존하는 함수를 만듭니다.↗
  2. 자원 종료와 원자적 파일 교체실패 시 기존 보고서를 유지하고 임시 파일을 정리하는 출력 절차를 설계합니다.↗
  3. 설정 우선순위와 출처 추적기본값·파일·환경·명령행의 우선순위를 명시하고 잘못된 설정을 조용히 숨기지 않습니다.↗
  4. 자식 프로세스·argv·시간 제한입력을 명령 문자열로 합치지 않고 인자 목록으로 전달하며 실패와 시간 초과를 구분합니다.↗
  5. 구조화 로그·허용 필드·민감 정보사건을 고정된 필드로 기록하고 비밀 노출과 줄바꿈 주입을 구분해서 검증합니다.↗
