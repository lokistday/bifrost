01 / UNDERSTAND

먼저 이해하기

subprocess는 다른 실행 파일을 자식 프로세스로 시작하는 도구입니다. 프로그램 경로와 인자 목록을 분리하면 공백이 있는 값도 하나의 인자로 전달할 수 있습니다. 사람이 보는 셸 명령 문자열과 실제 argv 목록은 같은 자료구조가 아닙니다.

run_worker는 현재 Python 실행 파일과 고정된 argv_worker.py 경로를 사용하고 shell=False로 실행합니다. x;echo NOT_A_COMMAND는 자식에게 전달되는 하나의 텍스트이며 두 번째 셸 명령으로 실행되지 않습니다. 사용자가 실행 파일·임의 옵션까지 선택하게 해도 안전하다는 뜻은 아닙니다.

CompletedProcess의 returncode와 stdout·stderr는 각각 다른 정보를 줍니다. 자식이 상태 3으로 실패해도 check=False에서는 호출자가 결과를 읽고 판단해야 합니다. stdout에 문장이 있다는 이유로 성공이라고 처리하지 않습니다.

timeout은 너무 오래 걸리는 자식을 끝내고 TimeoutExpired로 알릴 수 있습니다. 표본의 --sleep은 짧은 제한보다 긴 2초 지연을 요청합니다. 프로세스 생성의 지연이나 자식이 만든 전체 프로세스 트리까지 같은 방식으로 통제된다고 가정하지 않습니다.

목록 인자는 셸 해석을 줄이지만 입력 내용·명령 옵션·권한·작업 폴더·환경·출력 크기 제한은 여전히 검토해야 합니다. 특히 Windows 배치 파일처럼 별도 해석 계층이 있는 실행 대상을 임의로 받지 않습니다. 이 예제는 고정 Python 스크립트와 작은 출력만 사용합니다.

자주 헷갈리는 지점

입력에 공백을 따옴표로 붙여 명령 문자열을 만들면 모든 플랫폼에서 안전하다고 생각한다.
고정 실행 파일과 목록 인자를 우선 사용하고 플랫폼별 해석 계층과 옵션 의미도 확인합니다.
timeout이 모든 자손 프로세스와 무한 출력까지 통제한다고 생각한다.
전체 프로세스 트리·출력 크기·권한 제한은 별도 설계입니다. 표본의 작은 단일 자식 범위와 구분합니다.

입력 두 개는 문자 그대로 전달되고, 정상·상태 3 실패·시간 초과를 구분합니다.

이제 단계별로 바꾸고 관찰하기

  1. 공백과 세미콜론을 포함한 값 전달하기

    process 모드는 두 값을 자식 argv에 그대로 보냅니다. 그 뒤 고정 실패 모드와 고정 지연 모드를 실행하며 실제 셸 명령을 만들지 않습니다.

    관찰할 결과

  2. 자식의 정확한 인자 목록 확인하기

    함수에 두 문자열을 넣고 자식의 stdout만 확인합니다. 두 단어가 공백 때문에 두 인자로 갈라지지 않는지 봅니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Python 3.10 이상 · 표준 라이브러리 · Foundation ZIP
    python3 -c "from workflow import run_worker; r=run_worker(['two words','plain']); print(r.stdout.strip()); print(r.returncode)"
    관찰할 결과
    argv=["two words","plain"]
0

  3. 비정상 상태와 진단을 별도로 읽기

    --fail은 외부 오류가 아니라 표본이 의도한 상태 3입니다. stdout은 비어 있고 stderr에 fixture failure가 있어야 합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Python 3.10 이상 · 표준 라이브러리 · Foundation ZIP

    관찰할 결과

True

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

작업 사본의 호출에서 인자에 "a b", "x|y", "$(demo)"를 각각 넣고 자식이 받은 목록을 확인하세요. --fail의 상태를 0으로 바꾸면 실패 기대 검사가 결함을 잡는지도 확인한 뒤 복구하세요.

막혔을 때 힌트 보기

도구에 넣는 문자열은 Python 파일의 리스트로 작성하면 셸의 선행 해석을 피할 수 있습니다. 터미널의 따옴표와 Python의 문자열을 혼동하지 마세요.

과제 해설과 예시 답안 보기
  1. 별도 probe.py에서 run_worker(["a b","x|y","$(demo)"])를 호출합니다. 세 값은 모두 별도 인자로 그대로 출력되어야 합니다.
  2. 소스의 고정 실행 파일과 shell=False를 확인합니다. 단순히 셸 특수문자를 필터링한 결과가 아니라 해석 계층을 줄인 구조임을 적습니다.
  3. argv_worker.py 사본의 --fail 반환을 0으로 바꾸면 returncode==3 기대가 실패합니다. 복구 뒤 정상·실패·timeout을 다시 구분합니다.

결과를 판단하는 기준

자식 argv는 세 문자열을 그대로 보존해야 합니다. 상태 결함은 실패 기대 검사에서 검출되고, 원본으로 복구한 뒤 다시 통과해야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

이해한 내용을 점검하기

1. shell=False의 고정 Python 스크립트에 "x;echo TEST"를 목록의 한 값으로 넘겼습니다. 의미는?

정답과 이유 읽기

정답: 세미콜론을 포함한 하나의 argv 데이터다.

이 구조에서는 셸을 호출하지 않습니다. 다만 선택한 프로그램 자체의 옵션이나 별도 해석 동작도 검토해야 합니다.
