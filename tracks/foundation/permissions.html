01 / UNDERSTAND

먼저 이해하기

ls -l의 권한은 소유자·그룹·그 외 사용자의 읽기(r), 쓰기(w), 실행(x)을 나타냅니다. 파일과 디렉터리의 x 의미는 다릅니다. 파일은 실행, 디렉터리는 내부 경로를 통과할 수 있는 권한입니다.

파이프 |는 앞 명령의 표준 출력을 다음 명령의 표준 입력에 연결합니다. >는 파일을 새로 쓰고 >>는 덧붙입니다. 소유한 실습 파일에서만 권한을 바꾸고, 권한 오류를 무조건 sudo로 덮기 전에 대상과 소유자를 확인하세요.

권한 숫자는 r=4, w=2, x=1을 더한 세 자리입니다. 600은 소유자 6(rw-), 그룹 0(---), 나머지 0(---)을 뜻합니다. 400은 소유자의 읽기만 남깁니다. 파일 이름이나 내용이 권한 숫자에 의해 바뀌지는 않습니다.

파이프는 파일을 옮기는 동작이 아니라 프로세스 사이로 출력을 연결하는 동작입니다. cat working.txt | grep Bifrost는 원본을 그대로 두고 일치하는 줄을 출력합니다. 필터 결과를 저장할 때 새 파일 이름을 쓰면 전체 입력과 추출 결과를 비교할 수 있습니다.

자주 헷갈리는 지점

일반 파일의 x와 폴더의 x를 같은 실행 의미로 생각한다.
디렉터리 x는 경로 탐색 권한입니다. 파일 내용을 읽는 r과 함께 역할을 구분합니다.
권한 실험을 root로 하고 쓰기가 성공했다고 400이 무의미하다고 결론 낸다.
실행한 사용자·파일시스템·추가 접근 정책을 확인하고 일반 사용자 기준 관찰과 구분합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL Bash · 일반 사용자
cp notes.txt working.txt
chmod 600 working.txt
ls -l working.txt
cat working.txt | grep Bifrost
printf "new line\n" >> working.txt

변경 전 예상 결과와 해석

권한 부분에 -rw-------가 보이고, grep 결과는 Bifrost 한 줄입니다. 소유자·날짜는 환경마다 다릅니다.

이제 단계별로 바꾸고 관찰하기

  1. 사본의 권한 세 묶음 읽기

    원본을 복사하고 소유자만 읽고 쓰게 설정합니다. ls -l에서 첫 문자는 파일 종류이므로 그 뒤 아홉 글자를 세 묶음으로 나눕니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL Bash · 일반 사용자
    cp notes.txt working.txt
chmod 600 working.txt
ls -l working.txt
    관찰할 결과
    일반 파일의 권한 표시는 -rw-------입니다.

  2. 필터 결과를 별도 파일로 저장하기

    grep은 Bifrost가 포함된 줄을 선택합니다. 새 출력 파일을 사용하면 원본 전체와 결과를 모두 남길 수 있습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL Bash · 일반 사용자
    cat working.txt | grep Bifrost > filtered.txt
cat filtered.txt
wc -l working.txt filtered.txt
    관찰할 결과
    Bifrost
원본 사본 3줄, 필터 결과 1줄입니다.

  3. 읽기와 쓰기를 구분하기

    자신의 작업 사본을 400으로 바꿔 읽기는 되는지 확인하고, 수정 권한은 권한 표에서 설명합니다. 실험이 끝나면 600으로 복구합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL Bash · 일반 사용자
    chmod 400 working.txt
cat working.txt
ls -l working.txt
chmod 600 working.txt
    관찰할 결과
    읽기 결과는 유지되며 400 상태의 표시는 -r--------입니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

파이프 결과를 filtered.txt에 저장하고 원본과 줄 수를 비교하세요. chmod 400과 600의 차이를 자신의 파일로 설명합니다.

막혔을 때 힌트 보기

다른 사용자 권한의 효과는 현재 소유자로만 실행해서 증명할 수 없습니다. 관찰 범위를 적으세요.

과제 해설과 예시 답안 보기
  1. 원본 notes.txt를 덮어쓰지 않는 이름 filtered.txt로 파이프 출력을 저장합니다.
  2. 새 working.txt가 세 줄인 기준에서 filtered.txt는 Bifrost 한 줄입니다. 앞선 실습에서 덧붙였다면 현재 줄 수와 이유를 기록합니다.
  3. 600은 소유자 읽기·쓰기이고 400은 소유자 읽기입니다. root, ACL, 파일시스템 정책은 이 단순 권한 표만으로 모두 설명되지 않음을 적습니다.

결과를 판단하는 기준

필터 파일에는 Bifrost 한 줄만 있고 전체 사본은 유지됩니다. 600과 400의 차이를 쓰기 비트 유무로 설명해야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

INDEPENDENT PRACTICE

도움 없이, 조건을 바꿔 보기

자신이 만든 일반 파일에서 실행 비트만 추가·제거하고 읽기 가능 여부를 확인하세요. 디렉터리의 x와 비교해 설명하세요.

  1. 위 해설을 닫고 예상 결과와 근거를 먼저 적습니다.
  2. 코드·원시 자료·문서 근거로 확인하고 예상과 실제 차이를 설명합니다.
  3. 새 반례 하나를 만들고 무엇까지 확인했는지 기록합니다.
시도한 뒤 판단 기준 읽기
