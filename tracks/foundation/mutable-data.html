01 / UNDERSTAND

먼저 이해하기

대입은 객체를 복제하는 명령이 아니라 이름을 객체와 연결하는 동작입니다. alias=original이면 두 이름이 같은 dict를 가리킵니다. 한 이름으로 키나 중첩 목록을 바꾸면 다른 이름으로 읽는 결과도 달라질 수 있어, 원본을 보존해야 하는 분석 도구에서 중요한 경계입니다.

dict(original)은 바깥 dict를 새로 만들지만 값인 tags 목록까지 복제하지 않습니다. 이를 얕은 복사라고 합니다. 바깥 dict의 키를 바꾸는 것과 tags.append로 같은 목록을 바꾸는 것을 구분해야 예상하지 않은 원본 변경을 찾을 수 있습니다.

deepcopy는 이 예제의 dict와 list로 된 중첩 자료를 별도 구조로 복사합니다. tagged_copy는 원본을 읽어 깊은 복사에 태그를 더하고 반환합니다. 함수가 입력을 바꾸지 않는다는 계약을 정하면 여러 분석 단계가 같은 원본을 안전하게 비교하기 쉬워집니다.

is는 같은 객체인지, ==는 값이 같은지 비교합니다. 새 복사본은 처음에는 값이 같아도 is가 False일 수 있고, 얕은 복사본 안의 목록은 is가 True일 수 있습니다. 값 출력만 보면 공유 관계가 숨겨지므로 바깥과 중첩 객체를 따로 확인합니다.

깊은 복사가 모든 자원과 프로그램 상태를 복제하는 것은 아닙니다. 열린 파일·잠금·외부 연결과 사용자 정의 객체에는 별도 설계가 필요하고 큰 구조에는 비용이 듭니다. 이번 실습은 작은 일반 dict/list이며, 불변 자료를 쓰거나 필요한 필드만 새로 구성하는 대안도 검토합니다.

자주 헷갈리는 지점

b=a를 원본 백업이라고 생각한다.
같은 객체의 별칭입니다. 원본 보존 계약에 맞는 복사나 불변 구조를 선택합니다.
dict를 새로 만들었으니 모든 중첩 값도 새 객체라고 생각한다.
얕은 복사는 중첩 참조를 공유합니다. 실제 변경이 일어나는 깊이에서 확인합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

tagged_copy의 사본에서 deepcopy를 dict로 바꿔 원본 보존 검사가 실패하는지 확인하세요. 그 뒤 복구하고 tags 외에 nested={"counts":[1]}을 넣어 내부 목록 수정도 독립적인지 검사하세요.

막혔을 때 힌트 보기

바깥 dict가 다른 객체인 것만으로 충분하지 않습니다. 두 단계 안의 목록을 바꾼 뒤 원본의 [1]이 유지되는지 봅니다.

과제 해설과 예시 답안 보기
  1. 원본과 반환값이 같은 객체가 아닌지뿐 아니라 원본 tags가 ["start"]인지 고정 기대값으로 비교합니다.
  2. deepcopy를 dict로 바꾼 작업 사본에서는 반환값에 done을 더할 때 원본 tags도 바뀌어야 합니다. 이 실패를 보고 복구합니다.
  3. 깊은 복사를 복구한 뒤 반환값의 nested.counts에 2를 추가해도 원본은 [1], 복사본은 [1,2]인지 확인합니다.

결과를 판단하는 기준

얕은 복사 결함에서 원본 보존 기대가 실패하고, 복구 뒤 두 중첩 목록이 독립적이어야 합니다. 복사 비용과 열린 자원은 이번 검증 범위가 아닙니다.

05 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. dict(original) 뒤 copy["tags"].append를 했더니 원본도 바뀌었습니다. 원인은?

정답과 이유 읽기

정답: 바깥 dict는 달라도 tags 목록의 참조를 공유한다.

얕은 복사는 값인 참조를 새 dict에 담습니다. 중첩 목록의 독립성은 별도 문제입니다.

2. deepcopy한 dict/list 구조에서 두 값이 처음에 ==라고 합니다. 반드시 같은 객체인가요?

정답과 이유 읽기

정답: 아니다. 값의 같음과 객체의 동일성은 다른 질문이다.

==와 is를 구분해야 합니다. 이번처럼 작은 일반 자료에서 복사 후 값은 같아도 독립 객체일 수 있습니다.
