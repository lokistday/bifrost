01 / UNDERSTAND

먼저 이해하기

16진수 03 00은 숫자 자체가 아니라 두 바이트입니다. 작은 자리부터 저장하는 little-endian으로 읽으면 3, big-endian으로 읽으면 768입니다. 숫자가 그럴듯하다는 이유만으로 순서를 고르지 말고 형식의 명세와 실제 남은 데이터 길이를 함께 비교해야 합니다.

이 차시의 BF 형식은 마법값 BF 2바이트, little-endian 길이 2바이트, 그 길이만큼의 본문으로 직접 정의한 교육용 형식입니다. ELF나 실제 문서 포맷이 아닙니다. 오프셋 2에서 <H로 읽으면 플랫폼의 기본 정렬과 무관하게 2바이트 unsigned 값을 얻습니다.

선언 길이를 읽는 것과 그만큼의 데이터가 존재하는지 검증하는 것은 별도 단계입니다. Python 슬라이스는 범위를 넘겨도 예외 없이 짧은 결과를 돌려주므로 슬라이스 성공을 유효성 검증으로 사용하면 안 됩니다. 이 모형은 남는 바이트도 거부합니다.

원시 바이트와 텍스트 표현은 구분합니다. 본문 ABC는 ASCII로 표시할 수 있지만 모든 파일이 텍스트는 아닙니다. 길이 검사는 decode 전에 하고, 표시할 수 없는 바이트를 대체 표시해도 원래 바이트를 바꾸거나 유효한 문자라고 단정하지 않습니다.

자주 헷갈리는 지점

03 00을 0x0300으로 고정해서 읽는다.
명세의 endian을 지정하고 남은 바이트 수로 확인합니다.
본문을 먼저 UTF-8로 해석한 뒤 문자 수를 길이와 비교한다.
파일 형식 길이는 바이트 단위입니다. 바이트 검증 후 표현을 정합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

길이 3을 유지한 채 마지막 43 바이트를 빼고, 정상 본문 뒤에 21을 붙인 경우도 시험하세요. 각각 왜 거부돼야 하는지 오프셋 표를 만드세요.

막혔을 때 힌트 보기

길이는 문자 수가 아니라 바이트 수입니다. 전체 길이 == 4 + 선언 길이인지 먼저 계산하세요.

과제 해설과 예시 답안 보기
  1. 03 00을 little-endian 3으로 읽고 전체 길이 7 = 헤더 4 + 본문 3을 기록합니다.
  2. 잘린 입력은 6 != 7, 여분 입력은 8 != 7이므로 같은 길이 규칙에서 거부됩니다.
  3. 길이 2·본문 AB는 6 == 4+2이므로 허용되는 별도 정상 사례로 둡니다.

결과를 판단하는 기준

정상 2건·잘림 1건·여분 1건의 실제 길이와 선언 길이가 나란히 적힌 표를 제출합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
