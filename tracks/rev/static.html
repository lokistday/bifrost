01 / UNDERSTAND

먼저 이해하기

strings는 바이너리에서 출력 가능한 문자 구간을 추출합니다. BIFROST나 match가 보인다는 사실은 그 문자열이 들어 있다는 근거이지 실제로 그 경로가 실행된다는 증거는 아닙니다. 사용되지 않는 문자열도 남을 수 있습니다.

문자열을 참조하는 함수, 비교 조건, 반환 흐름을 함께 보면 더 구체적인 가설을 세울 수 있습니다. 분석 노트에는 관찰과 해석을 별도 칸에 기록하고 다음 동적 실험으로 무엇을 검증할지 정합니다.

관찰은 명령 출력에서 직접 확인한 사실이고 가설은 그 사실로부터 예상한 동작입니다. 예를 들어 BIFROST 문자열 존재는 관찰, 그 문자열과 같을 때만 match를 출력할 것이라는 설명은 코드 연결이 필요한 가설입니다. 보고서에서 두 문장을 같은 확신으로 쓰지 않습니다.

문자열이 어떤 함수에서 참조되는지와 조건 분기의 방향을 연결하면 단서를 좁힐 수 있습니다. 이 예제는 소스가 함께 있어 가설을 검토하기 쉽지만, 실제 최적화 바이너리에서는 문자열 공유·인라인·사용되지 않는 자료 때문에 이름만으로 기능을 확정하기 어렵습니다.

반례는 기존 가설이 틀릴 수 있는 입력입니다. 길이 7이면 모두 일치한다는 가설에는 길이는 7이지만 다른 BIFROSa가 좋은 반례입니다. 정확한 대문자 문자열만 일치한다는 가설은 길이 변화·대소문자 변화·같은 길이의 내용 변화로 구분해 검증 계획을 세웁니다.

자주 헷갈리는 지점

해석 문장을 도구의 원문 출력처럼 기록한다.
명령 출력에서 본 관찰과 사람이 추정한 가설을 별도 칸에 씁니다.
성공 입력 하나만 정적 가설의 검증 계획으로 둔다.
조건을 하나씩 바꾸는 입력과 반례를 설계해 가설을 구분합니다.

변경 전 예상 결과와 해석

BIFROST, match, no match 같은 문자열과 관련 함수의 코드가 관찰됩니다.

이제 단계별로 바꾸고 관찰하기

  1. 문자열 단서만 먼저 기록하기

    strings check 결과에서 BIFROST와 출력 메시지를 찾고 명령을 함께 적습니다. 문자열이 보인 사실과 실행되는 조건을 아직 분리합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GNU strings·objdump · analysis.md
    strings check
    관찰할 결과
    BIFROST와 match/no match에 해당하는 문자열을 관찰할 수 있습니다. 출력 전체는 환경에 따라 다릅니다.

  2. 코드 연결 근거 추가하기

    objdump에서 check의 비교 흐름과 main의 메시지 선택을 연결합니다. analysis.md에 관찰 / 해석 / 추가 검증 세 칸을 만듭니다.

    관찰 절차·자료 예시 · 그대로 셸에 붙여 넣지 말고 본문 안내를 따라 확인
    관찰: 길이 비교 및 문자열 비교에 해당하는 코드
해석: 두 조건이 모두 참일 때 match 경로
추가 검증: 같은 길이의 다른 문자열 실행
    관찰할 결과
    정적 코드 근거가 있는 가설과 아직 확인하지 않은 부분이 구분됩니다.

  3. 가설을 구분할 입력 설계하기

    BIFROST, ABCDEFG, bifrost, BIF를 고릅니다. 모든 입력이 서로 다른 목적을 가지도록 정상 / 길이만 같음 / 대소문자 변경 / 길이 다름을 붙입니다. 아직 실행 전이므로 결과 칸은 예상으로 표시합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

analysis.md에 길이 7이면서 정확한 대문자 문자열이어야 한다는 가설과 근거를 적고, 길이만 같은 반례 입력을 정하세요.

막혔을 때 힌트 보기

문자열 하나만으로 비밀번호·인증 기능이라고 단정하지 마세요. 이 프로그램은 입력 비교 데모입니다.

과제 해설과 예시 답안 보기
  1. analysis.md에 문자열 존재와 코드 비교를 관찰로 적고 길이 7과 정확한 대문자 일치가 필요하다는 가설을 씁니다.
  2. 길이만 같으면 된다는 더 약한 가설을 배제하기 위해 BIFROSa 또는 ABCDEFG를 반례 입력으로 고릅니다.
  3. 외부 서비스 인증·비밀번호 보호 같은 기능은 이 작은 비교 데모에서 확인한 사실이 아니므로 결론 범위에 넣지 않습니다.

결과를 판단하는 기준

문자열 단서 / 코드 근거 / 가설 / 반례 목적이 각각 있어야 합니다. 실행하지 않은 결과는 관찰로 적지 않아야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
