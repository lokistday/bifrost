01 / UNDERSTAND

먼저 이해하기

fe ff 두 바이트를 little-endian 16비트로 읽으면 unsigned 값 65534와 signed 값 -2가 됩니다. 바이트가 바뀐 것이 아니라 16비트의 최상위 비트를 어떻게 해석할지 달라진 것입니다. 저장 폭과 부호를 명시하지 않은 숫자 추론은 비교 분기를 잘못 해석할 수 있습니다.

16비트 값을 32비트로 넓힐 때 0으로 채우면 0000fffe, 부호를 유지하도록 상위 비트를 채우면 fffffffe입니다. 이 출력은 32비트 비트패턴의 Hex 표시이지 파일의 바이트 순서가 아닙니다. 실제 명령어에서는 zero/sign extension과 비교의 부호 조건을 함께 확인합니다.

예제 flags=0xa5는 하위 4비트 version=5, 최상위 비트 urgent=1, 중간 3비트 reserved=2로 정의합니다. &15와 오른쪽 이동은 각 필드만 분리합니다. 이 배치는 자체 모형의 명세이며 C 구조체 비트필드의 메모리 배치나 네트워크 표준으로 일반화하지 않습니다.

Python 정수는 임의 정밀도이므로 signed & 0xffffffff처럼 표시할 폭을 명시합니다. Python에서 동작한 비트 연산을 곧바로 C의 signed overflow나 모든 shift 규칙에 적용하면 안 됩니다. 이 실습은 명시적 struct 크기와 마스크로 해석 차이를 관찰합니다.

자주 헷갈리는 지점

ffffffff 같은 표기를 파일의 바이트 순서와 혼동한다.
정수 비트패턴 표시와 메모리 저장 순서를 분리합니다.
Python 정수 규칙을 모든 C 연산에 적용한다.
C 자료형 폭·승격·부호·오버플로 규칙을 별도로 확인합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

0080과 ff7f를 비교해 부호가 바뀌는 경계를 기록하세요. flags의 urgent만 끄고 version을 유지하는 입력도 만드세요.

막혔을 때 힌트 보기

little-endian 0080은 0x8000입니다. urgent는 bit7, version은 하위 4비트입니다.

과제 해설과 예시 답안 보기
  1. ff7f는 32767/32767, 0080은 32768/-32768이므로 bit15가 부호 경계입니다.
  2. 0x85 & 0x7f = 0x05로 urgent만 끄고 하위 version=5를 유지합니다.
  3. 표시의 00008000/ffff8000을 메모리 byte order와 구분해 적습니다.

결과를 판단하는 기준

두 경계값의 signed/unsigned·확장 패턴·flags 필드 변화와 폭 오류를 기록합니다.
