01 / UNDERSTAND

먼저 이해하기

소스의 switch가 기계어에서도 점프 하나씩으로 보인다고 가정하면 안 됩니다. 컴파일러는 case의 밀도·반환 패턴·최적화 옵션과 대상 CPU에 따라 비교 체인, 점프 테이블, 값 조회 표, 산술식 등으로 바꿀 수 있습니다. 형태를 보고 원래 소스를 단정하기보다 의미를 복원합니다.

switches.c의 classify는 0~5에 고정 정수 11,17,23,31,47,59를 반환하고 나머지는 -1입니다. 반환 상수만 다른 이 예제는 -O2에서 함수 주소 점프표가 아니라 정수 값 조회 표로 바뀔 수 있습니다. 데이터 표를 코드 주소 표로 잘못 해석하지 않도록 사용 명령을 확인합니다.

범위 검사와 기본값 경로는 표의 시작점만큼 중요합니다. 음수 -1과 마지막 case 밖 6을 함께 실행해 무조건 인덱싱한다는 잘못된 가설을 구분합니다. 이 예제는 외부 입력을 실행 주소로 쓰는 도구가 아니라 고정 배열로 작은 함수의 분기 의미를 관찰합니다.

두 빌드의 출력이 같은 것은 검사한 8개 입력에서 관찰 의미가 같다는 근거입니다. 주소·명령어 수·표의 유무가 같아야 하는 것은 아닙니다. 최적화가 다른 결과를 만들었다면 먼저 소스·빌드·undefined behavior 가능성을 점검하며 본 실습에서는 정의된 작은 정수 입력만 사용합니다.

자주 헷갈리는 지점

switch이면 항상 점프 테이블을 찾는다.
비교 체인·값 표·산술 변환 등 다른 구현을 고려합니다.
표의 존재만으로 원소를 코드 주소라고 부른다.
로드·산술·점프에서 값이 어떻게 사용되는지 확인합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
gcc -g -O0 -Wall -Wextra switches.c -o switch-o0
gcc -g -O2 -Wall -Wextra switches.c -o switch-o2
./switch-o0
./switch-o2

변경 전 예상 결과와 해석

-1:-1 0:11 1:17 2:23 3:31 4:47 5:59 6:-1
두 빌드에서 같은 한 줄이 출력됩니다.

이제 단계별로 바꾸고 관찰하기

  1. 두 빌드의 관찰 계약 만들기

    같은 소스를 최적화만 달리 빌드하고 고정 8개 입력의 출력을 비교합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    gcc -g -O0 -Wall -Wextra switches.c -o switch-o0
gcc -g -O2 -Wall -Wextra switches.c -o switch-o2
./switch-o0
./switch-o2
    관찰할 결과
    두 실행 모두 -1:-1 0:11 1:17 2:23 3:31 4:47 5:59 6:-1

  2. 명령의 목적을 분류하기

    분기 목적지 주소를 세기보다 입력 범위 검사·기본값 반환·case값 선택을 찾아 주석을 답니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    objdump -d -Mintel --disassemble=classify switch-o0
objdump -d -Mintel --disassemble=classify switch-o2
    관찰할 결과
    동일 의미를 다른 명령 배치로 구현할 수 있습니다. -O2에서 값 표가 보일 수 있으나 표나 점프의 정확한 형태는 보장하지 않습니다.

  3. 반환 상수 하나만 변경하기

    사본의 case2 반환만 29로 바꾼 후 빌드합니다. 바뀐 출력 열과 관련 상수/표를 연결합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    gcc -g -O2 -Wall -Wextra switches-work.c -o switch-work
./switch-work
    관찰할 결과
    -1:-1 0:11 1:17 2:29 3:31 4:47 5:59 6:-1
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

최적화 두 빌드에서 범위 밖 입력과 case값 표 사용을 비교하세요. case2의 반환을 23→29로 바꾼 사본의 출력과 정적 표 변화도 기록하세요.

막혔을 때 힌트 보기

간접 점프인지, 인덱스로 정수 값을 읽는 명령인지 구분하세요. 특정 GCC 버전의 모양을 정답으로 고정하지 않습니다.

과제 해설과 예시 답안 보기
  1. case2에서만 23→29로 바꾸고 다른 case/default는 유지합니다.
  2. 입력2의 출력만 바뀌는지 비교하고 정적 코드나 값 표의 바뀐 상수를 찾습니다.
  3. 실제 명령 형태를 기록하고 이 결과만으로 모든 switch가 같은 방식으로 컴파일된다고 쓰지 않습니다.

결과를 판단하는 기준

두 최적화의 의미 대응·기본값 경로·상수 한 개 변경을 실행 결과와 연결합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
