01 / UNDERSTAND

먼저 이해하기

동적 분석은 특정 입력에서 실제로 실행한 경로를 관찰합니다. 한 번의 성공 입력으로 모든 입력의 동작을 증명할 수는 없습니다. 정상·길이 불일치·길이만 일치·대소문자 변경을 나눠 테스트합니다.

GDB break check로 함수 진입에 멈추고 print text로 인자를 확인한 뒤 finish로 호출자까지 실행하면 반환값을 관찰할 수 있습니다. 최적화나 심볼 상태에 따라 표시가 달라지므로 이 실습은 -g -O0 빌드를 기준으로 합니다.

실행을 관찰하면 해당 입력에서 어떤 경로를 지났는지 확인할 수 있습니다. 반면 성공 입력 한 개는 다른 길이·내용·인자 개수의 동작까지 말해 주지 않습니다. 정적 가설을 검증할 입력표를 먼저 두면 관찰의 범위가 분명해집니다.

finish는 현재 함수를 호출자에게 돌아갈 때까지 실행하고 반환값을 보여 줄 수 있습니다. check가 1을 반환하는 것과 main이 0으로 끝나는 것은 서로 다른 프레임의 값입니다. continue를 해야 main의 메시지 출력과 전체 종료까지 이어서 관찰할 수 있습니다.

동적 결과가 정적 가설과 다르면 주소 차이만 찾지 말고 분석한 실행 파일과 실제 실행 파일, 빌드 옵션, 입력 철자와 길이부터 비교합니다. 소스를 고쳤는데 다시 빌드하지 않은 경우에도 서로 다른 근거를 연결하는 실수가 생깁니다.

자주 헷갈리는 지점

성공 입력만 반복해서 테스트 범위가 넓어졌다고 생각한다.
각 입력이 어떤 조건을 바꾸는지 적고 길이·내용·누락 경로를 구분합니다.
함수 반환 1을 프로세스 실패 상태 1로 적는다.
check의 판정값과 main이 반환하는 종료 상태를 프레임별로 기록합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

혼합 절차 · 먼저 터미널에서 빌드·gdb 실행 → 주석 아래는 GDB 콘솔에 입력
gdb --args ./check BIFROST
# GDB에서
break check
run
print text
finish
continue
quit

변경 전 예상 결과와 해석

입력 문자열 BIFROST가 보이고 check는 참에 해당하는 값을 반환한 뒤 match를 출력합니다.

이제 단계별로 바꾸고 관찰하기

  1. 성공 입력을 함수 진입에서 보기

    Bash에서 gdb --args로 프로그램 인자를 지정하고, GDB에서 중단점을 설정해 실행합니다. text가 예측한 입력인지 먼저 확인합니다.

    혼합 절차 · 먼저 터미널에서 빌드·gdb 실행 → 주석 아래는 GDB 콘솔에 입력
    gdb --args ./check BIFROST
# GDB 프롬프트
break check
run
print text
    관찰할 결과
    text가 BIFROST를 가리키는 것을 확인합니다. 주소는 고정하지 않습니다.

  2. 함수 반환과 전체 출력을 구분하기

    finish 후 check의 반환값을 적고 continue로 main의 출력을 봅니다. 반환값이 1이라고 프로세스가 종료 상태 1이 되는 것은 아닙니다.

    GDB 콘솔 명령 · 대상 실행 파일을 연 같은 디버깅 세션
    finish
continue
quit
    관찰할 결과
    check의 반환값은 1이고 이어 match가 출력됩니다. 프로그램의 정상 종료 상태는 0입니다.

  3. 조건 하나씩 바꿔 재실행하기

    BIFROSa와 bifrost는 모두 7바이트지만 문자열이 다릅니다. 같은 중단 절차 또는 일반 실행으로 비교한 뒤 함수 반환과 출력의 차이를 표로 만듭니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GDB · -g -O0 빌드
    ./check BIFROSa
./check bifrost
./check BIF
    관찰할 결과
    세 입력 모두 no match입니다. 각 실패 이유를 길이 조건 또는 내용 조건과 연결합니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

BIFROSa와 bifrost로 다시 실행해 길이가 같아도 결과가 다른 이유를 관찰하세요.

막혔을 때 힌트 보기

finish와 continue는 다릅니다. 반환값을 확인한 후 전체 프로그램을 계속 실행하세요.

과제 해설과 예시 답안 보기
  1. BIFROST는 check 반환 1 / match, BIFROSa와 bifrost는 반환 0 / no match로 기록합니다.
  2. 추가로 BIF를 넣으면 길이 조건에서 거짓이 되는 경로라는 정적 가설과 대조합니다.
  3. GDB에서 입력 확인 → finish 반환 확인 → continue 전체 실행 순서를 유지하고, 입력별로 가설과 관찰 결과를 나눠 씁니다.

결과를 판단하는 기준

동일 빌드에서 정상·같은 길이의 다른 내용·대소문자 변경을 구분한 결과표가 있어야 합니다. 함수 반환과 main 종료 상태도 구분되어야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
