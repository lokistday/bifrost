01 / UNDERSTAND

먼저 이해하기

데이터 흐름 분석은 어떤 입력 값이 어떤 연산을 지나 출력에 영향을 주는지 추적합니다. 이 실습은 각 바이트를 0x20과 XOR한 뒤 인덱스를 더합니다. 같은 입력 바이트라도 위치가 다르면 결과가 달라져 단순한 문자 치환표와 구분됩니다.

BIF의 바이트 값은 66,73,70입니다. XOR 뒤에는 98,105,102가 되고 인덱스 0,1,2를 더하면 98,106,104가 됩니다. 중간 값을 기록하면 결과 62 6a 68이 단지 문자열 힌트가 아니라 연산의 결과라는 근거를 확보합니다.

역변환은 마지막 연산부터 거꾸로 수행합니다. 저장값에서 인덱스를 빼고 0x20과 XOR해야 합니다. XOR을 먼저 적용하고 인덱스를 빼는 가설은 연산 순서가 바뀌어 일반적으로 실패합니다. 순환 검사는 한 입력뿐 아니라 길이와 반복 문자가 다른 입력에도 적용합니다.

ASCII 16바이트 이하라는 입력 범위를 정해 덧셈 결과가 0~255 범위를 벗어나지 않게 했습니다. 이 변환은 키도 인증도 없으며 보안을 제공하는 암호가 아닙니다. 실제 바이너리에서 비슷한 패턴이 보여도 주변의 입력 검증·버퍼 범위·다른 경로를 추가로 확인해야 합니다.

자주 헷갈리는 지점

가역 변환이면 안전한 암호라고 생각한다.
가역성은 기능 성질이며 비밀성·인증과 다릅니다.
한 순환 테스트의 성공으로 연산 순서를 증명한다.
경계 문자와 다른 길이로 반례를 찾습니다.

  3. 역연산 순서 검증

    Python 한 줄 명령으로 순서가 다른 두 역변환을 직접 비교합니다. XOR과 덧셈은 일반적으로 교환되지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · 오프라인 · Python 3.10 이상 · 표준 라이브러리

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

AAA를 입력하고 같은 문자라도 저장 바이트가 다른 이유를 설명하세요. 잘못된 역연산 순서가 실패하는 최소 입력도 찾아보세요.

막혔을 때 힌트 보기

변환은 (value ^ 0x20) + index입니다. 역순으로 index를 먼저 빼야 합니다.

과제 해설과 예시 답안 보기
  1. AAA의 stored는 97,98,99로 인덱스의 영향을 확인합니다.
  2. AAA만으로 역순 가설을 구분할 수 없으므로 source의 XOR 결과가 0x1f 또는 0x3f 경계를 지나도록 ASCII ?를 포함합니다.
  3. 예를 들어 b'A?'의 두 번째 문자는 XOR 결과 31에 1을 더해 32입니다. 올바른 역변환은 63, 잘못된 순서는 (32 ^ 32)-1=-1로 bytes 생성도 실패합니다.

결과를 판단하는 기준

우연히 양쪽 순서가 통과하는 AAA와 실패를 드러내는 A?를 대비하고, 올바른 decode(encode(x)) == x를 확인합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
