01 / UNDERSTAND

먼저 이해하기

어셈블리는 CPU 명령을 읽을 수 있는 표기로 나타냅니다. 레지스터는 CPU의 작은 저장소이며 비교와 분기는 계산 결과에 따라 다음 실행 위치를 고릅니다. 함수 인자·반환값 전달 방식은 해당 플랫폼의 ABI가 정합니다.

이 예제에서는 strlen 결과와 7의 비교, strcmp 호출 또는 이에 대응하는 코드, 참/거짓 반환을 찾아봅니다. 최적화가 켜지면 라이브러리 호출이 변형되거나 상수 비교로 바뀔 수 있으므로 특정 명령 줄이 반드시 나와야 한다고 가정하지 않습니다.

처음에는 모든 명령을 번역하려 하지 말고 함수 시작, 호출, 비교, 조건 분기, 반환을 표시합니다. 소스의 &&는 앞 조건이 거짓이면 뒤 비교를 수행할 필요가 없는 단락 평가입니다. 길이가 7이 아닌 입력에서 문자열 비교 쪽을 건너뛰는 경로를 찾아보세요.

strcmp는 두 문자열이 같을 때 0을 반환합니다. 이 소스는 strcmp(...) == 0이라는 추가 판정으로 참을 만듭니다. strlen은 널 종료 바이트를 제외한 바이트 수를 반환합니다. 예시의 BIFROST는 ASCII 7바이트이며 한글 화면 글자 수와 같은 개념으로 일반화하지 않습니다.

호출 규약은 함수가 인자를 어디에 받고 결과를 어디에 두는지 정한 약속입니다. Ubuntu x86-64의 System V AMD64에서는 첫 포인터 인자를 RDI로, int 결과를 EAX로 읽는 경우를 확인할 수 있습니다. AArch64의 AAPCS64에서는 첫 포인터 인자는 X0, int 결과는 W0에 대응합니다. 도구가 함수 내부 저장소로 옮긴 뒤에는 원래 인자 레지스터만 계속 읽지 않도록 데이터 이동도 따라갑니다.

자주 헷갈리는 지점

AT&T 표기와 Intel 표기의 피연산자 순서를 확인하지 않는다.
objdump가 사용하는 문법과 CPU를 먼저 적고 데이터 이동 방향을 읽습니다.
함수 진입 인자 레지스터가 함수가 끝날 때까지 그대로일 것으로 가정한다.
호출이나 임시값 사용으로 바뀔 수 있으므로 저장·복원과 값 이동을 따라갑니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GNU objdump · -g -O0 check
objdump -d check > disassembly.txt
# disassembly.txt에서 <check>를 찾아 함수 범위를 읽습니다.

변경 전 예상 결과와 해석

check의 명령 목록과 길이 검사·문자열 비교에 해당하는 제어 흐름을 찾습니다. 명령어 표기는 CPU마다 다릅니다.

이제 단계별로 바꾸고 관찰하기

  1. 함수 범위를 좁혀 읽기

    전체 출력에서 <check> 위치를 찾습니다. 필요하면 --disassemble=check로 함수만 출력해 호출·분기·반환에 주석을 붙입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GNU objdump · -g -O0 check
    objdump -d --disassemble=check check
    관찰할 결과
    check 함수의 명령 목록을 얻습니다. 명령 주소와 표기 방식은 CPU·빌드에 따라 달라집니다.

  2. 두 조건을 제어 흐름에 연결하기

    strlen 결과와 길이 7 판정, strcmp 결과와 0 판정을 찾습니다. 호출이 보이지 않으면 동등한 길이·바이트 비교로 바뀌었는지 확인합니다. 분기의 주소를 소스 줄 번호와 혼동하지 않습니다.

    관찰 절차·자료 예시 · 그대로 셸에 붙여 넣지 말고 본문 안내를 따라 확인
    가설: 길이 != 7 → 거짓 반환
가설: 길이 == 7 → 문자열 일치 판정 → 참 또는 거짓
    관찰할 결과
    두 조건이 모두 충족되어야 참인 흐름을 설명합니다.

  3. ABI와 관찰값 연결하기

    자신의 CPU와 ABI를 적고 인자가 함수 진입 후 어디로 이동하는지 따라갑니다. GDB의 print text를 함께 보면 이름 있는 인자와 낮은 수준의 전달 상태를 비교할 수 있습니다. 하나의 레지스터 이름을 다른 CPU 결과에 강제로 적용하지 않습니다.

05 / VERIFY

이 정도면 다음으로

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. strcmp(text, "BIFROST")가 0을 반환했습니다. 소스의 == 0 판정은 어떤 의미인가요?

정답과 이유 읽기

정답: 두 문자열이 같아서 그 조건은 참이다.

strcmp의 0은 문자열 일치를 뜻합니다. 함수 비교 결과, check의 불리언 반환, main의 프로세스 종료 상태를 구분합니다.

2. 입력 길이가 3이면 && 뒤의 문자열 비교는 반드시 실행되어야 하나요?

정답과 이유 읽기

정답: 아니다. 앞 조건이 거짓이면 &&는 뒤 식 평가를 생략한다.

C의 &&는 단락 평가를 합니다. 빌드 형태가 달라도 이 식의 의미를 유지하는 제어 흐름을 찾아야 합니다.
