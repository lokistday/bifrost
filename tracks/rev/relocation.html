01 / UNDERSTAND

먼저 이해하기

소스의 extern int adjust(int)는 함수의 정의를 현재 파일에 넣지 않습니다. linkmain.o에는 adjust 참조와 링크 단계에서 해결할 위치에 대한 재배치 정보가 남습니다. 함수 이름이 U로 보인다고 파일 손상이나 실행 실패를 바로 뜻하지는 않습니다.

linkpart.c를 -fPIC -shared로 빌드하면 위치 독립 코드를 가진 자체 libbfmath.so를 만듭니다. 실행 파일은 이 라이브러리의 adjust와 libc의 printf에 의존합니다. 동적 연결은 적재 후 필요한 심볼 참조를 해결하는 과정이며 소스가 한 파일로 합쳐지는 것과 다릅니다.

이 실습은 실행 파일 위치를 기준으로 자체 라이브러리를 찾도록 $ORIGIN rpath를 설정합니다. Bash에서 작은따옴표를 유지해 빌드 셸이 변수로 확장하지 않게 합니다. 교육 폴더의 직접 만든 파일만 실행하며 시스템 라이브러리나 검색 경로를 덮어쓰지 않습니다.

readelf -d의 NEEDED는 필요한 라이브러리 이름을 보여 주지만 실제 어떤 경로의 파일이 선택됐는지와 함수가 호출됐는지는 추가 런타임 근거가 필요합니다. 낯선 바이너리에 무조건 실행 도구를 적용하지 말고 이 차시의 자체 소스와 빌드 결과로 한정합니다.

자주 헷갈리는 지점

U 심볼을 손상으로 단정한다.
객체/실행 파일/공유 라이브러리의 단계와 정의 위치를 확인합니다.
$ORIGIN의 따옴표를 없애 셸 확장을 일으킨다.
Bash 작은따옴표를 유지하고 readelf -d로 경로 태그를 확인합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
gcc -g -O0 -c linkmain.c -o linkmain.o
gcc -g -O0 -fPIC -shared linkpart.c -o libbfmath.so
gcc linkmain.o -L. -lbfmath -Wl,-rpath,'$ORIGIN' -o linkdemo
./linkdemo

변경 전 예상 결과와 해석

adjusted=12

이제 단계별로 바꾸고 관찰하기

  1. 객체의 미해결 참조 관찰

    별도 객체로 컴파일하고 재배치와 심볼을 확인합니다. adjust 정의가 없는 것은 이후 연결을 기다리는 정상적인 상태입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    gcc -g -O0 -c linkmain.c -o linkmain.o
readelf -rW linkmain.o
nm linkmain.o
    관찰할 결과
    adjust와 printf에 대한 참조가 보이며 nm에서 U adjust가 표시됩니다. 재배치 이름/오프셋은 플랫폼마다 다릅니다.

  2. 자체 라이브러리와 실행 파일 만들기

    제공한 함수만 공유 라이브러리로 만들고 같은 폴더의 실행 파일에 연결합니다. 아래 명령은 Bash입니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    gcc -g -O0 -fPIC -shared linkpart.c -o libbfmath.so
gcc linkmain.o -L. -lbfmath -Wl,-rpath,'$ORIGIN' -o linkdemo
./linkdemo
    관찰할 결과
    adjusted=12

  3. 선언과 의존성 대조

    객체의 U adjust와 라이브러리의 정의, 실행 파일의 NEEDED를 나란히 봅니다. libc의 정확한 버전 경로를 고정하지 않습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GNU binutils
    nm -D libbfmath.so
readelf -dW linkdemo
    관찰할 결과
    라이브러리에 T adjust가 있고 NEEDED에 libbfmath.so와 C 런타임 라이브러리가 표시됩니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

공유 라이브러리 사본에서 +7을 +9로 바꿔 다시 빌드하고 실행 파일을 재링크하지 않은 채 출력이 바뀌는지 확인하세요. 객체 파일의 미해결 참조와 라이브러리의 정의도 비교하세요.

막혔을 때 힌트 보기

실행 파일과 libbfmath.so를 같은 실습 폴더에 둡니다. $ORIGIN은 문자열 그대로 링커에 전달합니다.

과제 해설과 예시 답안 보기
  1. linkpart-work.c의 +9 버전으로 같은 libbfmath.so만 다시 빌드합니다.
  2. 새 프로세스에서 ./linkdemo를 실행하면 adjusted=14입니다. linkmain.o나 실행 파일의 재링크는 필요하지 않습니다.
  3. 이는 새 실행이 새 라이브러리를 연결한 관찰이며 이미 실행 중인 프로세스의 코드가 자동 교체됐다는 뜻은 아닙니다.

결과를 판단하는 기준

객체 U 심볼·라이브러리 정의·NEEDED·새 실행의 변경 출력과 관찰 한계를 연결합니다.
