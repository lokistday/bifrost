01 / UNDERSTAND

먼저 이해하기

실행 파일에는 기계어 외에 헤더, 섹션, 문자열, 심볼 등이 들어갈 수 있습니다. ELF는 Linux에서 쓰이는 실행 파일 형식이고 PE는 Windows에서 흔한 형식입니다. 형식과 아키텍처가 분석 도구의 해석에 영향을 줍니다.

제공한 check.c를 -O0 -g로 빌드하면 학습용 함수와 소스 대응을 관찰하기 쉽습니다. 심볼은 사람이 읽는 이름과 주소를 연결합니다. 심볼이 없다고 코드가 없는 것은 아닙니다.

심볼 check는 소스 파일 이름 check.c나 실행 파일 이름 check와 구분합니다. nm의 T 같은 표시는 심볼의 종류에 관한 정보이며 그 함수가 이번 입력에서 실행됐다는 뜻은 아닙니다. 정적 존재와 실제 실행을 분리해 기록합니다.

이 프로그램에서 check 함수의 판정값과 main의 종료 상태는 다릅니다. BIFROST이면 check는 참을 반환하고 match를 출력하지만 main은 입력이 하나 주어진 두 경우 모두 0을 반환합니다. 인자 개수가 다를 때만 사용법을 출력하고 2로 종료합니다.

실행 파일의 형식·아키텍처·심볼 상태를 먼저 알면 어떤 도구로 어느 수준까지 관찰할지 정할 수 있습니다. 디버깅 정보가 있다고 원본 프로젝트 전체가 포함된 것은 아니며, 심볼이 없다고 분석 자체가 불가능한 것도 아닙니다.

자주 헷갈리는 지점

실행 파일 check와 함수 check를 같은 이름이라는 이유로 같은 개념으로 읽는다.
파일·함수·프로세스 단계를 구분해서 표기합니다.
모든 no match를 비정상 프로세스 종료라고 기록한다.
메시지와 종료 상태를 각 실행에서 따로 관찰합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

  1. 직접 빌드한 대상 식별하기

    -g -O0 학습 빌드를 만들고 file과 nm를 봅니다. nm에서 check라는 함수 심볼을 찾되 main과 별개인지 확인합니다.

    작게 나눠 확인하기
    gcc -Wall -Wextra -g -O0 check.c -o check
file check
nm check
    관찰할 결과
    실행 형식과 CPU 정보, check 및 main 함수 심볼이 관찰됩니다. 주소는 환경마다 다릅니다.

  2. 메시지와 종료 상태를 함께 보기

    Bash에서 각 실행 바로 뒤 echo $?를 입력합니다. 성공/불일치 메시지는 프로그램의 판정이며 종료 상태 0은 main이 정한 별도 신호입니다.

    작게 나눠 확인하기
    ./check BIFROST
echo $?
./check bifrost
echo $?
    관찰할 결과
    match
0
no match
0

  3. 빠진 인자 경로 확인하기

    인자가 없을 때는 check 함수를 호출하는 정상 비교 경로와 다릅니다. 사용법 메시지와 종료 상태를 함께 기록합니다.

    작게 나눠 확인하기
    ./check
echo $?
    관찰할 결과
    usage: check WORD
2

전체 예제 연결하기

예제 · 명령 또는 관찰 절차
gcc -g -O0 check.c -o check
file check
nm check
./check BIFROST
./check WRONG

예상 결과와 해석

check 함수의 심볼을 찾을 수 있고 실행 결과는 각각 match, no match입니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

입력 인자가 없을 때와 소문자 bifrost를 넣었을 때의 결과·종료 상태를 기록하세요.

막혔을 때 힌트 보기

인자를 빠뜨리면 사용법을 출력하고 종료합니다. 성공 메시지와 프로세스 종료 코드는 다른 관찰값입니다.

과제 해설과 예시 답안 보기
  1. 소문자 bifrost는 길이는 같지만 정확한 문자열이 아니므로 no match이고 종료 상태는 0입니다.
  2. 인자 없음은 usage: check WORD를 출력하며 종료 상태 2입니다.
  3. 세 결과를 입력 / stdout / 종료 상태 표로 나누고 함수 판정과 프로세스 결과를 혼동하지 않습니다.

결과를 판단하는 기준

BIFROST → match·0, bifrost → no match·0, 인자 없음 → usage: check WORD·2입니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
