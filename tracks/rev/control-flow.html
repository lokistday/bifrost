01 / UNDERSTAND

먼저 이해하기

제어 흐름 그래프는 실행 위치 사이의 가능한 이동을 표현합니다. 소스의 if 하나가 항상 기계어 분기 하나와 일치하지는 않습니다. 먼저 입력과 상태 변화를 추적한 뒤 objdump의 점프 목적지를 루프 헤더·누적·종료 블록으로 묶어 가설을 세웁니다.

flow.c는 양수만 더하고 음수는 건너뛰며 0에서 전체 반복을 종료합니다. continue는 다음 원소로 이동하고 break는 루프 밖으로 나갑니다. 두 문장을 모두 단순 실패 경로로 묶으면 0 뒤의 99가 더해지지 않는 이유를 설명할 수 없습니다.

반환값은 원소별 판정만 아니라 누적 상태 total에도 의존합니다. 입력 4,-2,6,0,99는 4→4→10→종료이므로 10입니다. 0을 제거하면 마지막 99도 누적돼 109가 됩니다. 조건 하나만 바꾼 두 입력이 서로 다른 경로 가설을 구분합니다.

교육용 프로그램은 원소 1~8개, 각 값 -100~100으로 제한해 int 합산 범위를 충분히 좁힙니다. 이 검증을 제거한 임의 정수의 누적은 오버플로를 별도로 검토해야 합니다. -O0와 -O2 출력이 같아도 기계어의 블록 구조가 같다는 뜻은 아닙니다.

자주 헷갈리는 지점

음수와 0을 모두 건너뛰는 경로로 적는다.
continue와 break의 다음 목적지를 구분합니다.
최종 합이 같으면 같은 실행 경로라고 생각한다.
방문 원소와 상태 변화를 별도로 추적합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GDB·binutils
gcc -g -O0 -Wall -Wextra flow.c -o flow
./flow 4 -2 6 0 99
./flow 4 -2 6 99

변경 전 예상 결과와 해석

sum=10
sum=109

이제 단계별로 바꾸고 관찰하기

  1. 상태 변화를 먼저 예측하기

    코드를 읽고 각 원소를 처리한 뒤 total을 적습니다. 뒤의 99를 일부러 두어 break가 전체 루프를 끝내는지 구분합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GDB·binutils
    gcc -g -O0 -Wall -Wextra flow.c -o flow
./flow 4 -2 6 0 99
    관찰할 결과
    sum=10

  2. 분기 조건 하나만 제거하기

    0만 제거해 누적 경로가 마지막까지 이어지는지 확인합니다. 음수 -2는 여전히 건너뜁니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GDB·binutils
    ./flow 4 -2 6 99
./flow 0 4
    관찰할 결과
    sum=109
sum=0

  3. 역어셈블을 블록으로 묶기

    주소를 외우지 말고 sum_positive의 루프 조건, 0 비교, 음수 비교, 누적, 다음 인덱스 경로를 소스와 연결합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL x86-64 · GCC·GDB·binutils
    objdump -d -Mintel --disassemble=sum_positive ./flow
    관찰할 결과
    sum_positive의 비교·조건 점프·누적 명령이 보입니다. 명령어와 주소의 정확한 배치는 컴파일러마다 다릅니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

첫 원소 0, 모두 음수, 마지막만 0인 입력을 각각 만들고 방문한 원소와 total 변화를 표로 적으세요.

막혔을 때 힌트 보기

0은 더할 값이 0인 사례가 아니라 반복 종료 신호입니다. 0 뒤 원소는 방문하지 않습니다.

과제 해설과 예시 답안 보기
  1. ./flow 0 4는 첫 원소에서 종료해 sum=0입니다.
  2. ./flow -1 -2 -3은 모두 continue 경로로 이동해 sum=0입니다.
  3. ./flow 4 6 0은 4와 6을 더하고 마지막에서 종료해 sum=10입니다. 각 경우에 방문하지 않은 원소를 구분합니다.

결과를 판단하는 기준

세 입력에 대해 검사한 인덱스·분기·처리 후 total이 있어야 하며 sum만 같다고 같은 경로로 묶지 않습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
