Reverse Engineering

소스 코드가 없어도 실행 파일의 동작을 알아낼 수 있을까?

주로 다루는 문제
실행 파일의 동작 파악, 함수·조건 분기 추론, 의심스러운 프로그램 분석
만나는 개념
어셈블리·호출 규약, 바이트 순서, 제어·데이터 흐름, 정적·동적 분석, 차등 검증
잘 맞을 수 있는 관심
퍼즐처럼 단서를 연결하고, 관찰 근거를 바탕으로 동작을 추론하는 일을 즐긴다.
도움 되는 기초
C 기초와 함수·조건문 이해가 도움이 된다. 어셈블리는 작은 예제부터 익힌다.
첫 실습

차시별 독립 과제에서 조건을 바꿔 보고, 마지막에는 두 표본을 분석한 결과와 근거 보고서를 완성합니다.

차시 검색 · 목표별 경로 ↗
WHAT YOU WILL BUILD

이 과정을 마치면

바이트·함수 경계·분기·데이터 의존성을 근거로 동작 가설을 세우고 최소 반례와 회귀 검사로 검증합니다.

01 · 바이너리와 정적 관찰

Ubuntu/WSL gcc·binutils 기준입니다. 명령어와 호출 규약은 x86-64와 ARM64에서 다르므로 이름을 고정해 외우지 않습니다.

  1. ELF·심볼·컴파일 옵션실행 파일의 정보와 분석 환경을 식별합니다.↗
  2. 명령어·비교·호출 읽기기계어 목록에서 호출과 조건 분기를 찾아 고수준 의미를 연결합니다.↗
  3. 문자열은 단서, 결론은 가설실행하지 않고 얻은 단서와 추정한 동작을 구분합니다.↗

02 · 동적 검증과 보고

출처를 모르는 바이너리를 실행하는 과정이 아니라 자신이 빌드한 예제를 검증합니다.

  1. 입력으로 분기 검증하기정적 분석 가설을 실제 실행과 중단점으로 확인합니다.↗
  2. 최적화 비교와 분석 보고서분석 결과가 적용되는 빌드·환경·입력을 명시합니다.↗

03 · 형식과 함수 경계

원시 바이트의 형식과 함수 경계의 약속을 복원합니다.

  1. 바이트 순서와 길이 필드 복원파일의 원시 바이트를 명시적 형식으로 해석하고 길이 가설을 반례로 검증합니다.↗
  2. 호출 규약과 인자·반환값 추적x86-64 System V 환경에서 함수 경계의 레지스터와 소스 인자를 연결합니다.↗

04 · 흐름 복원과 반례 검증

제어·데이터 흐름의 가설을 입력표와 차등 검증으로 좁힙니다.

  1. 반복·건너뛰기·종료 경로 복원루프의 continue와 break가 만드는 서로 다른 실행 경로를 입력표로 복원합니다.↗
  2. 변환 연산과 데이터 의존성 역추적인덱스와 바이트가 결과에 기여하는 과정을 추적하고 역변환 순서를 검증합니다.↗
  3. 참조 구현과 차등 검증기능이 같아 보이는 두 파서의 입력 허용 범위를 비교해 최소 반례를 기록합니다.↗

05 · ELF와 정수 표현 심화

적재 구조·심볼 연결·정수 표현을 나눠 분석합니다.

  1. ELF 섹션과 적재 세그먼트 구분readelf의 두 관점을 비교하고 파일 오프셋·가상주소·메모리 크기를 구분합니다.↗
  2. 재배치와 자체 공유 라이브러리 연결미해결 심볼이 객체 파일·공유 라이브러리·실행 파일에서 어떻게 연결되는지 비교합니다.↗
  3. 부호 해석·확장·비트 필드 복원같은 비트열의 signed/unsigned 해석과 확장 방법을 구분하고 마스크를 검증합니다.↗

06 · 컴파일 변환과 상태 복원

구현 형태의 차이와 입력 순서의 의미를 검증합니다.

  1. switch 복원과 컴파일러의 선택같은 분기 의미가 비교 체인·값 표 등으로 바뀔 수 있음을 입력/출력과 역어셈블로 검증합니다.↗
  2. 입력 순서로 상태기계 복원토큰 집합이 아닌 순서와 현재 상태가 허용 여부를 결정하는 프로그램을 분석합니다.↗
