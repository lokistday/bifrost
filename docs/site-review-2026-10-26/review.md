# Bifrost 전체 검토 · 2026-10-26

## 검토 범위와 결과

최신 로컬 작업본의 9개 분야·49개 모듈·153개 차시, 306개 문제, 162개 도식, 실습 원본과 ZIP 생성기, 페이지 생성·뷰·테스트 구조를 검토했습니다. 공개 홈페이지는 확인 시점에 62개 차시를 표시했습니다. 최근 두 차례의 확장은 로컬 작업본에 있으며, 배포 대기는 앞서 안내한 상태입니다.

사이트 본문·실습 원본·런타임 코드는 수정하지 않았습니다. 재현 실험은 별도 임시 복사본에서 수행했고, 이 폴더에는 검토 기록만 작성했습니다. 실제 브라우저의 전체 화면·키보드 조작을 이번에 새로 검사한 것으로 표현하지 않습니다.

읽기 전용 저작 검증은 통과했습니다. 차시 ID·선행 참조·순환·필수 학습 항목·정답 인덱스·도식의 전체 포함 여부에 문제가 없었습니다. 대표적인 암호·파일 메타데이터·DNS·TLS 설명과 모형의 제한도 대조했습니다. 검토한 설명에서 핵심 개념을 명백히 잘못 가르친다고 확정할 근거는 찾지 못했습니다. 다만 모든 문장의 사실을 독립적으로 증명했다는 뜻은 아닙니다.

아래에서는 **재현한 문제**와 **학습 개선 제안**을 구분합니다. P1은 우선 수정, P2는 다음 개선, P3는 유지보수 보완입니다.

## 재현한 문제

### R01 · P1 · 변경 실습 이후 초기 예상 결과가 다시 등장함

- 위치: `content/courses/foundation.json:25`, `:59`, `:551`, `:585`; 화면 순서는 `js/learning-view.js:139`.
- 환경 준비 차시는 따라하기 3단계에서 `hello.py`의 이름을 Mina로 바꾸게 합니다. 그 뒤 화면의 「전체 예제 연결하기」를 실행하면 `Hello, Mina`가 나오지만, 아래 예상 결과는 초기 원본의 `Hello, Bifrost`입니다.
- C 포인터 차시도 따라하기에서 `*pointer = 12`로 바꾼 뒤 전체 예제의 예상 결과는 `after=9`입니다. 임시 사본을 실제로 컴파일해 `after=12`를 확인했습니다.
- 계산 자체의 오류가 아니라 **초기 상태·변경 상태를 구분하는 안내의 누락**입니다. 처음부터 순서대로 따르는 학습자는 정상 결과를 실패로 오해할 수 있습니다.
- 수정 방향: 원본과 작업 사본을 처음부터 나누거나, 초기 예상 결과라는 표시와 원본 복구 지점을 명시합니다. 한 차시를 같은 작업 폴더에서 처음부터 끝까지 순서대로 수행하는 검사도 추가합니다.

### R02 · P1 · 실습 ZIP이 생성 폴더의 임의 파일까지 포함함

- 위치: `scripts/build_labs.py:362`, `:383`, `:389`.
- 생성기는 저작 원본을 복사한 뒤 기존 `labs/<분야>` 안의 모든 일반 파일을 해시 목록과 ZIP에 넣습니다. 이전 실행물이나 임시 파일을 제외하는 허용 목록이 없습니다.
- 원본 저장소를 바꾸지 않은 임시 복사본의 `labs/web/REVIEW-STRAY.txt`를 만든 뒤 생성기를 실행했습니다. 이 파일이 `web.zip`과 `SHA256SUMS.txt` 모두에 포함되는 것을 확인했습니다.
- 현재 공개 묶음에 비밀이 들어 있다고 확인한 것은 아닙니다. 재현한 것은 **원본에 없는 파일도 정식 실습 자료로 배포될 수 있는 생성 규칙**입니다.
- 수정 방향: 깨끗한 별도 출력 폴더에서 만들고, 명시적으로 생성·복사한 파일만 묶습니다. 삭제된 원본·남은 바이너리·체크포인트 파일도 함께 점검합니다.

### R03 · P2 · 입력 사본을 잘못 편집했을 때 오류 안내가 일관되지 않음

- 위치: `scripts/lab_sources/cloud/boundary_models.py:78`, `network/protocol_models.py:118`, `crypto/record_crypto.py:106`.
- 세 스크립트에 각각 지원하는 `--input` 옵션으로 `{}`인 임시 JSON을 전달했습니다. 모두 종료 상태 1과 Python Traceback을 보이며 `lease_requests`, `queries`, `password_record`의 KeyError로 끝났습니다.
- 잘못된 입력을 허용한다는 문제는 아닙니다. 학습자가 일부 키를 지웠을 때, 무엇을 고쳐야 하는지 알려 주는 피드백이 부족합니다. 기존 `cloud/review.py`의 INVALID 처리와도 경험이 다릅니다.
- 수정 방향: 문서 형태·필수 필드·타입을 먼저 확인하고, 예상 입력 오류는 필드와 조건을 설명하며 일관된 실패 상태로 종료합니다. 개발 결함까지 삼키지는 않습니다. [Python argparse의 오류 처리 문서](https://docs.python.org/3/library/argparse.html#argparse.ArgumentParser.error)를 참고할 수 있습니다.

## 학습과 사용성 개선 제안

### R04 · P2 · 변경 과제의 학습자용 검사와 구체 답안이 부족함

- 개발용 확장 검사는 `tests/`에 있지만 공개 묶음에는 포함되지 않습니다. 학습자용 `test_*.py`는 Foundation의 `test_data_tools.py`가 확인됐습니다. 다른 실행 스크립트의 자체 검사까지 모두 없다는 뜻은 아닙니다.
- 153개 차시 모두 해설의 접근 방법과 결과 기준은 있으나, 별도 `solution.code`가 있는 차시는 1개입니다. 단순 관찰 과제에는 충분해도 파서 수정·롤백·배치 재개 같은 코딩 과제는 결과를 확인하기 어렵습니다.
- 수정 방향: 어려운 변경 과제부터 입력 표본·정상/거부 기대·실행법이 있는 가벼운 검사기를 제공하고, 필요한 차시에는 수정 코드나 예시 보고서 한 편을 추가합니다. 모든 해설을 코드로 바꾸자는 제안은 아닙니다.

### R05 · P2 · 153개 차시를 찾는 검색과 목표별 경로가 없음

- 분야별 목차와 선행 링크는 있지만 차시 검색·태그 필터·목표별 추천 묶음은 없습니다.
- 「쿠키」, 「로그」, 「키 교체」처럼 여러 분야에 걸친 개념을 찾으려면 목차를 반복해서 열어야 합니다.
- 수정 방향: 제목·목표·핵심어를 검색하는 정적 검색을 먼저 추가하고, 입문·DFIR 관심·레드팀 기초처럼 기존 차시를 연결한 경로를 제공합니다. 계정이나 서버가 필요한 기능은 아닙니다. 현재 과정을 완전한 직무 훈련으로 표현하지는 않습니다.

### R06 · P2 · 차시별 난이도·준비 시간·필수 여부가 없음

- 분야 전체의 난이도 표시는 있지만 153개 차시의 개별 난이도·예상 시간 메타데이터는 없습니다.
- Python 기본 출력, C 디버깅, ELF 동적 링크가 같은 차시 단위로 보여 설치 시간과 학습 부담을 예상하기 어렵습니다.
- 수정 방향: 설치 시간과 학습 시간을 나누고, 기초/응용·필수/선택을 표시합니다. C 구조체·정수 폭·컴파일 단계를 위한 짧은 보충 설명이나 선수 지식 점검도 연결합니다.

### R07 · P2 · 확장된 후반 내용을 포함하는 최종 종합 과제가 필요함

- Network의 종합 설계는 19차시 중 9번째, Cloud의 종합 검토는 17차시 중 7번째에 있습니다. 후속 모듈에서 추가한 재조립·시간 창·Kubernetes·사설 경로·긴급 접근 등을 모두 종합하지는 않습니다.
- 기존 과제가 틀렸다는 뜻은 아닙니다. 현재 목차에서는 중간 종합에 가까워졌습니다.
- 수정 방향: 기존 과제는 중간 종합으로 명확히 하고, 분야 끝에는 여러 자료를 함께 읽어 판단·수정·검증 기록을 제출하는 과제를 둡니다. 정해진 한 모드의 출력 재현과 다른 입력으로 이해를 전이하는 평가를 나눕니다.

### R08 · P2 · 일부 모형에서 실제 도구·자료로 넘어가는 단계가 짧음

- 실제 AES-GCM·Ed25519·GDB·ELF·TLS 표본은 이미 있습니다. 모든 실습이 모형이라는 지적은 아닙니다.
- 다만 Windows 이벤트는 합성 XML, 메모리는 JSON 영역, Kubernetes는 단순 권한 모형입니다. 한계를 잘 밝혔지만 이후 실제 파일·도구와 연결하는 학습은 적습니다.
- 수정 방향: 작은 고정 이벤트 파일·SQLite·PCAP·실제 권한 문서를 읽고 모형과 비교하는 선택 과제를 추가합니다. Windows 이벤트는 실제 파일을 읽고 XML 결과와 대조하는 방식도 가능합니다. [Microsoft wevtutil 문서](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/wevtutil)는 이벤트 파일 질의와 내보내기를 설명합니다. 실제 이용자 자료를 수집하라는 제안은 아닙니다.

### R09 · P2 · 코드 블록마다 실행 위치와 파일명이 더 분명해야 함

- `js/learning-view.js:95`, `:99`는 셸 명령·Python 코드·C 조각·GDB 명령을 공통 코드 상자로 렌더링합니다. 실행 환경 설명은 있지만 블록 자체의 표시는 공통 문구입니다.
- C 조각을 main 안에 넣어야 하는 경우, Python 파일로 저장해야 하는 경우, `(gdb)` 안에서 실행할 경우를 매번 문장에서 찾아야 합니다.
- 수정 방향: 블록별 언어·실행 위치·저장 파일명·같은 세션 필요 여부를 구조화해 표시하고, 실제 복사 가능한 부분과 관찰용 표를 구분합니다.

### R10 · P3 · 수치와 실습 저작 방식의 수동 관리 지점을 줄일 필요가 있음

- 메인의 차시 수·목차·사이트맵은 실제 원본에서 생성하지만 README의 수치와 `assets/og-image.svg:40`의 153개 문구는 수동입니다. 현재 수치는 일치합니다.
- 실습 원본도 기존 자료는 `build_labs.py`의 문자열, 확장 자료는 `scripts/lab_sources/`로 나뉩니다. 생성 JS·HTML을 별도로 저작하는 구조는 아니므로 그 점은 잘 정리되어 있습니다.
- 수정 방향: 실습 원본 위치를 통일하고 수치·버전·배포 묶음 목록을 같은 데이터로 관리합니다. 새 차시를 추가할 때 빠뜨릴 수 있는 수동 단계를 줄이는 유지보수 개선입니다.

## 참고 문서 링크 점검

차시의 227개 URL을 fragment를 제외한 196개 주소로 묶어 HEAD 요청으로 점검했습니다. 190개가 리다이렉트 포함 최종 200을 반환했습니다. GNU의 6개 주소는 시간 초과로 확인하지 못했고, 404/410으로 확정한 링크는 없었습니다. 시간 초과를 깨진 링크로 판정하지 않았습니다. 결과는 `reference-status.json`에 저장했습니다.

HEAD 성공은 링크 본문 전체가 정확하거나 특정 fragment가 존재한다는 증명은 아닙니다. 핵심 문서가 바뀌었을 때 재검토하는 기록과 주기적인 링크 확인은 별도로 유지하는 편이 좋습니다.
