01 / UNDERSTAND

먼저 이해하기

해시는 파일 바이트를 일정 길이 값으로 요약합니다. 같은 SHA-256 값은 두 사본의 일치를 확인하는 데 유용하지만 파일의 출처나 진실성 자체를 증명하지는 않습니다. 비교 기준이 되는 원본 해시를 언제·어디서 얻었는지도 기록해야 합니다.

ZIP을 풀어 원본 폴더를 보관하고 작업 사본을 만듭니다. 파일 복사·열기·수정이 메타데이터에 영향을 줄 수 있으므로 파일 이름·해시·관찰 시각·작업을 남깁니다. 이 입문 실습은 법적 증거 수집 절차의 전체를 대신하지 않습니다.

무결성은 수집한 뒤 내용이 바뀌었는지를 다루는 성질입니다. 원본이 이미 잘못된 자료였을 가능성과 분석 중 바뀐 가능성은 별개입니다. 그래서 해시 값 옆에 자료 출처, 수집 시각, 담당자, 파일 크기, 사용 도구를 적어 비교의 기준을 남깁니다.

보존용 사본과 분석용 사본을 나누고 도구가 만드는 결과를 다른 폴더에 저장합니다. 원본을 읽기 전용으로 다루는 습관은 우발적 덮어쓰기를 줄입니다. 파일 내용은 같아도 이름·경로·수정 시각은 다를 수 있으므로 내용 해시와 메타데이터를 따로 비교합니다.

SHA256SUMS.txt는 함께 받은 파일들이 내려받은 뒤 일치하는지 점검하는 목록입니다. 목록 자체가 공격자에게 바뀌었다면 믿을 기준이 사라집니다. 신뢰할 수 있는 배포 경로나 서명처럼 목록의 출처를 확인하는 절차가 추가로 필요합니다.

자주 헷갈리는 지점

원본을 편집한 뒤 해시를 처음 계산한다.
보존 기준은 분석·수정 전에 기록하고 변경 실험은 사본에서만 합니다.
파일 이름이 달라서 해시도 반드시 달라진다고 생각한다.
여기서 해시하는 것은 파일 내용 바이트입니다. 이름·경로는 별도 메타데이터입니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · 파일 보존 실습 · Python 3 또는 Linux/WSL
sha256sum evidence.txt
cp evidence.txt evidence-work.txt
sha256sum evidence-work.txt

변경 전 예상 결과와 해석

수정 전 두 파일의 SHA-256이 같습니다. 다운로드 자료의 SHA256SUMS.txt와도 비교할 수 있습니다.

이제 단계별로 바꾸고 관찰하기

  1. 보존 기준 만들기

    evidence.txt를 읽기 전에 이름·바이트 크기·SHA-256을 기록합니다. 작업 폴더의 다른 파일을 잘못 검사하지 않도록 파일 경로도 함께 남깁니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 파일 보존 실습 · Python 3 또는 Linux/WSL
    from pathlib import Path
import hashlib
p = Path("evidence.txt")
print(p.name, len(p.read_bytes()))
print(hashlib.sha256(p.read_bytes()).hexdigest())
    관찰할 결과
    파일 이름, 바이트 크기, 64자리 Hex 해시가 나옵니다. 숫자 자체보다 이후 비교에 같은 기준을 쓰는 것이 중요합니다.

  2. 사본의 일치 확인

    바이트를 그대로 복사하고 두 해시를 비교합니다. 텍스트 편집기로 다시 저장하면 인코딩·개행이 바뀔 수 있어 바이트 복사를 사용합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 파일 보존 실습 · Python 3 또는 Linux/WSL
    from pathlib import Path
import hashlib
a = Path("evidence.txt").read_bytes()
Path("evidence-work.txt").write_bytes(a)
print(hashlib.sha256(a).digest() == hashlib.sha256(Path("evidence-work.txt").read_bytes()).digest())
    관찰할 결과
    True

  3. 한 번의 변경만 실험

    작업 사본 끝에 느낌표 한 바이트를 붙여 비교합니다. 원본 해시가 그대로이고 사본만 달라졌는지 확인한 뒤 변경 시각과 작업을 기록합니다.

    Python 부분 코드 · 앞 단계의 변수·객체를 유지한 같은 스크립트 · 파일 보존 실습 · Python 3 또는 Linux/WSL
    p = Path("evidence-work.txt")
p.write_bytes(p.read_bytes() + b"!")
print(hashlib.sha256(a).digest() == hashlib.sha256(p.read_bytes()).digest())
    관찰할 결과
    False. 앞 단계와 같은 Python 세션에서 실행합니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본에만 한 글자를 추가하고 두 해시가 달라지는지 확인하세요. 원본 해시와 작업 이력을 기록합니다.

막혔을 때 힌트 보기

개행 변경도 바이트 변경입니다. 눈에 같아 보여도 다른 해시가 나올 수 있습니다.

과제 해설과 예시 답안 보기
  1. 원본과 사본의 수정 전 해시가 같은지 먼저 확인합니다.
  2. 사본에만 한 바이트를 추가하고 두 파일을 다시 해시합니다.
  3. 보고에는 원본 해시 유지, 사본 해시 변화, 수정 작업·시각을 적고 출처의 진실성은 해시만으로 판단하지 않았다고 명시합니다.

결과를 판단하는 기준

내용 동일성 비교와 작업 이력이 함께 남습니다. 해시가 다르면 바이트가 달라졌다는 결론까지 내릴 수 있고, 변경 원인은 이력과 추가 비교가 필요합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
