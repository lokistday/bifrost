01 / UNDERSTAND

먼저 이해하기

중앙 로그에는 같은 사건이 재전송되어 두 번 들어올 수 있습니다. 반대로 서로 다른 계정에서 같은 event_id를 쓸 수도 있습니다. 실습은 하나의 가상 공급자를 가정하고 account·region·event_id를 함께 써서 동일 사건의 중복을 제거합니다.

세 행 중 training-a의 E1 두 행은 중복이고 training-b의 E1은 다른 사건입니다. event_id만으로 중복 제거하면 두 계정의 사건을 하나로 합쳐 증거를 잃습니다. 실제로는 공급자와 로그 종류별 ID 의미·스키마 버전도 검토합니다.

관리 평면의 구성 변경 기록과 데이터 평면의 객체 읽기는 수집 설정이 다를 수 있습니다. 설정한 범주에 기록이 없으면 활동이 없었는지, 실제 활성화·권한·전달 경로·보존에 문제가 있는지 바로 알 수 없습니다. 수집 설정과 통제된 시험 이벤트를 대조해야 합니다.

unobserved_category는 현재 행에서 보이지 않은 범주일 뿐 로깅 비활성화의 증명도 아닙니다. 이 예제는 서명된 로그 검증·전달 지연·파티션별 누락·실제 CloudTrail 요금과 자원 설정을 다루지 않습니다. 외부 서비스를 실행하지 않고 범위와 증거의 한계를 연습합니다.

자주 헷갈리는 지점

행을 중복 제거하면서 원본도 덮어쓴다.
원본 보존과 분석용 변환 자료를 분리합니다.
관리 로그가 있으면 모든 데이터 접근도 기록된다고 본다.
이벤트 범주별 설정과 전달을 확인합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

event_id만 사용했을 때 몇 사건이 사라지는지 비교하세요. object-read를 확인하려면 설정·통제 시험·전달 파이프라인에서 각각 어떤 근거를 남길지 적습니다.

막혔을 때 힌트 보기

같은 E1도 계정이 다르면 다른 사건입니다. 관측되지 않음과 발생하지 않음을 구분하세요.

과제 해설과 예시 답안 보기
  1. 원본 행 3, 복합 키 사건 2, 단일 키 사건 1을 비교합니다.
  2. 원본을 삭제하지 않고 중복 집계의 기준과 변환 이력을 남깁니다.
  3. object-read는 수집 범주 설정, 허용된 테스트 읽기, 전송·보존·조회 권한을 단계별로 점검하고 미관측 원인을 유보합니다.
