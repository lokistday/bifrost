01 / UNDERSTAND

먼저 이해하기

Infrastructure as Code는 원하는 인프라 상태를 파일로 관리하는 방식입니다. 변경 계획은 현재 상태에서 어떤 자원을 만들고 바꾸고 없앨지 검토하는 자료입니다. 코드 검토와 변경 이력을 남길 수 있지만 코드라는 이유로 안전성이 자동 보장되지는 않습니다.

실습의 세 변경은 관리 접근 범위 확대, 데이터 자원 삭제, 복제 수 증가입니다. 같은 update라도 인터넷 공개와 용량 증가는 영향이 다르고 delete는 데이터를 되살릴 방법을 확인해야 합니다. 변경 전후 값을 읽지 않고 변경 개수만 세면 중요한 위험을 놓칩니다.

삭제·교체에는 백업과 복구 시험, 공개 범위 변경에는 허용된 관리 경로와 거부 반례가 필요합니다. 승인한 계획과 실제 적용할 계획이 같은지도 확인합니다. 계획 뒤에 상태가 바뀌는 drift와 별도 수동 변경은 추가 조사 대상입니다.

operations.json은 Terraform이나 공급자 API의 실제 계획 형식이 아닌 작은 교육 표입니다. 스크립트는 세 종류의 검토 표시만 내며 자원을 만들거나 적용하지 않습니다. CHANGE_REVIEW도 안전 판정이 아니고 비용·의존성·서비스 영향에 대한 사람의 검토가 남습니다.

자주 헷갈리는 지점

변경 개수가 적으면 영향도 작다고 본다.
한 번의 공개 확대나 삭제도 큰 영향을 줄 수 있어 전후 상태를 검토합니다.
코드 롤백으로 데이터 손실도 자동 복구된다.
상태·데이터·외부 효과의 복구 절차를 따로 검증합니다.
