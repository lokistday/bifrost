01 / UNDERSTAND

먼저 이해하기

암호 알고리즘이 올바르게 동작해도 키가 노출되면 보호 목적을 잃을 수 있습니다. 키를 누가 생성·사용·보관·교체·폐기할지 정하고 키 ID와 용도, 보유 데이터의 관계를 기록합니다. 비밀키 값 자체를 로그나 분석 문서에 복사하는 것은 피합니다.

주기적 교체와 침해 대응은 다릅니다. 이 모형은 active 키로 새 암호화와 기존 복호화를 허용하고 retired 키는 기존 데이터 복호화만 허용합니다. retired는 유출을 뜻하지 않으며 새 데이터용 키를 바꿔도 과거 데이터가 저절로 재암호화되지는 않습니다.

compromised는 침해가 의심되거나 확인된 상태입니다. 모형은 정상 경로의 사용을 전부 금지하고 조사·회복 절차를 요구합니다. 실제로는 사건 범위와 데이터 복구·증거 보존에 따라 통제된 예외가 필요할 수 있으므로 이를 자동화된 정상 권한과 구분합니다.

폐기는 남아 있는 데이터·백업의 복구 가능성에도 영향을 줍니다. 누가 어떤 키를 필요로 하는지 확인하고 승인·보존 정책·폐기 증적을 남깁니다. 실습은 상태와 허용 행동의 표일 뿐 실제 키 저장소·KMS·메모리 삭제나 키 파기를 실행하지 않습니다.

자주 헷갈리는 지점

키 ID를 변경하면 기존 데이터도 재암호화됐다고 본다.
키 참조 변경과 실제 데이터 재암호화를 구분합니다.
퇴역 키를 곧바로 파기한다.
보유 데이터·백업 복구와 보존 의무를 먼저 검토합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

K2로 암호화된 과거 백업을 남긴 채 K2를 파기하는 제안의 영향을 적으세요. 주기적 교체와 K1 유출 의심에서 각각 필요한 정상 사용 중지·조사·복구 계획을 비교합니다.

막혔을 때 힌트 보기

새 암호화 중지와 기존 복호화 필요성은 다릅니다. 키를 없애기 전에 데이터·백업과의 관계를 확인하세요.

과제 해설과 예시 답안 보기
  1. K2가 필요한 백업 목록과 보존 기간을 확인합니다.
  2. 퇴역 키는 새 암호화에 쓰지 않되 과거 데이터 복구를 위한 제한된 권한·감사를 검토합니다.
  3. 침해 의심은 단순 교체와 달리 정상 사용 중지, 영향 조사, 관련 자격·데이터 회복과 재암호화 여부를 판단합니다.

결과를 판단하는 기준

키 교체만으로 과거 노출이 취소되지 않으며, 성급한 파기는 복구 가능성을 잃을 수 있습니다. 실제 키 값과 운영 시스템은 변경하지 않습니다.
