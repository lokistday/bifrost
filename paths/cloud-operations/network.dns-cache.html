01 / UNDERSTAND

먼저 이해하기

DNS 응답을 캐시하면 같은 질의마다 권한 서버에 다시 물을 필요가 줄어듭니다. TTL은 그 응답을 재사용할 수 있는 시간이며, 응답을 받은 시각을 기준으로 남은 시간을 계산합니다. 레코드 변경 뒤 모든 캐시가 즉시 같은 값을 보게 되는 것은 아닙니다.

이 모형의 양성 응답은 name·qtype에 연결되고 받은 시각 0에서 TTL30입니다. 시각 29에는 HIT지만 정확히 30에는 MISS입니다. MISS는 원래 이름이 존재하지 않음을 뜻하지 않고 이 자료의 재사용 가능한 항목이 없다는 뜻입니다.

부정 응답도 캐시될 수 있습니다. NXDOMAIN은 해당 이름의 존재 부정, NODATA는 이름은 있지만 요청한 타입의 자료가 없다는 의미로 구분합니다. 이 한 IN 클래스 모형에서 NXDOMAIN은 다른 qtype에도 적용하고 NODATA는 같은 name·qtype에만 적용합니다.

표본의 부정 TTL은 SOA TTL과 SOA MINIMUM 중 작은 값입니다. 받은 시각 10, 두 값 60·20이면 30에 만료됩니다. 실제 DNS의 위임·CNAME·DNSSEC·서버 오류 재시도·오래된 응답 제공은 구현하지 않았으며 실제 리졸버를 만들거나 외부 질의를 보내지 않습니다.

자주 헷갈리는 지점

DNS 변경은 모든 이용자에게 즉시 반영된다고 한다.
기존 캐시의 남은 TTL과 리졸버 동작을 확인합니다.
모든 실패 응답을 NXDOMAIN으로 묶는다.
이름 부재·타입 부재·서버 오류·전달 실패를 분리합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

부정 레코드의 soa_minimum을 5로 바꿔 Q3가 왜 MISS가 되는지 예측하세요. NODATA의 A 결과를 AAAA의 부재로 확대하면 안 되는 이유도 적습니다.

막혔을 때 힌트 보기

새 만료 시각은 받은 시각 10 + min(60,5)=15입니다. NXDOMAIN과 NODATA의 캐시 키를 비교하세요.

과제 해설과 예시 답안 보기
  1. soa_minimum=5의 사본을 --input으로 실행합니다.
  2. 부정 응답 만료가 15이므로 Q3(29)와 Q4(30)가 모두 MISS라고 계산합니다.
  3. NODATA는 name·qtype, NXDOMAIN은 이 클래스의 name에 적용하며 둘 다 만료 시각 뒤에는 재사용하지 않는다고 적습니다.

결과를 판단하는 기준

Q3는 MISS로 바뀝니다. 캐시 미일치·권한 서버의 최신 응답·네트워크 장애는 서로 다른 상태입니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
