01 / UNDERSTAND

먼저 이해하기

HTTP 요청은 하려는 작업과 대상을, 응답은 처리 결과를 담습니다. GET /notes/1은 메서드와 경로이고 Host는 목적 호스트를 나타내는 헤더입니다. 상태 코드는 응답에 들어갑니다. 빈 줄은 헤더와 본문을 구분합니다.

쿠키는 브라우저가 이후 요청에 보내는 값입니다. 세션 식별자를 담을 수 있지만 그 값 자체가 모든 권한을 보장하지는 않습니다. 제공된 예시는 읽기용 가상 요청이며 실제 로그인 기능이 아닙니다. 민감한 쿠키·토큰을 노트에 복사하지 마세요.

요청은 시작 줄의 메서드와 대상으로, 응답은 시작 줄의 상태로 역할을 나눕니다. 헤더는 각 메시지에 대한 추가 정보를 담으며 본문이 항상 있는 것은 아닙니다. 예시의 두 시작 줄은 하나의 메시지가 아니라 요청 한 개와 응답 한 개를 이어 보여 준 것입니다.

개발자 도구는 HTTP/2·HTTP/3 정보를 사람이 읽기 쉽게 정리하므로 예시 HTTP/1.1 텍스트와 화면 모양이 다를 수 있습니다. 일반 문서 요청의 GET은 읽기 관찰에 사용하고, 주소·상태·Content-Type·응답 본문을 연결해서 어떤 자료를 받았는지 확인합니다.

자주 헷갈리는 지점

Network의 모든 행을 자신이 연 문서 요청으로 생각한다.
이미지·스타일·스크립트 요청과 문서 요청을 Type 및 URL로 구분합니다.
응답 헤더가 요청 때도 그대로 전송되었다고 생각한다.
Request Headers와 Response Headers를 분리해서 읽습니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

관찰 절차·자료 예시 · 그대로 셸에 붙여 넣지 말고 본문 안내를 따라 확인
GET /notes/1 HTTP/1.1
Host: localhost

HTTP/1.1 200 OK
Content-Type: text/plain

hello

변경 전 예상 결과와 해석

요청 메서드 GET, 경로 /notes/1, 응답 상태 200, 본문 hello를 각각 찾습니다.

이제 단계별로 바꾸고 관찰하기

  1. 요청과 응답을 두 칸으로 나누기

    GET으로 시작하는 부분을 요청, HTTP/1.1 200으로 시작하는 부분을 응답으로 구분합니다. Host는 요청 헤더이고 Content-Type은 이 예시에서 응답 헤더입니다.

  2. 빈 줄 뒤의 본문 찾기

    응답 헤더 뒤 빈 줄 다음의 hello가 본문입니다. HTML, JSON, 이미지 등 응답 종류에 따라 본문 표현이 달라집니다.

    관찰 절차·자료 예시 · 그대로 셸에 붙여 넣지 말고 본문 안내를 따라 확인
    HTTP/1.1 200 OK
Content-Type: text/plain

hello
    관찰할 결과
    상태=200, 자료형=text/plain, 본문=hello

  3. 실제 문서 요청과 대조하기

    Network에서 유형이 document인 요청 하나를 선택합니다. Request URL, Request Method, Status Code, Response Headers와 Response 탭을 각각 기록합니다. 쿠키와 Authorization 값은 기록에서 제외합니다.

    관찰 절차·자료 예시 · 그대로 셸에 붙여 넣지 말고 본문 안내를 따라 확인
    기록 예: GET /bifrost/ → 관찰한 상태 코드
응답 Content-Type → 관찰한 값
본문 → HTML 문서인지 확인
    관찰할 결과
    캐시 여부와 HTTP 버전은 관찰한 그대로 적습니다. 예시와 같은 200만 정답인 것은 아닙니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

브라우저 개발자 도구 Network에서 이 사이트 문서 요청 하나를 골라 네 요소를 기록하세요. 캐시나 HTTP 버전에 따른 표기 차이도 적습니다.

막혔을 때 힌트 보기

재요청이 캐시에서 처리되면 상태와 전달 크기가 다를 수 있습니다. 관찰한 값과 의미를 분리합니다.

과제 해설과 예시 답안 보기
  1. 공개 페이지의 문서 요청 한 개를 선택해 메서드·경로·상태·응답 자료형을 기록합니다.
  2. 본문이 사이트 HTML인지 Response 탭에서 확인하고 헤더와 본문을 다른 칸에 둡니다.
  3. 캐시에서 받은 결과나 재검증 응답을 관찰했다면 그 상태와 전달 크기를 그대로 적습니다. 특정 상태가 나오도록 도구 설정을 무작정 바꾸지 않습니다.

결과를 판단하는 기준

정답 기록은 실제 관찰값에 따라 달라집니다. 네 요소가 올바른 요청·응답 위치에 연결되고 민감한 값이 없어야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

정답과 이유 읽기

정답: 실제 버전과 도구가 정리한 메서드·상태·헤더를 기록한다.

HTTP의 핵심 의미와 전송 표현을 구분합니다. 이 차시 예시는 읽기 쉬운 HTTP/1.1 표기이며 다른 버전 관찰도 유효합니다.

내 결과물 확인하기

  • 요청과 응답에서 헤더를 각각 찾았다.
  • 쿠키 값 없이 요청 관찰 기록을 남겼다.
