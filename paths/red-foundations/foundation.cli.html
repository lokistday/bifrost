01 / UNDERSTAND

먼저 이해하기

명령행 인터페이스는 다른 사람이 파일을 열어 소스를 고치지 않고 같은 계산을 실행하도록 만드는 약속입니다. 위치 인자 path는 입력 파일, --minimum은 선택 기준이라는 의미를 부여합니다. 코드에 숨은 숫자보다 실행 기록에 인자가 드러나야 재현하기 쉽습니다.

argparse는 인자 분리·도움말·기본 자료형 변환을 담당합니다. type=int는 abc를 거부하지만 -1이나 2000이 업무상 허용되는지는 알지 못합니다. data_tools는 parse_minutes를 다시 호출해 0~1440 범위라는 계약도 확인합니다.

요약 도구의 선택 조건은 minutes >= minimum입니다. 정확히 경계에 있는 값이 포함되는지가 요구 사항입니다. 30분 입력에서 minimum=30과 31을 비교하면 참·거짓의 차이를 관찰할 수 있으며 이 한 쌍이 다음 테스트 차시의 기준이 됩니다.

기본 입력 파일은 스크립트 옆 record.json이지만 직접 준 상대 경로는 현재 작업 폴더를 기준으로 해석됩니다. 무엇을 읽었는지 기록하려면 실행 위치와 전달한 파일을 함께 적습니다. 이 구분을 하지 않으면 다른 파일을 읽고 같은 결과라고 착각할 수 있습니다.

자동화에는 명확한 오류 계약도 필요합니다. 없는 파일과 잘못된 데이터는 진단과 상태 2로 끝나고, 알 수 없는 옵션은 argparse가 거부합니다. allow_abbrev=False는 긴 옵션의 뜻이 축약 입력에 따라 달라지는 일을 줄이지만 입력 내용 검증을 대신하지 않습니다.

자주 헷갈리는 지점

argparse의 type=int가 모든 업무 입력을 검증해 준다고 믿는다.
형식 변환 뒤 허용 범위와 의미 검증을 별도로 합니다.
스크립트 경로와 입력 파일의 상대 경로가 언제나 같은 기준이라고 생각한다.
기본 입력과 직접 지정한 입력의 해석 기준을 확인하고 실행 위치를 기록합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

--minimum 0, 30, 31, 1440, 1441을 각각 실행하고 결과를 표로 만드세요. 없는 파일을 지정했을 때도 성공 요약이 출력되지 않는지 확인하세요.

막혔을 때 힌트 보기

0~1440은 옵션의 유효 범위이고, 선택 여부는 입력의 30분과 비교해서 정해집니다. 1440도 유효하지만 선택은 False입니다.

과제 해설과 예시 답안 보기
  1. 0과 30은 selected=True, 31과 1440은 selected=False가 되어야 합니다. 입력값은 계속 30이고 옵션의 경계만 달라집니다.
  2. 1441은 유효한 정수 표기이지만 계약 범위를 벗어나 INVALID·상태 2로 끝납니다. abc의 구문 변환 오류와 원인이 다릅니다.
  3. missing-record.json을 지정한 명령은 OSError 계열 진단·상태 2를 내고 learner 요약을 쓰지 않는다고 기록합니다.

결과를 판단하는 기준

정상 범위 네 사례와 범위 초과·없는 파일의 실패를 구분한 실행 표를 만듭니다. 오류 메시지의 운영체제별 파일 경로 문구는 고정값으로 비교하지 않습니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

05 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. 30분 자료에서 --minimum 30은 True, 31은 False입니다. 이 쌍이 확인하는 것은?

정답과 이유 읽기

정답: 최소값이 같은 경우 포함하는 경계 조건이다.

>=와 >의 차이는 정확히 경계에서 드러납니다. 입력 자료를 고정하고 기준값만 바꿨기 때문에 조건 해석을 좁힐 수 있습니다.

2. --minimum 1441을 type=int가 읽었습니다. 다음에 필요한 것은?

정답과 이유 읽기

정답: 0~1440이라는 업무 범위를 따로 검사한다.
