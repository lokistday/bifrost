01 / UNDERSTAND

먼저 이해하기

이 예제의 local과 values는 함수 블록의 자동 저장 기간을 갖고 heap은 malloc이 확보한 영역을 가리킵니다. 보통 앞쪽은 스택, 동적 영역은 힙으로 구현하지만 실제 위치와 최적화는 구현에 달려 있습니다.

포인터 변수의 수명과 가리키는 메모리의 수명은 다릅니다. free 이후에는 그 영역을 읽거나 쓰면 안 됩니다. heap = NULL은 이 변수의 실수를 줄이지만 같은 영역을 가리키던 다른 포인터까지 무효화하지는 않습니다.

객체의 수명, 이름을 쓸 수 있는 범위, 포인터가 담은 주소를 분리합니다. main의 지역 포인터 heap은 함수 안에서 사용하는 변수이고 malloc으로 확보한 정수 영역은 free까지 사용할 수 있습니다. 이름이 heap이라는 사실이 변수 자체를 동적 할당 영역으로 만드는 것은 아닙니다.

malloc 실패는 NULL로 확인한 뒤 사용을 중단해야 합니다. 성공한 경로에서는 *heap = 9로 내용을 초기화한 후 읽고, 마지막 사용 뒤 free합니다. malloc이 준 영역의 초기 내용은 9로 자동 설정되는 것이 아니므로 쓰기 전 읽지 않습니다.

동적 메모리의 소유자는 해제 책임을 가진 코드를 뜻합니다. 같은 영역을 여러 포인터가 가리킬 수 있어 두 번 해제하거나 한 별칭을 남겨 두는 실수가 생깁니다. 지금은 소유자 하나와 해제 시점을 명확히 표시하는 것부터 연습합니다.

자주 헷갈리는 지점

포인터 변수의 이름 heap만 보고 저장 위치와 수명을 결정한다.
언어의 저장 기간과 실제 할당·해제 경로를 근거로 대상을 구분합니다.
free 이후 읽어도 한 번은 값이 남았으므로 안전하다고 판단한다.
값이 우연히 보이는 것과 객체 접근의 유효성은 다릅니다. 해제 후 접근하지 않습니다.

이제 단계별로 바꾸고 관찰하기

  1. 포인터 변수와 대상 영역을 별도 상자로 그리기

    local과 values는 main의 지역 객체로, heap은 포인터 변수로 그립니다. malloc이 성공하면 heap에서 별도의 정수 공간으로 화살표를 잇습니다.

  2. 성공·실패 경로 나누기

    if (!heap) return 1은 할당 실패 시 사용을 건너뛰는 경로입니다. 성공 시에만 *heap = 9가 실행됩니다. 출력까지 도달한 경우와 실패로 종료한 경우를 도식에서 나눕니다.

    C 소스 조각 · 해당 함수·파일에 넣고 다시 컴파일 · Ubuntu/WSL · memory.c와 텍스트 편집기
    int *heap = malloc(sizeof *heap);
if (!heap) return 1;
*heap = 9;
    관찰할 결과
    성공 경로에서는 초기화된 값 9를 읽습니다. 실패 경로는 역참조하지 않고 종료합니다.

  3. 마지막 사용과 해제 표시하기

    printf로 읽은 뒤 free(heap)에서 동적 영역 수명을 종료합니다. heap = NULL은 이 변수에 남은 주소를 지우는 동작입니다. 별칭이 있었다면 그 별칭은 자동 변경되지 않는다는 점을 점선으로 표시합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

메모리 확보 → NULL 검사 → 사용 → free → 재사용 금지 흐름도를 그리세요. 함수가 지역 변수의 주소를 반환하면 어떤 문제가 생길지도 설명합니다.

막혔을 때 힌트 보기

함수가 끝나는 시점과 free 호출 시점을 각각 표시하면 수명을 비교하기 쉽습니다.

과제 해설과 예시 답안 보기
  1. 할당 → 실패 검사 → 초기화 → 사용 → free → 해당 영역 접근 금지로 도식화합니다.
  2. 함수 지역 변수 주소를 반환하는 경우에는 함수가 끝나면서 대상의 수명이 끝나므로 반환한 포인터로 유효한 객체를 계속 읽을 수 없다고 설명합니다.
  3. NULL 대입은 현재 변수에만 적용됩니다. 다른 별칭의 무효화나 이중 해제 방지를 자동으로 해결한다고 쓰지 않습니다.

결과를 판단하는 기준

지역 포인터 변수와 동적 영역이 따로 그려지고 NULL 실패 경로·free 수명 종료·별칭 한계가 모두 표시되어야 합니다.

05 / VERIFY

이 정도면 다음으로

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. free(heap) 다음 heap = NULL을 했습니다. 같은 주소를 저장한 alias도 자동 NULL이 되나요?

정답과 이유 읽기

정답: 아니다. heap 변수만 바뀌며 alias의 값은 자동 변경되지 않는다.

포인터 변수는 각각의 저장 공간입니다. 해제된 대상을 가리키는 별칭을 통한 접근을 별도로 막아야 합니다.

2. malloc이 성공한 직후 *heap을 읽으면 이 예제의 9가 이미 들어 있을까요?

정답과 이유 읽기

정답: 아니다. *heap = 9 대입을 실행한 뒤에야 그 초기값을 기대할 수 있다.

malloc은 요청한 공간을 확보하지만 그 내용을 예제의 값으로 초기화하지 않습니다. 사용 전 초기화를 구분해야 합니다.
