01 / UNDERSTAND

먼저 이해하기

중단점은 지정한 위치에 도달하면 실행을 멈춥니다. next는 현재 소스 줄을 실행하고 다음 줄로 가며 step은 함수 안으로 들어갈 수 있습니다. print는 현재 멈춘 프레임에서 변수를 평가합니다.

main 시작 시점에는 아직 초기화되지 않은 변수도 있습니다. 값을 읽기 전에 해당 대입 줄이 실행됐는지 확인하세요. 주소는 ASLR 등에 따라 바뀌므로 같은 주소 숫자가 나온다는 것을 완료 기준으로 삼지 않습니다.

GDB에서 멈춘 줄은 보통 다음에 실행할 위치입니다. 줄이 화면에 보인다는 이유만으로 그 줄의 대입이 이미 수행됐다고 생각하면 초기화 전 값을 읽을 수 있습니다. list로 소스를 보고 next 실행 전후 위치와 값을 묶어 기록합니다.

print heap은 포인터 값이고 print *heap은 그 위치의 정수입니다. malloc 성공과 *heap 초기화가 끝난 시점을 먼저 확인해야 대상 내용을 유효하게 해석할 수 있습니다. 현재 스택 프레임에서 보이는 변수라는 조건도 필요합니다.

디버거는 전체 프로그램을 증명하는 도구가 아니라 멈춘 실행의 상태를 관찰하는 도구입니다. 보고서에는 사용한 입력·빌드 옵션·중단 위치·실행한 스텝·관찰값을 남깁니다. 주소 숫자가 달라도 같은 대입과 값 관계를 재현할 수 있습니다.

자주 헷갈리는 지점

Bash에 break main을 입력하거나 GDB 안에 gcc 명령을 그대로 입력한다.
각 명령의 실행 주체를 프롬프트로 구분합니다.
해제 후 *heap을 찍어 값이 보이는지로 수명을 판단한다.
수명은 프로그램의 계약으로 판단합니다. 유효한 사용 구간에서만 대상 값을 관찰합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

혼합 절차 · 먼저 터미널에서 빌드·gdb 실행 → 주석 아래는 GDB 콘솔에 입력
gcc -g -O0 memory.c -o memory
gdb ./memory
# 아래는 GDB 프롬프트에서
break main
run
list
next
print local
continue
quit

변경 전 예상 결과와 해석

local = 7 대입 줄을 실행한 뒤 print local은 7을 보여 줍니다. main 첫 줄에서의 next 횟수는 컴파일러에 따라 다릅니다.

이제 단계별로 바꾸고 관찰하기

  1. Bash와 GDB 명령 분리하기

    먼저 Bash에서 빌드하고 GDB를 시작합니다. 이후 break와 run은 (gdb) 프롬프트에서 입력합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · GDB · -g -O0 빌드
    gcc -Wall -Wextra -g -O0 memory.c -o memory
gdb ./memory
    관찰할 결과
    GDB가 memory의 심볼 정보를 읽고 프롬프트를 표시합니다.

  2. 초기화 실행 여부를 먼저 확인하기

    break main, run, list 순서로 입력합니다. 현재 위치를 보고 int local = 7 대입을 실제로 실행할 때까지 next로 진행한 뒤 print local을 합니다. 필요한 next 횟수는 줄 매핑에 따라 다를 수 있습니다.

    GDB 콘솔 명령 · 대상 실행 파일을 연 같은 디버깅 세션
    break main
run
list
next
print local
    관찰할 결과
    local 초기화가 끝난 위치에서 관찰값은 7입니다.

  3. 포인터와 대상 값을 함께 보기

    list와 next로 malloc 검사와 *heap = 9가 끝난 위치까지 진행합니다. 그때 print heap과 print *heap을 비교하고 continue로 정상 종료시킵니다.

    GDB 콘솔 명령 · 대상 실행 파일을 연 같은 디버깅 세션
    print heap
print *heap
continue
quit
    관찰할 결과
    유효한 주소와 역참조 값 9를 관찰하며 정상 출력 뒤 프로그램이 종료합니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

local 초기화 전과 후에 멈춘 위치를 비교하고 heap에 값을 넣은 뒤 print *heap을 확인하세요.

막혔을 때 힌트 보기

No symbol 오류면 -g 옵션과 현재 프레임을 확인합니다. list로 현재 줄을 먼저 찾으세요.

과제 해설과 예시 답안 보기
  1. local 초기화 전에는 줄 위치만 기록하고 초기화되지 않은 값에 의미를 부여하지 않습니다. 대입 후 print local = 7을 확인합니다.
  2. malloc 성공 검사와 초기화 뒤 heap 주소와 *heap=9를 별도로 적습니다.
  3. 마지막에 continue로 정상 종료하고, -g -O0 빌드와 사용한 GDB 명령 순서를 노트에 남깁니다.

결과를 판단하는 기준

소스 위치·초기화 순서·local=7·*heap=9·정상 종료가 연결된 기록이어야 합니다. 포인터 주소의 고정값은 요구하지 않습니다.

05 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. GDB가 int local = 7 줄을 가리키고 있습니다. 바로 print local의 값이 항상 7이라고 믿어도 될까요?

정답과 이유 읽기

정답: 아니다. 현재 줄 실행 전인지 확인하고 대입 후 값을 읽어야 한다.

멈춘 위치는 다음 실행할 줄일 수 있습니다. 대입이 실제로 수행됐는지 next 전후 소스 위치로 확인합니다.

2. 함수 안으로 들어가지 않고 현재 소스 줄의 실행을 지나 다음 줄로 가려면 기본적으로 어떤 명령을 쓰나요?

정답과 이유 읽기

정답: next

next는 현재 프레임의 다음 소스 줄로 진행하며 줄 안의 호출은 지나갑니다. step은 디버깅 정보가 있는 호출 함수 안으로 들어갈 수 있습니다.

  • 중단 후 계속 실행해 정상 종료했다.
