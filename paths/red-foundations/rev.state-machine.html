01 / UNDERSTAND

먼저 이해하기

입력 값이 각각 유효해도 그 순서가 틀리면 거부될 수 있습니다. state_machine.py의 장난감 규칙은 CLOSED에서 HELLO로 READY에 들어가고 DATA를 0회 이상 처리한 뒤 END로 DONE이 됩니다. 실제 소켓·TLS·인증 프로토콜은 구현하지 않습니다.

같은 DATA도 READY에서는 허용되고 CLOSED나 DONE에서는 거부됩니다. 따라서 단순히 허용 토큰 목록만 복원하면 프로그램 의미를 놓칩니다. 현재 상태와 입력을 행·열로 둔 전이표를 만들고 거부 전이도 명시합니다.

HELLO END는 DATA가 없어도 정상 종료되지만 HELLO DATA는 마지막 상태가 READY라 불완전합니다. 토큰별 검사 통과와 전체 시퀀스 완료는 다른 조건입니다. END 뒤 DATA를 붙인 입력은 이미 끝난 세션에 추가 자료를 허용하는지 시험하는 반례입니다.

이 모형은 고정된 작은 문자열만 처리하고 시간 제한·재전송·동시성·메시지 길이·네트워크 오류를 모델링하지 않습니다. 전이표가 맞는다는 사실을 실제 서비스의 안전성으로 일반화하지 말고, 분석한 입력 집합과 포함하지 않은 상태를 보고서에 적습니다.

자주 헷갈리는 지점

허용 문자열 목록만 쓰고 상태를 생략한다.
현재 상태·입력·다음 상태와 거부 전이를 함께 복원합니다.
이 장난감 전이표를 실제 네트워크 보안 구현이라고 부른다.
시간·오류·재전송·동시성과 보안 속성은 별도 설계입니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

DATA END, HELLO DATA, HELLO END DATA를 각각 실행해 잘못된 시작·미완료·종료 후 입력을 구분하세요. 전이표에 거부 경로를 추가하세요.

막혔을 때 힌트 보기

마지막 토큰이 허용된 것과 최종 상태가 DONE인 것은 다릅니다.

과제 해설과 예시 답안 보기
  1. CLOSED+HELLO→READY, READY+DATA→READY, READY+END→DONE 세 허용 전이를 적습니다.
  2. 나머지 조합은 거부이며 최종 READY/CLOSED도 미완료로 거부합니다.
  3. 세 반례를 시작 위반·완료 조건 누락·종료 뒤 추가 입력으로 분류합니다.
