01 / UNDERSTAND

먼저 이해하기

호스트 트리아지는 제한된 시간에 추가 조사가 필요한 단서를 좁히는 과정입니다. 이름이 낯설다는 이유만으로 악성으로 분류하지 않습니다. 합성 snapshot.json의 부모 관계·사용자·시작 시각·현재 연결을 함께 보며 확인된 사실과 의심 이유를 구분합니다.

이 표본에서 PID 300 helper의 부모는 PID 200 viewer이고 C01 연결은 PID 300을 참조합니다. 따라서 viewer→helper→203.0.113.44:443이라는 관찰 연결을 만들 수 있습니다. 주소는 문서용 예약 대역이며 실제 위험 인프라가 아닙니다. 연결 유무만으로 데이터 유출을 확정하지 않습니다.

PID는 영구 신원이 아닙니다. 프로세스가 종료되면 재사용될 수 있고 서로 다른 시각에 모은 표를 PID만으로 붙이면 잘못된 연결을 만들 수 있습니다. 이 예제는 하나의 합성 스냅샷 안에서만 조인합니다. 실제 자료는 호스트·수집시각·프로세스 시작시각이나 고유 이벤트 식별자를 함께 검토합니다.

C03의 PID 999는 프로세스 표에 없습니다. 수집 간격·권한 부족·종료·누락 등의 가능성을 두고 UNKNOWN으로 남깁니다. 이 명령은 실제 메모리나 프로세스를 읽지 않으며 프로그램 이름, 서명, 실행 경로, 명령줄, 해시와 역사적 이벤트는 별도 증거가 필요합니다.

자주 헷갈리는 지점

프로세스 이름이 helper면 정상이라고 결론 낸다.
이름은 바뀔 수 있습니다. 경로·서명·동작·원인 관계를 추가 확인합니다.
외부 443 연결이 보이면 데이터 유출을 확정한다.
암호화 연결의 존재와 실제 내용·목적은 별도 증거입니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

snapshot.json의 사본에서 C01의 PID를 999로 바꾸고, 어떤 연결 근거를 잃는지 쓰세요. helper를 조사하려면 추가로 필요한 근거 세 가지도 적으세요.

막혔을 때 힌트 보기

UNKNOWN은 악성이라는 뜻도 정상이라는 뜻도 아닙니다. 표에 존재하지 않는 연결 키라는 뜻입니다.

과제 해설과 예시 답안 보기
  1. C01의 PID를 999로 바꾸면 helper와의 조인이 사라지므로 원래 이름 관계를 그대로 복사하지 않습니다.
  2. 추가 근거로 실행 파일 경로·해시/서명, 명령줄·부모 시작 이벤트, 연결 전후 패킷/전송량을 요청합니다.
  3. PID 재사용과 수집 시각 차이 때문에 다른 시점의 프로세스 표를 바로 붙이지 않는다고 기록합니다.

결과를 판단하는 기준

관찰 가능한 연결 1건, UNKNOWN의 의미, 추가 증거 요청 3가지와 조사 우선순위 이유가 있어야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
