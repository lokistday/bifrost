01 / UNDERSTAND

먼저 이해하기

DFIR은 증거 분석과 사고 대응을 연결하지만 분석자가 관찰한 모든 의심을 즉시 확정 사고로 바꾸지는 않습니다. response.json에서 unexpected-child는 확인된 관찰이고 external-transfer는 미확인입니다. confirmed-hosts는 확인된 관찰의 호스트 집합이며 전체 침해 범위를 증명하는 목록이 아닙니다.

격리·종료·삭제는 피해를 줄일 수 있지만 업무 중단과 증거 손실도 만들 수 있습니다. 이 모형은 승인, 영향 검토, 증거 보존이 모두 참인 조치를 READY-FOR-REVIEW로 표시합니다. 이 표시는 검토 준비 상태일 뿐 실제 실행 승인이나 특정 조치의 보안 적합성 인증이 아닙니다.

전원 종료는 프로세스 실행을 멈추지만 휘발성 근거를 잃고, 네트워크 격리는 접속을 줄여도 이미 저장된 자료와 내부 실행을 모두 제거하지 않습니다. 조치마다 의도·범위·부작용·되돌리기 조건을 적고 조직의 담당자와 절차에 따라 판단합니다. 이 실습은 어떤 시스템에도 조치를 적용하지 않습니다.

복구는 서비스를 다시 켜는 것만이 아닙니다. 원인 수정과 정상 기능, 허용/거부 정책, 모니터링, 재발 징후, 복구 후 증거 보존을 확인하고 완료 기준과 관찰 기간을 정합니다. NIST SP 800-61r3의 대응·복구와 개선 관점을 참고하되 이 작은 모형이 전체 대응 절차를 대체하지 않습니다.

자주 헷갈리는 지점

확인 호스트 한 대가 전체 침해 범위라고 생각한다.
확인된 범위와 아직 조사하지 않은 범위를 구분합니다.
격리와 재부팅을 하면 증거 분석이 끝났다고 적는다.
휘발성 손실·원인 제거·복구 후 관찰과 교훈을 별도로 확인합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

response.json 사본에서 isolate-network의 authorized를 false로 바꾸고 결과를 비교하세요. 이후 격리 조치의 업무 영향·되돌리기 조건과 복구 확인 항목 세 가지를 작성하세요.

막혔을 때 힌트 보기

READY-FOR-REVIEW는 실행해도 된다는 뜻이 아닙니다. 미확인 전송 가설을 확인된 피해로 바꾸지 마세요.

과제 해설과 예시 답안 보기
  1. 승인이 false이면 다른 두 조건이 참이어도 격리는 HOLD입니다.
  2. 업무 영향은 원격 작업 중단, 되돌리기는 승인된 재연결과 재격리 가능 경로로 적습니다.
  3. 복구 확인으로 정상 접근/거부 정책, 원인 구성 수정의 회귀 검사, 정한 기간의 재발 징후와 로그 수집을 명시합니다.
