01 / UNDERSTAND

먼저 이해하기

설정값은 기본값·파일·환경 변수·명령행처럼 여러 곳에서 들어올 수 있습니다. 어느 값이 이기는지 정하지 않으면 같은 코드가 다른 터미널에서 다르게 동작합니다. 이번 계약은 기본값 < 파일 < 환경 < 명령행이며 결과와 출처를 함께 반환합니다.

환경 변수의 값은 보통 문자열입니다. "20"을 숫자로 바꾸는 과정과 1~60이라는 허용 범위 검사는 별도입니다. 빈 문자열을 키 누락으로 취급하면 잘못 지정한 설정이 조용히 기본값으로 바뀔 수 있어, 이번 도구는 빈 환경값도 오류로 구분합니다.

resolve_timeout은 입력 계층을 순서대로 검증합니다. 낮은 우선순위의 파일 값이 잘못됐더라도 높은 CLI 값으로 숨기지 않는 엄격한 계약입니다. 다른 정책도 가능하지만 어떤 오류를 숨기는지 문서화하고 같은 방식으로 테스트해야 합니다.

환경 전체를 기록하면 접속 비밀이나 개인 경로가 함께 노출될 수 있습니다. 필요한 BIFROST_TIMEOUT 키만 읽고, 선택한 비밀이 아닌 값과 출처만 출력합니다. 재현에는 모든 환경을 덤프하는 것보다 사용한 입력 계약과 우선순위가 중요합니다.

config 모드는 재현을 위해 실제 PC 환경 대신 명시적으로 만든 dict를 넘깁니다. 실제 도구에 연결할 때에는 필요한 환경값을 골라 전달하고 변경된 환경이 어느 프로세스에 반영되는지도 확인해야 합니다. 환경 변수는 비밀 보관소나 사용자 권한 검사를 대신하지 않습니다.

자주 헷갈리는 지점

env.get(key) or default로 빈 설정과 누락을 같은 의미로 처리한다.
빈 문자열을 오류로 볼지 계약을 정하고 키 존재 여부와 값 검증을 분리합니다.
재현을 위해 환경 변수 전체를 로그에 남긴다.
필요한 비밀 아닌 설정과 출처만 기록합니다. 전체 덤프에는 비밀이 포함될 수 있습니다.

    명시적 file/env dict를 사용해 최종값과 출처를 확인합니다. cli=None은 미지정이며 0은 명시했지만 범위 밖인 값입니다.

  3. 미지정과 빈 값을 다르게 보기

    키가 없는 dict는 기본값을 유지합니다. 키가 있고 값이 빈 문자열이면 같은 결과로 처리하지 않습니다. 소스의 in 검사와 timeout_value 호출을 연결합니다.

    python3 -c "from workflow import resolve_timeout; print(resolve_timeout(environ={}))"
    관찰할 결과
    (5, 'default'). 빈 값의 거부는 config 모드 마지막 줄 empty_environment=INVALID로 확인합니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

CLI를 60과 61로 각각 지정하고 경계를 비교하세요. 파일 timeout=-1, CLI=30 조합이 왜 거부되는지 계약을 읽고 설명하세요. 선택한 값뿐 아니라 출처도 결과 표에 남기세요.

막혔을 때 힌트 보기

이 함수는 모든 명시 계층을 검증합니다. 최종값이 유효하다는 이유로 앞선 잘못된 파일 설정을 무시하지 않습니다.

과제 해설과 예시 답안 보기
  1. resolve_timeout(cli=60)은 (60,"cli"), cli=61은 ValueError입니다. 0과 불리언 True도 유효한 초 단위 정수로 취급하지 않습니다.
  2. resolve_timeout({"timeout":-1},None,30)은 파일 단계에서 거부됩니다. CLI가 덮어쓰더라도 오류를 숨기지 않는 정책임을 적습니다.
  3. 명령과 선택값·출처·실패 원인을 기록하고, 실제 환경 전체나 비밀은 기록하지 않습니다. 우선순위 정책을 바꾸면 검사도 명시적으로 바꿔야 합니다.

결과를 판단하는 기준

60은 cli 출처로 허용, 61과 잘못된 하위 계층은 ValueError입니다. 미지정·빈 값·범위 오류가 구분되어야 합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
