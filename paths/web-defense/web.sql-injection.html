01 / UNDERSTAND

먼저 이해하기

문자열 연결로 SQL을 만들면 따옴표나 연산자가 쿼리 구조를 바꿀 수 있습니다. demo.py는 가상 사용자 두 행을 만든 후 같은 입력을 연결 쿼리와 매개변수 쿼리에 넣습니다. 외부 DB나 서비스에 접속하지 않습니다.

바인딩은 입력에서 나쁜 글자를 지우는 방식이 아니라 문법과 데이터를 분리하는 방식입니다. 정상 이름, 존재하지 않는 이름, 따옴표를 포함한 이름을 함께 검증해야 수정이 정상 기능을 망가뜨리지 않았는지도 알 수 있습니다.

제공 입력은 작은따옴표로 값의 경계를 닫고 OR 1=1 조건을 덧붙이며 --로 남은 부분을 주석으로 만듭니다. 연결 방식에서는 사용자가 준 문자가 SQL 구조 일부로 해석됩니다. 바인딩 방식에서는 동일한 문자 전체가 이름 한 개의 값이므로 일치하는 사용자가 없어 0행입니다.

따옴표가 있다는 이유만으로 악의적인 데이터는 아닙니다. O'Brien처럼 정상 이름에도 들어갈 수 있습니다. 나쁜 글자 삭제는 정상 데이터를 손상시키기 쉬우며 DB·문맥에 따른 해석 차이를 모두 해결하지 못합니다. 문법과 값을 분리하고 정상값도 유지되는지 확인합니다.

현재 두 사용자는 alice와 bob뿐입니다. O'Brien 조회가 0행이라는 사실은 특수문자가 차단됐다는 뜻이 아니라 그 이름이 없다는 뜻입니다. 추가 실험으로 그 이름의 행을 바인딩 INSERT한 뒤 1행 조회를 확인하면 저장과 조회가 모두 데이터로 처리되는지 검증할 수 있습니다.

자주 헷갈리는 지점

따옴표 포함 입력을 전부 공격이라고 보고 삭제한다.
정상 데이터도 같은 문자를 포함합니다. 문법·값 분리와 정상 동작 검증을 유지합니다.
바인딩만 있으면 인증과 인가도 해결된다고 생각한다.
바인딩은 SQL 문법 경계를 보호합니다. 누가 어떤 자료를 읽는지는 별도 정책입니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

demo.py를 복사해 bob, nobody, O'Brien을 바인딩 조회하는 테스트를 추가하세요. 입력별 기대 행 수와 실제 행 수를 기록합니다.

막혔을 때 힌트 보기

따옴표를 직접 이스케이프하는 수정 대신 ?와 인자 튜플을 유지하세요.

과제 해설과 예시 답안 보기
  1. demo.py 사본에서 기존 DB 준비 뒤 bob, nobody, O'Brien의 바인딩 조회를 추가합니다. 각각 1, 0, 0을 기대값으로 적습니다.
  2. 추가로 O'Brien을 저장하려면 INSERT도 바인딩하고 다시 조회합니다. 이름이 정확히 저장되어 한 행이 나오는지 확인합니다.
  3. 취약한 연결 쿼리는 입력이 WHERE 문법을 바꾼다는 설명을 남기고, 수정은 문자열 삭제 대신 값 바인딩으로 제시합니다.

결과를 판단하는 기준

기본 데이터에서 bob 1 / nobody 0 / O'Brien 0입니다. O'Brien 행을 한 번 삽입한 추가 실험에서는 그 이름 조회가 1행입니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

INDEPENDENT PRACTICE

  1. 위 해설을 닫고 예상 결과와 근거를 먼저 적습니다.
  2. 코드·원시 자료·문서 근거로 확인하고 예상과 실제 차이를 설명합니다.
  3. 새 반례 하나를 만들고 무엇까지 확인했는지 기록합니다.
시도한 뒤 판단 기준 읽기

값 바인딩은 정상 이름을 허용하면서 공격 문자열을 하나의 값으로 취급합니다. 따옴표를 모두 금지하는 검사로 정상 기능을 훼손하지 않습니다.

05 / VERIFY

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. payload에 따옴표가 있는데 safe 조회에서 오류 대신 0행이 나오는 이유는?

정답과 이유 읽기

정답: 바인딩이 입력을 쿼리 구조와 분리된 하나의 값으로 전달하기 때문이다.

바인딩은 위험해 보이는 글자를 지우는 방법이 아닙니다. 같은 문자가 포함된 이름이 없으므로 결과가 없는 것입니다.

2. O'Brien 조회가 0행입니다. 특수문자 이름도 정상 처리하는지 더 확실히 확인하려면?

정답과 이유 읽기

정답: 그 이름을 바인딩으로 삽입하고 같은 값으로 조회해 1행을 확인한다.

데이터가 없는 경우와 문법 해석 실패를 구분해야 합니다. 정상 이름을 실제 데이터로 추가한 뒤 정확히 조회하는 실험이 이를 확인합니다.
