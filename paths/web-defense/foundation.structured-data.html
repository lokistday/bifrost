01 / UNDERSTAND

먼저 이해하기

JSON 파서는 문자열을 dict·list·str·int·bool·None 등의 Python 값으로 바꿉니다. 파싱 성공은 JSON 문법을 읽었다는 뜻입니다. minutes가 정수인지, 필요한 필드가 있는지, 예상하지 않은 admin 필드가 들어왔는지는 업무 규칙으로 따로 검사해야 합니다.

이 실습의 데이터 계약은 learner와 minutes 두 필드만 허용하고, learner는 비어 있지 않은 문자열, minutes는 0~1440 범위의 정수입니다. 명확한 계약이 있어야 잘못된 입력이 계산·필터·보고서까지 퍼지기 전에 같은 방식으로 거부됩니다.

JSON의 30, "30", true는 각각 정수·문자열·불리언으로 구분됩니다. Python에서는 bool이 int의 하위 클래스라 isinstance(True, int)가 True입니다. 이 계약처럼 불리언을 허용하지 않는 정수 필드는 type(value) is int로 명확히 구분합니다.

검사 순서는 파일 읽기 → JSON 파싱 → 문서 형태 → 필수/추가 키 → 값의 자료형과 범위입니다. JSONDecodeError와 값 검증의 ValueError를 분리하면 따옴표가 빠진 문법 오류와 minutes가 "30"인 계약 오류를 구분할 수 있습니다.

sort_keys와 공백 없는 separators로 만든 canonical 출력은 이 실습의 재현 가능한 표시 형식입니다. 모든 JSON 서명·정규화 표준을 구현한 것은 아닙니다. 실제 외부 자료는 파일 크기, 중복 키, 숫자 표현 등의 처리도 정책으로 정해야 합니다.

자주 헷갈리는 지점

json.load가 성공했으니 신뢰할 데이터라고 결론낸다.
문법과 업무 계약은 별도입니다. 필드·타입·범위를 검증한 뒤 사용합니다.
isinstance(value,int)만으로 true를 반드시 거부한다고 생각한다.
Python bool은 int의 하위 클래스입니다. 이 실습의 정수 계약은 정확한 타입 비교를 사용합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

record.json의 사본을 만들고 minutes를 true, 1441, 0으로 각각 바꿔 검사하세요. admin 필드를 추가한 경우도 검사하고, JSON 문법 오류와 계약 오류의 차이를 기록하세요.

막혔을 때 힌트 보기

JSON에서는 true를 소문자로 적습니다. 자료형 검사·값 범위·키 집합 검사를 한 번에 바꾸지 말고 하나씩 비교합니다.

과제 해설과 예시 답안 보기
  1. record-work.json에서 minutes=true는 bool이므로 거부, 1441은 범위 초과이므로 거부, 0은 하한을 만족하므로 통과하는지 확인합니다.
  2. 정상 두 필드에 admin=true를 더하면 키 집합 검사에서 record needs exactly learner and minutes가 나와야 합니다.
  3. 쉼표를 빠뜨린 별도 사본은 JSONDecodeError, 문자열 minutes는 ValueError로 나타나며 정상 요약은 생성되지 않는다고 표로 남깁니다.

결과를 판단하는 기준

minutes=0일 때 learner=Loki minutes=0을 출력합니다. true·1441·추가 필드는 종료 상태 2이고 INVALID입니다. 문법 오류도 실패하지만 원인을 JSONDecodeError로 구분합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
