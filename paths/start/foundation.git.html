01 / UNDERSTAND

먼저 이해하기

Git 커밋은 선택한 파일들의 특정 시점을 기록합니다. git add로 올릴 변경을 고르고 git commit으로 저장합니다. git diff는 아직 스테이징하지 않은 변경, git diff --staged는 커밋에 들어갈 변경을 보여 줍니다.

Git 저장은 외부 업로드와 다릅니다. 이 실습은 로컬 저장소에서 끝냅니다. README에는 목적, 환경, 입력 파일, 명령, 실제 출력, 예상과 다른 점을 남깁니다. 비밀번호나 접속 토큰은 기록·커밋하지 않습니다.

작업 폴더, 스테이징 영역, 커밋을 세 칸으로 그려 봅니다. 파일을 저장하는 일은 작업 폴더 변경이고 add는 다음 커밋에 넣을 내용을 고르는 일입니다. add 이후 같은 파일을 다시 편집했다면 추가 변경은 다시 add하기 전까지 스테이징에 포함되지 않습니다.

좋은 학습 기록은 결론뿐 아니라 입력 파일과 도구 버전, 실행 명령, 실제 출력, 기대와 다른 점을 포함합니다. 같은 결과를 다시 얻을 수 있어야 수정이 도움이 됐는지 비교할 수 있습니다. 비밀을 나중에 지운다고 과거 커밋에서 자동으로 사라지는 것은 아니므로 기록 전에 확인합니다.

자주 헷갈리는 지점

git commit을 하면 자동으로 GitHub에 공개된다고 생각한다.
이 실습의 commit은 로컬 기록입니다. 원격 전송은 별도의 작업입니다.
민감한 값을 새 커밋에서 지웠으니 과거에도 없다고 생각한다.
커밋은 과거 시점을 보관합니다. 커밋 전 diff에서 비밀이 없는지 확인합니다.

02 / WORKED EXAMPLE

따라 하며 관찰하기

먼저 수정하지 않은 원본으로 아래 기준 예제를 확인하세요. 원본 폴더를 보관하고 전체 폴더의 작업 사본에서 다음 변경 단계를 진행합니다. 아래 예상 결과는 변경 전 기준입니다.

처음 상태의 전체 예제

터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · Git · 로컬 저장소
mkdir bifrost-notes
cd bifrost-notes
git init
printf "# My Bifrost notes\n" > README.md
git add README.md
git diff --staged
git commit -m "Add first learning note"
git log --oneline

변경 전 예상 결과와 해석

README.md를 포함한 커밋 1개가 생깁니다. 커밋 ID는 환경마다 다릅니다. 사용자 이름·이메일 설정이 없으면 Git이 설정 안내를 출력합니다.

이제 단계별로 바꾸고 관찰하기

  1. 새 저장소에서 상태 확인하기

    본문 예제로 첫 커밋을 만든 뒤 상태와 로그를 봅니다. 사용자 신원 오류가 나면 이 폴더에서 git config user.name "Learner"와 git config user.email "learner@example.invalid"를 실행해 기록용 이름·이메일을 저장한 뒤 첫 커밋을 다시 시도합니다. 예시 주소는 실제 이메일이 아니며 원격 공개 시 커밋 메타데이터도 공개될 수 있습니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · Git · 로컬 저장소
    git status
git log --oneline
    관찰할 결과
    첫 커밋이 있고 작업 폴더 상태를 확인할 수 있습니다. 커밋 ID는 매번 다를 수 있습니다.

  2. 실행 가능한 기록 추가하기

    README에 실습 파일명, 환경, 명령, 실제 출력과 해석을 추가합니다. 예시에서는 foundation의 hello.py를 사용했다는 사실과 실행 위치를 명시합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · Git · 로컬 저장소
    git diff
git add README.md
git diff --staged
    관찰할 결과
    수정 전후 차이와 다음 커밋에 들어갈 내용을 각각 확인합니다.

  3. 커밋 후 기록만 보고 재실행하기

    수정한 기록을 커밋하고 README를 순서대로 따라 실행합니다. 빠진 경로나 입력 파일을 발견하면 기록을 고쳐 다시 커밋합니다.

    터미널 명령 · 이 분야의 작업 사본 폴더 · Ubuntu/WSL · Git · 로컬 저장소
    git commit -m "Record hello exercise"
git log --oneline
    관찰할 결과
    기존 첫 커밋과 학습 기록 커밋, 최소 두 개의 커밋이 남습니다.
03 / TRY IT YOURSELF

직접 바꾸고 확인하기

Foundation 실습 하나의 입력·실행 명령·결과를 README에 추가하고 두 번째 커밋을 만드세요.

막혔을 때 힌트 보기

Git이 신원을 요청하면 이 저장소에 git config user.name과 user.email을 설정하세요. --global은 모든 저장소에 적용됩니다.

과제 해설과 예시 답안 보기
  1. README에 목적, 실제 OS·셸·Python 버전, hello.py 위치, 실행 명령, 실제 출력을 적습니다.
  2. git diff와 git diff --staged로 검토한 뒤 README 변경을 두 번째 커밋으로 남깁니다.
  3. 다른 터미널에서 README만 보고 파일을 찾고 실행합니다. 실행 안 된 단계를 기록으로 보완했는지까지 점검합니다.

결과를 판단하는 기준

git log에 최소 두 커밋이 보이고, README에는 입력·환경·명령·출력·해석이 있어야 합니다. 개인별 환경값과 커밋 ID는 서로 달라도 됩니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.

INDEPENDENT PRACTICE

도움 없이, 조건을 바꿔 보기

임시 연습 저장소에서 README의 한 줄만 수정하고 커밋 전 diff와 커밋 후 log를 연결해 기록하세요.

  1. 위 해설을 닫고 예상 결과와 근거를 먼저 적습니다.
  2. 코드·원시 자료·문서 근거로 확인하고 예상과 실제 차이를 설명합니다.
  3. 새 반례 하나를 만들고 무엇까지 확인했는지 기록합니다.
시도한 뒤 판단 기준 읽기

05 / VERIFY

이 정도면 다음으로

이해한 내용을 점검하기

답을 고른 뒤 이유까지 확인하세요. 점수는 저장하지 않습니다.

1. git add README.md 후 README를 더 수정했습니다. 다음 커밋에 최신 수정도 넣으려면?

정답과 이유 읽기

정답: git add README.md를 다시 실행하고 staged diff를 확인한다.

스테이징은 add 시점의 내용을 선택합니다. 이후 작업 폴더 변경은 별도이며 다시 선택해야 합니다.

2. 실행 기록에서 재현에 가장 도움이 되는 조합은?

정답과 이유 읽기

정답: 도구 환경, 입력 파일, 실행 명령, 실제 출력과 해석

재현에는 조건과 절차가 필요합니다. 결과 문장만 있으면 다른 사람이 무엇을 실행했는지 확인할 수 없습니다.

내 결과물 확인하기

  • status와 diff로 변경을 확인했다.
  • README만 보고 실습을 다시 실행했다.
