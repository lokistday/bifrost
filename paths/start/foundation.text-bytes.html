01 / UNDERSTAND

먼저 이해하기

Python의 str은 유니코드 코드 포인트의 나열이고 bytes는 0~255 값의 나열입니다. 파일·네트워크에는 바이트가 오가므로, 글자에 대한 처리와 전송할 표현 사이에 encode와 decode가 필요합니다. 두 타입의 길이가 언제나 같지는 않습니다.

A가는 코드 포인트 2개이지만 UTF-8에서는 41 ea b0 80의 4바이트입니다. len(str)이 세는 코드 포인트 수는 화면에서 보이는 글자 묶음의 수와도 다를 수 있습니다. 결합 문자나 이모지를 포함하는 화면 너비를 바이트 수로 제한하면 정상 입력을 잘못 자를 수 있습니다.

encode는 텍스트를 선택한 인코딩의 바이트로, decode는 바이트를 텍스트로 바꿉니다. 같은 인코딩으로 왕복하면 원래 문자열을 비교할 수 있습니다. Hex는 바이트를 보기 좋게 표기한 것이며 UTF-8이나 암호화 방식의 대체물이 아닙니다.

UTF-8 바이트를 ASCII로 해석하면 표현할 수 없는 바이트에서 UnicodeDecodeError가 납니다. errors="ignore"로 없애면 프로그램은 계속될 수 있지만 원본 증거와 사용자 입력이 달라집니다. 실패한 위치와 원본 바이트를 보존한 뒤 실제 인코딩을 확인합니다.

텍스트 파일의 줄바꿈 변환도 바이트 해시를 바꿀 수 있습니다. 원본 바이트 보존이 목적이면 read_bytes를, 텍스트 처리가 목적이면 명시적인 encoding="utf-8"을 사용합니다. 인코딩을 맞추는 것은 입력 내용의 안전성을 검증하는 일과 별개입니다.

자주 헷갈리는 지점

UTF-8에서 문자 하나는 항상 1바이트라고 생각한다.
ASCII 범위는 1바이트지만 가는 UTF-8에서 3바이트입니다. 바이트 길이는 실제 encode 결과로 확인합니다.
decode 오류를 ignore로 없애고 원본과 같은 자료라고 적는다.
오류를 없애는 과정에서 바이트가 사라질 수 있습니다. 원본을 유지하고 실패 원인과 손실 여부를 명시합니다.

03 / TRY IT YOURSELF

직접 바꾸고 확인하기

사본에서 value를 "A가!"로 바꾸고 코드 포인트 수·바이트 수·Hex를 실행 전에 예상하세요. bytes 길이만으로 화면 글자 수를 판단하면 생기는 문제를 적으세요.

막혔을 때 힌트 보기

!는 ASCII 한 바이트입니다. 기존 2개·4바이트에서 각각 무엇이 늘어나는지 계산하세요.

과제 해설과 예시 답안 보기
  1. 원본을 보관하고 사본의 text 분기에서 문자열만 A가!로 바꿉니다. encode·decode·오류 처리 부분을 동시에 바꾸지 않습니다.
  2. 예상값 codepoints=3, bytes=5, hex=41eab08021을 적은 뒤 text 모드를 실행합니다. roundtrip=True와 ASCII 오류도 유지되는지 봅니다.
  3. 기록에 바이트 수는 파일·전송 길이, 코드 포인트 수는 Python 문자열 길이이며 화면 글자 묶음 수는 별도라고 설명합니다.

결과를 판단하는 기준

codepoints=3 bytes=5 hex=41eab08021 / roundtrip=True / wrong_encoding=UnicodeDecodeError. 출력이 다르면 편집된 문자열과 실행한 파일 경로부터 비교합니다.

학습 기록: 사용한 환경과 명령 → 바꾸기 전 예상 → 실제 결과 → 차이의 이유를 남기세요.
