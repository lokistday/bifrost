# 같은 계정, 다른 호스트: 근거를 추적하는 조사
합성 이벤트를 실제 SQLite DB 파일로 만들고 조사하세요. 같은 session 값만으로 다른 호스트의 사건을 연결하면 잘못된 결론에 도달합니다.

## 준비
원본 ZIP 폴더를 보관하고 전체 폴더의 작업용 사본에서 진행하세요. Python 3.10 이상,
Linux/WSL/macOS에서는 python3, Windows PowerShell에서는 py -3를 사용합니다.
Crypto는 별도 가상 환경과 requirements.txt가 필요합니다. C/GDB 프로젝트는 WSL/Linux 기준입니다.
예상 180~270분(설치 제외, 저자 추정). 여러 번 나누어 진행해도 됩니다.

## 출력 계약
project-build-db.py가 A/B DB를 생성합니다. host=lab-1, session=S7인 행만 조사 범위입니다. timeline은 UTC 시각순 ID, reads는 그 범위의 read ID입니다. 시각 동률은 ID순입니다. suspect_actor는 자료만으로 실제 행위자를 확정할 수 없어 UNKNOWN입니다.
project-answer-template.json의 키·타입을 유지하고 실제 계산 결과를 새 JSON에 저장합니다.
값은 결과로 채우세요. 템플릿의 0과 빈 목록은 정답이 아닙니다.

## 수행 순서
1. 새 작업 폴더에서 DB를 생성하고 원본 해시와 보관 기록을 남깁니다.
2. sqlite3의 mode=ro로 열거나 별도 작업 사본에서 SELECT를 수행합니다. 행의 원시 시각과 UTC를 함께 보관합니다.
3. 호스트·세션 범위로 연결해 A/B 결과를 만들고 제외된 기록의 이유를 적습니다.
4. 1페이지 보고서에서 관찰 사실·가설·미확인·추가 수집·업무 영향을 분리합니다.

## 결과 검사
1. project-answer-template.json을 answers-a.json으로 복사하고 직접 구한 결과를 넣습니다.
2. `python3 project.py check answers-a.json --variant a`
3. 새 B 표본을 독립적으로 풀어 `python3 project.py check answers-b.json --variant b`
4. 막혔을 때만 `python3 project.py example --variant a`와 project_reference.py를 읽습니다.
   참조 구현은 숨긴 정답이 아니라 공개 해설입니다. 읽은 뒤 새 반례로 다시 확인하세요.
검사기는 답안 JSON만 읽습니다. 제출된 코드 실행·네트워크 전송·자동 진도 저장은 없습니다.
성공 0, 결과 불일치 1, 답안 형식 오류 2의 종료 상태를 사용합니다.

## 평가와 복습
- 원본/작업 사본 해시와 재현 명령을 보관했다.
- 호스트·세션·시간을 함께 사용하고 범위 밖 기록을 섞지 않았다.
- 시각 순서를 인과나 실제 행위자의 신원으로 과장하지 않았다.
- 각 결론에 이벤트 ID를 연결하고 반증 자료·관측 공백을 적었다.
각 항목 0(없음)·1(설명만)·2(재현 근거 있음), 합계 8점의 자기 평가입니다.
다음으로 넘어갈 기준은 각 항목의 근거를 확보하는 것입니다. 점수는 자격 인증이 아닙니다.
1~3일 뒤 답안을 닫고 B 또는 자신이 만든 변형을 풀어 재현 여부를 확인하세요.

## 실제 형식과 연결
JSON 모형에서 실제 SQLite 헤더·테이블·읽기 전용 질의로 넘어갑니다. 선택 과제로 자기 테스트 계정에서 만든 Windows 이벤트를 wevtutil로 내보내고 원시 XML과 비교할 수 있습니다. 외부 공유 전에 개인정보를 검토하세요.

## 범위와 한계
SQLite는 실제 형식이지만 행은 교육용 합성 자료입니다. 실제 EVTX·메모리 이미지 수집·증거 법적 적격성까지 다루는 인증 과정은 아닙니다.
